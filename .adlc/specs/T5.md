# T5 — Loop 5: Federation — the wire speaks to itself (export/import) (rev 2)

## Context

T1–T4 built the claim lifecycle: emit → sign → persist → view. A claim now lives on one
instance; T5 lets it JOURNEY — `Kyber.Federation` exports the store as wire JSONL and
imports wire JSONL through the door (every signature re-verified by the frozen witness,
union dedup, per-line reporting). This is the loam-compatible exchange in miniature (a
federation peer in another language parses exactly this text — the wire bytes are the
contract, pinned in T3) — and the import machinery IS the migration path: spec/07's
legacy-log unification will translate legacy shapes to wire and feed them through
`import/1`, so T6 can reuse it wholesale.

Rev 2 folds the 9-cause premortem (all accepted): the duplicate mechanism is pinned
(pre-append membership check — the door returns :ok for duplicates and re-persists the
line), the export byte shape is exact (NO trailing newline; import drops a final empty
segment), import_report lives in the DurableStore GenServer (the replay_report pattern,
updated at import END), the never-crash promise is TOTAL (catch_exit per line — a
mid-import store death answers a tagged tuple and the report shows lines processed so
far), sink failures HALT with `{:error, {:import_failed, line_no, reason}}` (input
failures never halt; a broken sink must not silently drop claims), AC3's cross-instance
test is rewritten against the singleton reality (sequential boots — two stores cannot
coexist on the global name), the "tampered" example is bit-level sig tampering (a
validly foreign-authored claim IS the federation happy path and imports), the splitter
and CRLF normalization are pinned (matching Log.strip_eol), and AC4's byte-identity is
underpinned by the witness's blessed int→float point (Profile.parse_claims'
coerce_number — verified at profile.ex:43 — so an integer-ts foreign line parses to the
same float the builder would emit).

## Requirements

1. **Kyber.Federation** — Verification: `mix test test/federation_test.exs`.

   ```elixir
   export() -> {:ok, jsonl_text} | {:error, reason}     # store-down -> {:error, :store_not_running}
   import(jsonl_text) -> {:ok, import_report} | {:error, reason}
   import_report() -> %{imported: non_neg_integer(), refused: [line_no()], skipped: non_neg_integer()}
   ```

   `export/0`: the store's delta set as wire JSONL — ONE pinned envelope per line
   (`Wire.envelope({claims, sig})` rebuilt from the set's `{claims, sig}` values,
   `Wire.encode`), DETERMINISTIC order (sorted by id_hex — the same sort view/0 uses).
   **BYTE SHAPE (rev 2 pin): encoded envelopes joined by `"\n"` with NO trailing
   newline; the empty store exports `""`.** Store-down → `{:error, :store_not_running}`
   (the T4 guard shape, at call start).
   `import/1`: split `String.split(text, "\n")` (eager — federation texts are bounded;
   the migration path feeds bounded files), strip a trailing `"\r"` per line BEFORE
   decode (CRLF parity with `Log.strip_eol` — rev 2 pin), DROP a final empty segment
   (a trailing `"\n"` in the text is tolerated, never counted). Per line: empty/blank →
   `skipped`; `Wire.decode` failure → `refused` (1-based line number); decode-ok →
   membership pre-check on `DurableStore.set()` — already present → `skipped` (the
   line is NOT appended again; the set copy is O(n) per line — documented cost, bounded
   syncs; concurrent imports are OUT OF SCOPE — the GenServer serializes, last-import-
   wins report) — else `DurableStore.append` via the catch_exit closure (rev 2 — the
   T4 TOCTOU pattern): `:ok` → `imported`, door refusal → `refused`. NEVER halts on an
   INPUT failure (torn/tampered/non-envelope/refused); a SINK failure (append returns
   `{:error, :persist_failed}` or `{:error, {:write, _}}`) HALTS the import with
   `{:error, {:import_failed, line_no, reason}}` (a broken sink must not silently drop
   claims — rev 2 pin). Store-down at ANY point — before the first line or mid-import
   (the catch_exit maps `exit(:noproc)` to the tagged tuple) → `{:error,
   :store_not_running}`; the report then shows the lines processed so far (the failed
   line not counted).
   `import_report/0`: the last import's report, stored IN THE DurableStore GenServer
   (rev 2 — a new state field updated atomically at import END, mirroring
   `replay_report/0`; store-owned, so it has replay_report's call semantics and its
   store-down behavior — a bare call, same as replay_report/0).
2. TDD; no Process.sleep; `mix format` clean. Verification: `grep -r "Process.sleep"
   test/` finds nothing, `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes; T1–T4 test files byte-untouched, pinned base.**
  `git diff 7e82aa5a -- test/` touches ONLY test/federation_test.exs; `mix test` exits
  0 with no skips. (7e82aa5a = the pre-T5 commit, pinned at rev 1.)
  Verification: the git diff command + `mix test`.
- **AC2 — Export is deterministic and complete: two calls return identical text; every
  stored claim appears as its pinned envelope, sorted by id_hex; the text has NO
  trailing newline; the empty store exports `""`; each line round-trips through
  `Wire.decode`.** Verification: `mix test test/federation_test.exs`.
- **AC3 — Cross-instance round trip (rev 2 — sequential singleton boots: two stores
  cannot coexist on the global name): boot A on tmp path A (T4 Harness: one human
  claim + one agent claim ingested) → `export(A)` → stop A → boot B on tmp path B →
  `import(export(A))` → both claims re-verify through B's door (admit `{:ok, _}`), are
  present in B's set, and `Harness.view()` (B's store) equals the claims decoded from
  A's export text. Import the same text AGAIN → dedup: `imported: 0, skipped: 2`.**
  Verification: `mix test test/federation_test.exs`.
- **AC4 — Byte-identical union round trip: export(A) imported into B then exported
  equals export(A) byte-for-byte — INCLUDING a fixture with an INTEGER timestamp in
  the wire text (rev 2 — the witness's `coerce_number` at Profile.parse_claims is the
  one blessed int→float point, so the parsed float re-encodes byte-identically to the
  builder's output).** Verification: `mix test test/federation_test.exs`.
- **AC5 — Import never halts, never repairs; the taxonomy is pinned:** a TORN final
  line, a TAMPERED line (valid JSON whose signature does not verify against its OWN
  claims — e.g. a bit-flipped sig nibble, the durable_store_test tamper pattern), a
  NON-ENVELOPE line (`"[]"`), and valid lines interleaved → valid lines land, each bad
  line is reported with its 1-based line number (`imported: n, refused: [torn_no,
  tampered_no, nonenvelope_no], skipped: 0`). A VALIDLY FOREIGN-AUTHORED claim (signed
  by a key B has never met — the federation happy path, rev 2) IS imported, not
  refused: the door is self-authenticating.
  Verification: `mix test test/federation_test.exs`.
- **AC6 — Store-down is a tagged tuple at ANY point, never a crash (rev 2):** with
  :kyber stopped, `export/0` and `import/1` return `{:error, :store_not_running}`; the
  catch_exit closure covers a store stopping MID-import (the harness TOCTOU pattern) —
  same tagged tuple, report shows lines processed so far.
  Verification: `mix test test/federation_test.exs` (stop the app, assert the tag,
  re-boot).
- **AC7 — import_report is a live, store-owned observable (rev 2):** the shape is
  `%{imported: n, refused: [line_nos], skipped: n}` (1-based line numbers), updated
  atomically at import END, readable between imports (initially all zeros), reset by
  each import.
  Verification: `mix test test/federation_test.exs`.
- **AC8 — A sink failure halts with a tagged tuple (rev 2):** a door-valid line whose
  WRITE fails (the T2 AC9 close-the-io-behind-the-store technique) → import returns
  `{:error, {:import_failed, line_no, reason}}`; input failures before it remain
  reported, never fatal.
  Verification: `mix test test/federation_test.exs`.
- **AC9 — No Process.sleep anywhere in test/.** Verification: `grep -r "Process.sleep"
  test/` finds nothing.
- **AC10 — Classification parity (rev 2):** the same bytes classify identically whether
  they arrive via `import/1` or via a boot replay of an on-disk log (CRLF handling
  matches `Log.strip_eol`).
  Verification: `mix test test/federation_test.exs`.
