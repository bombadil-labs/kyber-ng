# T7 — Loop 7: The Vault-as-View — claims become a human-navigable memory (the lens) (rev 2)

## Context

Legacy kyber's core value: "Memory isn't a database schema; it's a markdown file that a
human can read and edit in Obsidian" (~/repos/kyber/CLAUDE.md §5). Kyber-ng's answer is
the LENS principle: the claims store is the truth; the vault is derived state rendered
from it — `Kyber.Vault` materializes the store's claims as an Obsidian-compatible
markdown vault. Nothing is deleted from the store (the store only learns); the vault can
be rebuilt from claims alone; a re-render is byte-idempotent (no churn, no duplicates,
no orphans). The 8-cause premortem (rev 2) folded ALL findings — including that the
frontmatter emitter is an invented YAML subset with no parser in the frozen deps (the
rendered shape is pinned BYTE-EXACT below), that wikilinks dangled by construction
(entity ids can never be claim addresses — only `{:delta, hex, _}` refs are), that
`claim:<id>.md` is invalid on Windows, and that hand edits must be REPORTED, never
silently clobbered.

**Rendered shape (PINNED BYTE-EXACT — rev 2, the premortem's golden-fixture pin):**
one file per claim, **`claim_<id_hex>.md`** (underscore — `:` is forbidden on NTFS, rev 2)
in a flat `claims/` subdirectory of the vault dir. Frontmatter (YAML `---` block), pinned
line-by-line:

```
---
id: <id_hex>
author: <pubkey hex>
timestamp: <ts rendered via :erlang.float_to_binary(ts, decimals: 0) — DECIMAL, never scientific: 1_754_512_345_678.0 -> "1754512345678"; 1_700_000_000_000.0 -> "1700000000000" (rev 2)>
role: <the literal FIRST pointer's role — 'received' (message.received), 'sent' (message.sent), 'responds' (llm.response), 'tool' (tool.exec), 'legacy' (T6 archivist) — NEVER a kind name; the witness has no kind field (rev 2)>
pointers: <Wire.claims_json(claims)["pointers"] serialized as JSON text — the SAME debug-profile shape the wire uses, reused not reinvented (rev 2)>
---
```

Then the body (rev 3 — the wikilink home, folded from the build's spec-contradiction
report): the `content` pointer's target rendered per what `Delta.validate/1` allows —
`{:string, s}` renders as `s` (the pinned byte-exact case for every current builder),
`{:delta, hex, _}` renders as the wikilink `[[claim_<hex>]]` (rev 3 — the wikilink rule
LIVES in the body, the only surface the byte-exact pins leave for it: the frontmatter
`pointers:` field is pinned raw JSON and never transformed), `{:entity, _, _}` renders
as plain text; absent `content` pointer → a one-line `no content pointer` summary.
**Quoting rule (rev 2):** any string scalar that begins with `{`, `[`, `'`,
`"`, or contains `": "` is rendered single-quoted — the YAML subset is: bare scalars,
single-quoted scalars (with `''` escaping), and the flow-sequence/map literals that
`JSON.encode!` produces (never block YAML). **Wikilinks (rev 2, the dangling-link
fix):** ONLY `{:delta, hex, _}` pointer targets render as `[[claim_<hex>]]` (delta
refs ARE claim addresses — the link resolves); an `{:entity, id, _}` target renders as
PLAIN TEXT (entity ids — `message:discord:...`, `delta:<legacy_id>`, `human:<hex>` —
are never claim addresses, so linking them is structurally a dangling link). No other
link forms. Deterministic: files sorted by id_hex; no volatile content in the bytes.

**Idempotence (rev 2):** `refresh/1` = render + COMPARE-THEN-WRITE (the ONLY mechanism
— mtime is granularity-blind and File.write! always bumps it, so churn is measured by
the compare, never mtime): a file whose rendered bytes equal the existing bytes is NOT
written (`unchanged`); a file whose bytes differ — a hand edit or a stale render — IS
overwritten AND REPORTED in the observable (`overwritten: [paths]` — the lens is the
authority; the store is the truth; but the human is told, never silently clobbered,
rev 2); a foreign file (not a `claim_<id>.md` name) is NEVER touched or deleted (the
lens never deletes).
