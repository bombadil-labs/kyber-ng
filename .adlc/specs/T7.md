# T7 — Loop 7: The Vault-as-View — claims become a human-navigable memory (the lens)

## Context

Legacy kyber's core value: "Memory isn't a database schema; it's a markdown file that a
human can read and edit in Obsidian" (~/repos/kyber/CLAUDE.md §5). Kyber-ng's answer is
the LENS principle: the claims store is the truth; the vault is derived state rendered
from it — `Kyber.Vault` materializes the store's claims as an Obsidian-compatible
markdown vault. Nothing is deleted from the store (the store only learns); the vault can
be rebuilt from claims alone; a re-render is byte-idempotent (no churn, no duplicates,
no orphans).

**Rendered shape (pinned):** one file per claim, `claim:<id>.md` in a flat `claims/`
subdirectory; Obsidian frontmatter (YAML `---` block) carrying `id`, `author`,
`timestamp` (float ms, the D14 value), `role` (the first pointer's role — the claim's
kind: `legacy`, `content`, ...), and `pointers` (each pointer's role + target rendered as
JSON, human-readable); the body = the `content` pointer's string value when present (the
claim's human-facing text — for a migrated legacy delta, the embedded payload JSON),
else a one-line summary of the pointers. `[[wikilinks]]`: any pointer whose target is an
`{:entity, id, _}` renders as `[[claim:<id>]]` (Obsidian links between claims — the
entity pointers become navigable edges). Deterministic: files sorted by id_hex; no
timestamps or volatile content in the rendered bytes (a re-render of the same store is
byte-identical).

**Idempotence pin:** `refresh/1` renders every claim's file and leaves everything else
alone — a foreign file in the vault dir is never touched or deleted (the lens never
deletes); a re-render overwrites only changed files (byte-identical → zero churn). The
vault dir is created on first render (`File.mkdir_p!` — the T3 ownership pattern, but
the VAULT owns its own dir; a non-directory path → tagged tuple).

## Requirements

1. **Kyber.Vault** — Verification: `mix test test/vault_test.exs`.

   ```elixir
   render(vault_dir) -> {:ok, %{files: n}} | {:error, reason}    # store-down -> {:error, :store_not_running}
   refresh(vault_dir) -> {:ok, %{files: n, unchanged: n}} | {:error, reason}
   ```

   `render/1`: store-down guard FIRST (the T5 shape); `File.mkdir_p!(vault_dir)`
   (a regular-file path at vault_dir → `{:error, {:vault_dir_not_dir, path}}` — the
   mkdir failure is a tagged tuple, never a raise); claims from `DurableStore.set()`
   (every claim's `{claims, sig}` → the pinned markdown); write `claim:<id>.md` files
   (one per claim); the file name is the ENVELOPE id (id_hex); return
   `{:ok, %{files: n}}`. Deterministic (same store → byte-identical vault).
   `refresh/1`: render + compare — a file whose content is byte-identical to the
   previous render is NOT rewritten (zero churn — verify via mtime or a compare-then-
   write; the observable is `%{files: n, unchanged: n}`); foreign files in the vault
   dir are untouched; a claim file whose content CHANGED (it can't — claims are
   immutable and content-addressed — but a hand-edited file) is overwritten with the
   canonical render (the lens is the authority; a hand edit is a VIEW edit, the store
   is the truth).
2. TDD; no Process.sleep; `mix format` clean. Verification: `grep -r "Process.sleep"
   test/` finds nothing, `mix format --check-formatted` exits 0.
