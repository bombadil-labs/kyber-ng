# T19 — Kyber dashboard: delta intake waterfall + span/trace view (Phoenix LiveView)

## Purpose

Kyber is an agent harness on an append-only delta store. Today its only surface is the
CLI; a human watching an agent think has nothing but `kyber log` tail and process
forensics. T19 adds an in-repo Phoenix LiveView dashboard with two linked views:

1. **View 1 — delta intake waterfall.** Every appended delta appears live as it lands,
   showing delta → subscriber-fire → re-emitted claim re-entering the intake in one flow.
   Every delta is clickable.
2. **View 2 — span/trace view.** An OTel-style waterfall per agent turn. Clicking any
   delta in view 1 opens the trace: the full waterfall if the id is a trace root, else the
   spans whose activity referenced it.

## Decisions (user, 2026-08-14)

- **In-repo** Phoenix + LiveView (rail exception recorded in AGENTS.md — the dashboard
  track may amend `mix.exs`/`config/` and add Phoenix/LiveView deps; substrate rails stay
  frozen for everything else).
- **Span storage = in-memory ring buffer** with ETS index by trace id. Traces are
  ephemeral by design; the store keeps only deltas (the atom is untouched — spans never
  become claims).
- **Emitter in core, pin-1 cast seam** — `GenServer.cast(Kyber.Trace.Collector, msg)` at
  the call sites; a cast to an unregistered name is dropped, never a crash (the
  `notify_reactor/1` precedent). NO new substrate deps (no `:telemetry` package).
- **Live waterfall** for view 1 (LiveView `stream/4` — append-only semantics match the
  delta log).

## Design resolution (converged plan, rumble 2026-08-14)

Blind round: opus-5 + deepseek on the two open forks (span boundary set; ring buffer
capacity/retention). Both independently pinned 256 traces / 4096 spans / whole-trace
oldest-first eviction / ETS bag for click-through. Synthesis below cites provenance per pin.

### Span boundary set (fork B)

**Six spans** (atoms verbatim), from deepseek's leaner set (opus's `:gate_check` folded
into the turn span per deepseek's argument — `gate_open?/0` scans the full set, so a
per-dispatch span would double an O(n) copy):

| span | call site | attrs |
|---|---|---|
| `:turn` | reactor `dispatch/3` (reactor.ex:287) when `turn_for/3` creates a Turn for kind `"received"` (pin 11); END cast at the pinned turn-terminal sites (below) | `gate: :open\|:closed` (at turn start), `budget_cap`, `outcome` |
| `:dispatch` | reactor `dispatch/3` → `invoke/5` (reactor.ex:386), one per CHARGED dispatched delta of the subscribed kinds — starts at invoke entry; budget-refused deltas never reach invoke and get no dispatch span (the refusal appears as the refusal GateDecision's own dispatch span, L8) | `delta_kind`, `handler_result` |
| `:llm` | engine `complete/3` wrapping `LlmHandler.chat/3` | `model` (never api_key/seed — D8) |
| `:tool_exec` | tool_executor around `result_wires/8` (tool_executor.ex:537) on verdict `:allow` (tool_executor.ex:274) | `tool_id`, `result_status` (NO args/results — redaction by construction) |
| `:store_append` | store for every `{:append, wire}` | `delta_id`, `outcome: :committed\|:duplicate\|:refused\|:persist_failed` |
| `:fan_out` | store `fan_out/2` per committed delta | `delivered`, `pruned` |

**Tree shape.** Root = turn span. trace_id = the BARE initiating received delta id (M5 —
content-addressed, so trace ids and micro-trace keys stay disjoint by construction). The
turn span is `span_id: "turn:"<>received_id, trace_id: received_id, parent_id: nil`.
Children attach by `parent_id` at collector START, in order: (1) `trace_id` given →
attach; (2) `parent_id` → `:l19_by_span` → inherit; (3) first `refs` id in `:l19_by_delta`
→ inherit; (4) else micro-trace keyed by the first ref (untraced deltas: seed,
attestation, probe, and the engine-emitted kinds never dispatched — message.sent,
PromptAssembled, ConversationSummary, key material; view 1 renders an "untraced" state
for them, L7). The reactor is the ONE attribution authority — it already owns
`state.emitted` (wire_id → turn_id) and `walk_to_received/2`; it casts
`{:trace_attribution, delta_id, turn_id}` at Turn creation and in `emit/3` (and the
engine's sink-side appends are attributed via the attribution cast at emit/3 — M3: the
attribution casts feed a SEPARATE delta→trace index in the collector that SURVIVES span
eviction, so click-through-after-eviction works; I4 reworded accordingly below).
Ordering is not guaranteed per sender-pair, so attach-by-refs + orphan handling is
mandatory, not optional (opus's orphan-bucket insight, adopted).

**Re-parent pass (M2 — mandatory, not optional):** on every successful attach and on
each `:sweep`, the collector merges any micro-trace whose first ref now resolves (rule
3) to a non-micro trace — spans' `trace_id` rewritten, and `by_span`/`by_delta`/trace
rows + I2/I4 maintained atomically in the one handler. Additionally, reactor-owned spans
carry explicit `trace_id`/`parent_id` (rules 1/2) so rules (3)/(4) fire only for
genuinely untraced deltas.

**Span data** (map, immutable once closed): `span_id`, `trace_id`, `kind`, `parent_id`,
`refs` (delta ids), `start_ts` (initiating delta's `claims.timestamp` — never wall
clock, AC5), `start_mono_ms`/`end_mono_ms` (`System.monotonic_time(:millisecond)`),
`status`, `data`. NO payload carries seed/api_key/raw args or results (D8 by
construction).

**Emitter API** (cast seam, no return-value plumbing — span id minted locally so the call
is total whether or not a collector lives):

```elixir
@spec span_start(map()) :: :ok      # {:span_start, %{span_id, kind, trace_id, parent_id, refs, ts, data}}
@spec span_end(binary(), atom(), map()) :: :ok   # {:span_end, span_id, %{status, data}}
```

Span ids are deterministic: `"turn:"|"dispatch:"|"llm:"|"tool:"|"append:"|"fan:"` <>
delta id — except `:llm`, which is per-attempt: `"llm:"<>request_id<>"#"<>attempt`
where attempt = the request's ToolResult count + 1 (M1 — a tool-using turn performs k+1
real chats under ONE request_id; first-wins would silently drop chats 2..k+1. Per-attempt
ids are mandatory for `:llm`, not optional; a re-fired attempt re-derives the same number
and still merges first-wins within the attempt). START for an open id = no-op (first
wins — crash-window replays merge into the first span); END for unknown/closed id =
no-op; refs-less unparented span = dropped.

**Emitter calls are TOTAL (L5):** a raise while building the span-data map at a call
site would change the wrapped return value (breaking AC6's byte-identity even WITH a
collector present) and, in the store's append path, take the write path down. Span data
maps are built from pre-validated fields only; `span_end` fires on error returns too
(e.g. `complete/3`'s `{:error, reason}` branch and non-`:allow` executor statuses still
close their spans with status set).

### Ring buffer & ETS index (fork C)

- **Capacity.** Global span cap `C = 4096`; trace cap `T = 256`; per-trace cap `P = 1024`
  (a runaway turn truncates itself, not the ring). Both voices independently pinned
  256/4096.
- **Eviction** (checked at every span_start/span_end): over C → evict whole traces
  oldest-first by `root_seq`, preferring `:complete` then `:active`, until total ≤ C.
  Over P on one trace → drop that trace's oldest non-root spans (root preserved; row
  marked `truncated: true`). Over T → evict the oldest `:complete` row. Eviction deletes
  from ALL tables in the same handler — no orphan spans, no dangling by_delta/by_span.
  **Whole-trace eviction is invariant** (I3) — a half-evicted trace renders a lying
  waterfall.
- **ETS tables** (collector single-writer; LiveView reads directly, `:named_table,
  :protected, read_concurrency: true`):
  - `:l19_spans` `:ordered_set` `{trace_id, seq}` → span map (seq = collector monotonic
    counter at START; ring = bounded window over seq)
  - `:l19_traces` `:set` `trace_id` → `%{root_seq, status, span_count, open, first_ts,
    truncated}`
  - `:l19_by_span` `:set` `span_id` → `{trace_id, seq}` (parent/attach)
  - `:l19_by_delta` `:set` `delta_id` → `[{trace_id, seq}]` (view-2 click-through)
- **Completion/retention.** Trace `:complete` when last span's END arrives (open → 0).
  **Turn-END sites are pinned (H1):** (i) `refuse_budget/4` (reactor.ex:465) casts
  `span_end("turn:"<>turn.turn_id, %{status: :closed, data: %{outcome: :refused}})`
  (turn_id known directly); (ii) on `{:engine, {:answered, request_id}}` the reactor
  resolves request_id → received via `walk_to_received/2` (reactor.ex:347) and casts the
  turn END with `outcome: :answered` (closed-id END no-op keeps re-fires coherent).
  Watchdog: one self-sent `{:sweep}` every 5 s; `:active` traces with root older than
  `@max_trace_age_ms = 60_000` (comparing `System.monotonic_time` against the root's
  `start_mono_ms` — never `claims.timestamp`, L2) are force-completed, open spans closed
  `:truncated` (crash/straggler safety only — NOT the normal closer). Completed traces
  retained until evicted (preferred victims). Tests drive the sweep by direct send — no
  `Process.sleep`.
- **Eviction fallback (H2):** Over T with no `:complete` row → evict the oldest row by
  `root_seq` REGARDLESS of status; an `:active` victim is force-closed (`:truncated`,
  whole-trace, I3 intact) before eviction; a span whose admission would leave T violated
  after eviction is DROPPED — never a partial admit.

### Collector ownership & run mode

`Kyber.Trace.Collector` is a GenServer, registered under its module name, supervised in
the Phoenix app tree (dashboard track, same BEAM, node-wide name). It has NO store/daemon
dependency — spans are one-way casts that cannot affect a turn's outcome; a collector
crash loses only ephemeral traces.

**Run mode is pinned (M4):** `mix kyber.dashboard` boots store + daemon
(`loop: :reactor`) + collector + endpoint in ONE supervision tree. A separate-BEAM
dashboard (`mix phx.server` in one shell, `kyber daemon` in another) is a documented
"nothing to show" state — the dashboard renders an explicit banner when the collector or
store is absent. LiveView table reads use a rescue→empty-read guard on every ETS access
(missing table raises ArgumentError on a named-table lookup; the guard keeps the socket
alive across a collector restart, L6). View 1's data source is `subscribe_seeded/1`
(durable_store.ex:115 — F2 seam, no commit gap, L3); the fan_out span carries only
delivered/pruned COUNTS (the store knows pids, not names — view 1 renders the counts,
L4).

## Dynamics contract (T17 doctrine — the span lifecycle)

Subsystem: `Kyber.Trace.Collector` — pre-impl tests in
`test/kyber/live/span_lifecycle_test.exs` (cast-in, poll state; sleep-free).

**States** — span: `:pending | :closed | :evicted`; trace:
`:forming | :active | :complete | :evicted`; collector: `:empty | :serving`.

**Events** — `:span_start`, `:span_end`, `:sweep`, `:shutdown` (cast/send inputs only;
nothing else mutates state).

**Transitions** — span: `:pending --span_end--> :closed`; `:pending --sweep(age>60s)-->
:closed(:truncated)`; `:pending|:closed --evict--> :evicted`. trace: `:forming
--span_start--> :active`; `:active --span_end(open==0)--> :complete`; `:active
--sweep(age)--> :complete` (open spans forced :truncated); `:active|:complete --evict-->
:evicted`. collector: `:empty --span_start--> :serving`.

**Invariants (every state — these are the pre-impl tests):**
- **I1** Totals ≤ C/P/T, restored by eviction on every span_start/span_end.
- **I2** No orphan spans — every live span's trace row exists; `span_count`/`open` match.
- **I3** Whole-trace eviction — no row ever holds a partially-evicted span list.
- **I4** `by_span`/`by_delta` hold exactly the live spans' entries (no dangling
  click-through after eviction); the SEPARATE attribution-seeded delta→trace index
  survives span eviction by design (M3 — it is what makes click-through-after-eviction
  and `resume/1` work; its rows reference trace ids, not span ids, so eviction never
  dangles it).
- **I5** Live span ids unique (first START wins); END for unknown/closed id = no-op.
- **I6** No payload carries seed/api_key/raw args or results (D8 by construction).
- **I7** The collector never calls store or daemon (one-way casts) — spans cannot affect
  a turn's outcome; a collector crash loses only ephemeral traces.
- **I8** `end_mono >= start_mono` for every closed span.

## ACs

- **AC1 (view 1 — live intake):** a LiveView page (source: `subscribe_seeded/1`)
  streams every committed delta live, in order, showing each delta, the subscribers that
  fired on it (delivered/pruned counts), and re-emitted claims re-entering the intake.
  Duplicate re-appends surface via the store_append span's `:duplicate` outcome (they are
  never fanned out).
- **AC2 (view 2 — trace):** a LiveView page renders an OTel-style waterfall per trace id;
  spans are parent-attached, durations from monotonic clocks, statuses shown.
- **AC3 (click-through):** clicking any delta in view 1 opens view 2 — check
  `:l19_traces` for the clicked id first (trace_id = the bare received delta id, so a
  root click IS the trace key, M5): full trace if found, else the spans whose activity
  referenced it (`:l19_by_delta`), else the attribution-seeded index (post-eviction).
- **AC4 (ring buffer):** under a synthetic 300-trace flood, the collector never exceeds
  C/T/P, evicts whole traces oldest-first, and keeps `:l19_by_delta` consistent (I4).
- **AC5 (secrets):** no span payload ever carries a seed, api_key, or raw tool
  args/results (I6) — proven by a redaction-scan test over emitted spans.
- **AC6 (emitter seam):** with no collector registered, every emitter call returns `:ok`
  and the wrapped call site's return value is byte-identical to the pre-instrumentation
  value (I7 — the pin-1 seam).
- **AC7 (deliverables):** `lib/kyber/trace.ex` (emitter), `lib/kyber/trace/collector.ex`
  (ring buffer + ETS), `lib/kyber/trace/span.ex`, Phoenix LiveView pages for both views,
  `test/kyber/live/span_lifecycle_test.exs` + dashboard integration tests. Suite green,
  format clean, no `Process.sleep` in tests.

## Open items (post-premortem residuals)

- Gate as a span: folded into the turn span (premortem-confirmed right — a per-dispatch
  gate span would double the O(n) set scan); revisit if gate scans prove hot.
- Finer tool spans (per-tool gate/policy/action detail) need an emitter seam inside
  `ToolExecutor`, which is a pure gather closure — breaking the purity rail for
  observability deserves its own argument, not a side effect of this loop.
- Hot-loop rate limiting: no sampling pinned; eviction counters make it visible first.
- Federation/multi-node: out of scope — the collector is node-local, traces ephemeral.
- The reactor's pre-existing unbounded maps (dispatched/emitted/turns, reactor.ex:198 —
  write-only, never pruned) are the attribution authority's substrate; T19 must not add
  another unbounded structure (L10 — by_delta/by_span are eviction-bounded; the
  attribution index is, too).
