# T6 — Loop 6: Migration — the legacy log becomes claims (spec/07) (rev 2)

## Context

The ORIGINAL mission lands: kyber's pre-rhizomatic delta log is unified with
rhizomatic/loam deltas. The legacy repo (~/repos/kyber) writes `deltas.jsonl` — one
`Kyber.Delta.to_map/1` map per line, Jason-encoded (store.ex `write_line/2`): string keys
`id`, `ts`, `origin`, `kind`, `payload`, `parent_id`. **The byte-realistic legacy line
(rev 2, verified against ~/repos/kyber/lib/kyber_beam/delta.ex): `origin` is ALWAYS an
object** — `Kyber.Delta.Origin.serialize/1` yields `{"type": "channel", "channel": ...,
"chat_id": ..., "sender_id": ...}` (or cron/subagent/tool/human/system variants); `ts` is
an integer (ms since epoch); `payload` is arbitrary JSON (a memory map, a string, ...);
`parent_id` is a string or null.

Legacy deltas are UNSIGNED — migration cannot fabricate signatures. The archivist answer
(pinned): each legacy delta becomes a claim SIGNED BY THE AGENT KEY (the harness attests
"this delta existed in my history"); the legacy identity lives in the claim's pointers;
the timestamp is the legacy ts (coerced to float per D14 — translate_line IS the builder
here). No signature is fabricated: the archivist signature is the harness vouching for
its own past.

T5's architecture pays off: migration is a PURE translator feeding the existing pipeline —
`Kyber.Migration.migrate/2` translates the legacy log to wire text and hands it to
`Federation.import/1` (the SAME door, the SAME dedup → re-migration is idempotent, the
SAME reporting).

**Claim shape (rev 2 — the 8-cause premortem folded, all accepted):**
`%{timestamp: float, author: agent_pubkey, pointers: [%{role: "legacy", target:
{:entity, "delta:<legacy_id>", "legacy"}}, %{role: "kind", target: {:string, kind}},
%{role: "origin", target: {:string, JSON.encode!(origin)}}, %{role: "parent", target:
{:string, parent_id}}, %{role: "content", target: {:string, JSON.encode!(payload)}}]}`
— the origin OBJECT is embedded as an encoded string (a map cannot be a string target;
verified: `Delta.validate` rejects `{:string, map}` and Cbor crashes on it — rev 2).
Optional fields (origin/parent_id/payload) absent or null → their pointer is omitted.
`translate_line/1` calls `Delta.validate` BEFORE signing (mirroring the Events builders)
so every refusal is a tagged tuple, never a Cbor crash.

## Requirements

1. **Kyber.Migration** — Verification: `mix test test/migration_test.exs`.

   ```elixir
   migrate(legacy_path, keyring_dir) -> {:ok, migration_report} | {:error, reason}
   translate_line(legacy_map, seed_hex) -> {:ok, {claims, sig}} | {:error, reason}   # PURE (rev 2)
   ```

   `translate_line/2` (PURE — no I/O, no store, no process; the archivist seed is a
   PARAMETER — rev 2, the 1-arity pin could not obtain a seed): takes the DECODED legacy
   map (string keys), validates the required keys (`id`, `ts`, `kind` — `origin` /
   `parent_id` / `payload` optional, absent or null → pointer omitted), coerces `ts` to
   float per the Events.timestamp/1 contract (a NON-NUMBER ts → `{:error,
   :timestamp_not_a_number}` — never a raise; an integer ts → the exact-f64 check
   `trunc(1.0 * ts) == ts` — total over decoded JSON values, rev 2), builds the pinned
   claim shape, runs `Delta.validate/1` (rev 2 — the refusal is a tagged tuple, never a
   Cbor crash), signs with the given seed (`Keys.sign/2`). Returns `{claims, sig}` — the
   same shape the Events builders return. Deterministic over the DECODED term (same
   decoded map + same seed → same claims → same id — rev 2, the idempotency foundation).
   `migrate/2`: store-down guard FIRST (`Process.whereis(Kyber.DurableStore)` →
   `{:error, :store_not_running}`); THEN load the archivist seed ONCE
   (`Keys.load_agent_seed/1` from keyring_dir — its error tags pass through:
   `{:error, :no_agent_seed}` / `{:error, {:keyring_dir_missing, _}}`; same keyring_dir
   → same seed → same author, rev 2); THEN the file mechanism (rev 2): `File.regular?`
   pre-check → `{:error, {:no_legacy_log, path}}`; `File.open(path, [:read, :binary])`
   in a try → `{:error, {:unreadable_legacy, path, reason}}`; stream lines from the
   OPEN device (`IO.stream(io, :line)`, line numbers 1-based; CRLF: strip ONE trailing
   `"\r"` per line before decode — the T5 parity lesson). Per line: `JSON.decode` →
   `translate_line(line, seed)` → `{:ok, {claims, sig}}` → `Wire.envelope/1` +
   `Wire.encode/1` → a wire line (collect); `{:error, _}` → `legacy_refused ++
   [line_no]` (never fatal). Then `Federation.import(wire_text)` — all collected lines
   at once (**MIGRATION IS BOUNDED (rev 2):** typical legacy logs are 10^3–10^4 lines;
   the collect-then-import design with T5's documented O(n)-per-line import cost is
   accepted; a streaming-import ticket is a later loop — the "large memory logs"
   justification is DROPPED). The result:
   `%{imported: n, refused: [], skipped: n, legacy_refused: [line_nos]}` — **`refused`
   is structurally ALWAYS `[]` (rev 2, pinned): an archivist-signed envelope cannot be
   door-refused (sig verifies, id matches, envelope closed) — documented, and the
   migration report keeps the field for shape-compatibility with the import_report it
   wraps**; `legacy_refused` carries LEGACY-file line numbers (1-based); the import
   side's own numbering (wire-text positions) never appears in the migration report
   (rev 2 — no dual numbering traps). A store-down from the import (mid-migration)
   passes through as `{:error, :store_not_running}` — **with NO partial report; the
   translated-but-unimported work is DISCARDED (translation is pure and uncached); a
   retry re-translates from scratch (bounded files make this acceptable — a resume
   mechanism is a later ticket, rev 2)**. An EMPTY file → `{:ok, %{imported: 0,
   refused: [], skipped: 0, legacy_refused: []}}`. In-file DUPLICATE legacy lines →
   identical claims → the second occurrence is `skipped` (not imported, not refused —
   rev 2, pinned counting).
2. TDD; no Process.sleep; `mix format` clean. Verification: `grep -r "Process.sleep"
