# T11 — The Agent Actually Lives In It: LLM handler + memory store + schema layer (the harness eats a real model)

Rev 1 — design conversation 2026-08-06 (Myk + Veles): deltas-as-events ↔ entities-as-resolutions;
primitives ride, composites point; actors bound to containers; memory reified to markdown;
schemas are deltas. The T10 harness is real; the agent is a stub. T11 swaps the stub.

## Why this loop exists (user direction, 2026-08-06)

T10's closing line: "the harness is real, the agent is a stub." This loop is the stub going
live: a REAL model — Moonshot Kimi K3 (provider wiring proven on this repo: `moonshotai/kimi-k3`,
`MOONSHOT_API_KEY`) — becomes a gather handler, so an actual LLM lives in the loop: event in →
signed claim → model action → response claim → memory. The claims substrate IS the memory; the
Discord transport later plugs in as just another handler. And the memory store must be real:
organized, maintained, reified to disk as human-editable markdown (an Obsidian vault), reconciled
with the delta substrate. "In practice I don't expect to get this right on the first time" — the
architecture must make the memory store A/B-testable.

## The architectural model (the contract's spine — all pinned)

1. **Deltas ARE the events** (carried from T10). One kind of thing in motion. Admission
   (persist vs pulse) is a property of reduction at the sink, never of the object.
2. **Entities are resolutions, never written.** An entity (Prompt, Session, Memory) exists by
   being referenced: its id rides on deltas as a pointer role; resolution = gather the hyperview
   (every delta pointing at the entity) → hyperschema → schema → domain object. Entities are
   time-versioned: "resolve the session as of position T" is a valid query (retraction-is-negation
   gives mutation semantics without breaking append-only).
3. **The intake takes deltas, unconditionally.** Never resolved views. A view entering the
   stream bakes a schema decision at write time, breaks content-derived identity, and defeats
   admission. Resolution is read-time, or inside a handler that needs the resolved shape.
4. **Primitives ride, composites point.** A delta embeds small immutable facts of the act
   (channel, session_id, timestamp, prompt text) as content/roles; it REFERENCES composite
   history and memory (conversation, injected memories) via pointers. Never copy the history
   into the delta — the store holds it once, rehydrated by pointer-walk.
5. **The pointer is the crash-window guarantee.** Deltas freeze their pointers; the store is
   append-only and claims are immutable (retraction is a new claim). A pointer set therefore
   resolves identically at any later time → re-fires produce byte-identical inputs → the sink's
   content-address dedup drops replays. (The T10 lesson: wall-clock state in a delta is the
   duplicate bug; pointers into an immutable store are the opposite.)
6. **Actors are bound to containers.** The context builder (session hyperview), the inference
   engine (in-flight turn state), the memory container (memory entities) — each is a stateful
   actor whose in-memory state is a CACHE of truth, never the authority. Rehydration: replay the
   container's claims from the store; the ConversationSummary delta doubles as the checkpoint
   (rehydrate = summary + tail). Anything that must survive reboot is a delta or provably
   re-derivable. Communication between actors is deltas only.
7. **The schema layer is deltas too.** A genesis set of hyperschema + schema deltas saturates
   the lifecycle (Session, SubmittedPrompt, InferenceRequested, ResponseDelta, ToolCall,
   ToolResult, ConversationSummary, MemoryEntity, MemoryEdited + the T10 infra types). Schemas
   are signed, content-addressed, versioned, retractable — evolution is retraction-plus-new-issue.
   A schema container actor is the resolution authority: holds the compiled set, subscribes to
   schema deltas, answers `validate/1` and `resolve/1`. "Nothing anywhere should have any
   confusion about the exact shape of the deltas it's reading or writing."
8. **Windows are lenses, summaries are checkpoints.** The context builder's window (last N
   turns) is a schema over the session hyperview — a bounded lens, not a data structure. A
   summarizer reactor emits ConversationSummary derived claims at checkpoint positions; the
   window lens prefers summaries beyond its bound, so a 10,000-turn session resolves in the same
   bounded read as a 10-turn one.
9. **Tool chains are cascades of linked deltas.** A tool-using turn is Prompt → ToolCall →
   ToolResult → … → Response, each step a persisted delta linking to its predecessor, emitted as
   it happens (never batched at turn end). The engine holds the in-flight turn state and fires on
   each ToolResult; tool-executor handlers fire on ToolCall deltas. A daemon death mid-chain
   resumes from the last ack — the chain is the state.
10. **Rendering is a lens, not data.** Whether the UI shows tool steps collapsed or expanded,
    what tool output is visible — projection-layer policy, never a data-model decision.
11. **The memory store is entities reified to markdown.** System memories start as deltas
    (parsed from response deltas), resolve into MemoryEntity objects, project to markdown (the
    Obsidian vault = the L2 tier made human-editable, our `viking://`). Human edits change the
    canon — canon is a RESOLUTION, never a store — and the watcher observes the edit, diffs, and
    emits a `MemoryEdited` delta (attested by the memory container's key, or the user's key via
    the vault-sync tool). Even outside-system edits become post-hoc deltas: everything is
    reconstructable as a delta history. L0 (abstract) / L1 (overview) are derived deltas per
    entity (and per category), regenerated on edit; retrieval walks L0 → L1 → L2 with a recorded
    trajectory. Memory carries a `provenance` role (model | human | derived); human-canon is
    authoritative — never auto-consolidated without asking.

## Deliverables

- **`Kyber.Agent.LlmHandler`** — an OpenAI-compatible client (Moonshot base
  `https://api.moonshot.ai/v1`, key from `MOONSHOT_API_KEY`, model `kimi-k3`; stdlib
  `:httpc`/`:ssl` — zero new deps) implementing the gather contract `(delta[]) -> delta[]`
  with REAL (non-deterministic) content.
- **`Kyber.Agent.ContextBuilder`** — session-container actor: maintains the conversation
  hyperview (gather-into), applies the window lens (last N turns + summaries), injects memories
  (retriever output, human-canon weighted), emits one thin `InferenceRequested` delta per
  prompt (primitives ride, composites point).
- **`Kyber.Agent.Engine`** — stateful inference handler: fires on `InferenceRequested`,
  rehydrates context by pointer-walk, calls the model, emits `ResponseDelta` (or `ToolCall`
  deltas mid-turn), holds in-flight turn state, resumes from the chain on restart.
- **`Kyber.Agent.Memory`** — memory container: MemoryEntity resolution, projector (deltas →
  markdown vault), watcher (vault edits → diff → `MemoryEdited` delta), tierer (L0/L1 derived
  claims), retriever (L0 → L1 → L2 walk with trajectory).
- **`Kyber.Schema`** — the schema container actor + the genesis schema/hyperschema deltas;
  `validate/1` at admission (strict for declared lifecycle types, raw admission for unknown),
  `resolve/1` for typed access; codegen of Elixir structs from schema deltas is DERIVED
  convenience, never the authority.
- **Tool executor handler(s)** — fire on `ToolCall`, emit `ToolResult`.
- **CLI: `kyber agent`** — bounded, T8/T9 discipline; boots daemon + container actors on a
  configured store/keyring; `kyber memory` for vault projection/repair.

## Acceptance criteria

- **AC1 — The LLM handler is real and dependency-light:** `Kyber.Agent.LlmHandler` calls
  Moonshot (`MOONSHOT_API_KEY`, `kimi-k3`) with REAL non-deterministic content and zero new
  deps (stdlib `:httpc`/`:ssl` only; `mix deps` diff vs T10 is empty). verify: a test runs the
  handler against a canned Moonshot response (a stub HTTP adapter) AND a live smoke calls the
  real API once; `git diff 36205ba..HEAD -- mix.exs` is empty.
- **AC2 — The delta vocabulary is pinned (primitives ride, composites point):**
  `SubmittedPrompt` embeds {author-by-signature, timestamp, channel, prompt_text} and carries
  `sessionId`; `InferenceRequested` embeds primitives and points to `conversationRef`
  (session root/head) + `memoryPointers[]` + `promptRef`; `ResponseDelta` points back to its
  request + the memory claims it used. No delta embeds the conversation history. verify: a
  schema test asserts each lifecycle delta validates against its genesis schema and that no
  `InferenceRequested` in the test fixtures contains conversation text (pointers only).
- **AC3 — Re-boot idempotence holds WITH the LLM handler (the pointer guarantee):** daemon
  kill between the ack and the checkpoint with an in-flight LLM exchange → re-boot → the
  exchange does NOT duplicate (byte-identical re-fire → content-address dedup) and the answer
  claim persists exactly once. verify: the crash-window test (manufacture ack-persisted /
  checkpoint-lost, then re-boot) asserts one request delta, one response delta, and a counted
  skip.
- **AC4 — The operational run (THE gate):** Hermes boots the daemon on a tmp store/keyring
  with the LLM handler live; CLI-ingests a `message.received` whose content is a real question;
  the context builder fires, the model answers, the answer persists as `message.sent`
  (agent-signed, non-deterministic); the vault renders the exchange; SIGTERM; re-boot; no
  duplicate; the answer is still in the store. Bounded explicit polling, never
  `Process.sleep`. verify: the recorded operational run (this exact sequence) is the loop's
  acceptance evidence, machine-checked by the smoke.
- **AC5 — The store is the memory (grounded follow-up):** the handler's SECOND invocation is
  grounded in the FIRST exchange — the model sees its own prior `message.sent` claims and
  answers a follow-up that REQUIRES that memory ("what did I just say?"). verify: the second
  answer's content references the first exchange's content (asserted in the test).
- **AC6 — The memory store round-trips through markdown:** a MemoryEntity resolves → projects
  to a vault markdown file; a HUMAN EDIT to that file is observed by the watcher → a
  `MemoryEdited` delta (attested, `source: :human_edit`, old+new content) → the entity's canon
  re-resolves to the edited content; the edited memory carries `provenance: human` and the
  retriever ranks it above auto-derived memory. verify: a test writes a vault file, edits it
  out-of-band, ticks the watcher, and asserts the edit delta + the re-resolved canon + the
  provenance role.
- **AC7 — The schema layer is deltas, validated at admission:** the genesis schema deltas
  saturate the lifecycle; the door validates every delta that DECLARES a known lifecycle type
  against its schema (ill-shaped → refused; reject, never repair); unknown types are admitted
  raw and never saturate typed handlers; `Kyber.Schema.resolve/1` returns typed objects.
  verify: a test ingests a well-shaped `SubmittedPrompt` (admitted), a malformed one
  (refused), and an unknown-type claim (admitted raw, no typed handler fires).
- **AC8 — Tool chains are linked deltas:** a turn with a tool call produces
  `ToolCall` → executor → `ToolResult` → final `ResponseDelta`, each persisted and
  pointer-linked; the engine's in-flight state survives a daemon restart (the chain is the
  state); the UI projection is a lens — the smoke asserts the chain renders as
  prompt + final response with tool steps available (the projection API, not a special
  store path). verify: the tool-chain test with a stub executor asserts the link sequence,
  a mid-chain restart resumes, and the projection shows both collapsed and expanded views
  of the same store.
- **AC9 — The deterministic loop is the fallback, not a casualty:** with the LLM path
  disabled, the T10 built-in ack loop still works. verify: the T10 daemon/agent_loop tests
  stay green unchanged.
- **AC10 — Gates:** no `Process.sleep` in test/ (send_after/assert_receive only); rails
  (deps/, spec/, SPEC.md, mix.exs, config/) frozen — rails-guard clean; the real `~/.kyber`
  never touched (tmp store/keyring everywhere); format clean; warnings-as-errors clean;
  the memory store and schema container are swappable behind the same substrate (the A/B
  property: a second memory container can serve the same queries against the same store).
  verify: `grep -r "Process.sleep" test/` empty; rails-guard passes; `mix format
  --check-formatted` clean; `mix compile --force --warnings-as-errors` clean.
