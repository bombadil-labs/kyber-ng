## The slice

The agent's actions are governed. Three carries close here:
- **URL policy** (SSRF-open, T12 #4): HTTP actions carry a policy — schemes/hosts checked
  BEFORE any request; a refused URL never touches the network.
- **Policy epochs** (boot-frozen policy, T12 #5): policy can evolve WITHOUT restart —
  policies are store claims; each policy is an epoch; revocation is NON-RETROACTIVE (a
  decision made under epoch 1 stands even when epoch 2 supersedes it).
- **Idempotence enforcement** (documented-not-enforced, T12 #3): a duplicate ToolCall
  (same content-derived id) executes ONCE; the duplicate is absorbed and observed, never
  re-executed.

In scope: the policy claim shape + epoch semantics, the URL gate in the http action path,
the idempotence gate in the tool-execution path, and their refusal routing through the
closed "decides" loop (hosted, never rebuilt — the T14a reactor already routes refusals).
Out of scope: prompt-answer-as-delta + memory-read seam + operator-key boot wiring
(T14c), boundary enumeration + precision bounding (T14d), the M5 engine verdict fix (the
slice owning the engine's decides path — recorded, not fixed here, avoided by config).

## Acceptance criteria (draft — the rumble pins the exact shapes)

- AC1 (URL policy): a policy claim in the store gates an http action — an allowed URL
  executes (a request is recorded); a refused URL is refused with a policy GateDecision
  routed through "decides", and NO request is made (asserted, not assumed).
- AC2 (epochs): a second policy claim supersedes the first; the gate consults the CURRENT
  epoch; a decision made under epoch 1 stands (non-retroactivity asserted in the test);
  revocation means the current epoch changes, not that history is rewritten.
- AC3 (idempotence): a duplicate ToolCall executes once; the duplicate is observed
  (dedupe record), never re-executed — the side effect (e.g. an http request) happens
  exactly once across the original + duplicate.
- AC4 (live, @tag :operational): a real model turn triggers an http action — allowed URL:
  request recorded, machine-checked (request body, never answer content); refused URL:
  policy refusal, no request. (Tool-less or tool-bearing per the live config — the M5
  avoidance discipline applies.)
- AC5 (determinism): policy decisions derive from store state; epoch resolution is
  content-derived; no wall-clock in decisions.

### The Policy claim (exact)

`Events.policy(seed, ts, family, allow_hosts, allow_schemes, supersedes \\ nil)` via
the existing `build/4` machinery. Pointer order is content — pinned:

1. `%{role: "policy", target: {:entity, family, "epoch"}}` — kind marker, first;
   `@default_family "url_policy"`.
2. `%{role: "allow_host", target: {:string, host}}` — repeated; exact hosts only,
   downcased, port ignored (`URI.parse/1`), no regex, no wildcards (item 3).
3. `%{role: "allow_scheme", target: {:string, scheme}}` — repeated; REQUIRED for any
   allow (item 4).
4. `%{role: "supersedes", target: {:delta, prev_policy_id, "superseded"}}` —
   optional, at most one.
5. `type: "Policy"` rides last via `build/4`.

`"Policy"` and `"ToolCallDuplicate"` enter `Kyber.Schema.Genesis`
(lib/kyber/schema/genesis/genesis.ex) mechanically from the templates, AND (H1,
MANDATED) the existing `GateDecision` entry extends its optional list to
`optional: [{"reason", "string"}, {"policy_epoch", "delta"}]`. Without the
extension the pinned pointer is a dead end against closed validation
(`Compiler.check_fields` → `{:error, {:unknown_role, "policy_epoch"}}`) and all
four typed consumers choke on an epoch-attributed refusal: the engine's
`"decides"` dispatch never routes it (re-opening the T12 #1 hang class for
exactly this slice's refusal shape), the executor's stored-decision absorb scan
can't see it (voiding non-retroactivity for epoch-attributed refusals),
`Projection.refusal_of` renders the call in-flight forever, and the daemon's
`schema_door` refuses it. With the extension all four are typed-valid. Verified
ZERO-EDIT: the drift-proof test enumerates only the five infra emitters
(MessageReceived, MessageSent, PromptAnnotated, LlmResponse, ToolInvoked) — no
existing test pins GateDecision's optional set. This genesis edit is a
DELIVERABLE (§Deliverables). The genesis.jsonl regen step is per the T11a
record (citation corrected — L1: T12.md contains no genesis/jsonl mention); one

`mix run -e 'File.write!("lib/kyber/schema/genesis/wire/genesis.jsonl", Enum.map_join(Kyber.Schema.Genesis.deltas(), "", fn w -> {:ok, j} = Kyber.Wire.encode(w); j <> "\n" end))'`.

unsubscribed — the reactor's dispatch map takes it as `:ignore`, never an error.

### Epoch resolution — `Kyber.Agent.Policy` (pure, lib/)

`current(set, family \\ "url_policy") :: {:ok, epoch} | :none | {:error, :forked}`.
Current = the unretracted `Policy` claim of the family that is not the `supersedes`
target of any other unretracted family claim. Retracted (any `negates` pointer at
its id) ⇒ inert: neither current nor a superseder; retracting the current epoch
revives the previous unretracted one; all retracted ⇒ `:none`. Two unsuperseded
unretracted heads ⇒ `{:error, :forked}` ⇒ refuse-all. Pure set scans; no wall-clock
(AC5). Non-retroactivity is the executor's existing stored-decision absorb: a call
whose GateDecision is stored is re-emitted byte-identical, never re-decided.

### The URL gate (executor fresh-decide branch)

Applies to `@gated_tools ["http.get", "http.post"]`, after `Gate.decide/3` `:allow`,
before any execution. `Policy.current/2` ⇒ `:none` → allow (item 11);
`{:error, :forked}` → refuse; `{:ok, epoch}` → extract `"url"` from decoded args
(missing/undecodable → the policy layer ABSTAINS, deferring to the action's own
validation — P1, A1); check scheme then host (M2 PIN: downcase `uri.host` before
the exact compare — `URI.parse/1` downcases the scheme but NOT the host, and DNS
is case-insensitive; stored `allow_host` entries are already pinned downcased, so
the compare is exact on downcased-both-sides); no match → refuse.

Refusal wire: `Events.gate_decision(seed, call_ts, call_id, "refuse", "url_policy",
reason, epoch_id)` — kind `"decides"`, no ToolResult, the action never runs
(asserted, not assumed). Reason strings, exact:
- `"url_policy: scheme not allowed by the current epoch"`
- `"url_policy: host not allowed by the current epoch"`
- `"url_policy: epoch forked (fail closed)"`

**SYNTH-NEW-1**: the epoch attribution rides as an optional trailing arg on
`gate_decision` (default nil — existing /5 and /6 call sites byte-unchanged) adding
`%{role: "policy_epoch", target: {:delta, epoch_id, "under"}}` before the type
pointer, present on `url_policy` refusals only. Reason for the flag: P2 argued the
field as a content-map entry; no proposal argued the pointer-carrier spelling — this
is a mechanical translation into the adopted idiom, priced like UNARGUED and owned
by the premortem H-review.

When the policy layer allows, the executor emits the T12 gate's own decision
unchanged — byte-identical to today.

### Idempotence (executor absorb branches)

Enforcement already structurally exists (stored decision → re-emit; stored result →
re-execute never). The slice's delta is the OBSERVED record: on the
`stored_tool_result` absorb branch emit `[stored_result_wire, duplicate_observation_wire]`
— answer first. `Events.tool_call_duplicate(seed, ts, call_id, result_id)`:
pointers `%{role: "dedupes", target: {:delta, call_id, "deduplicated"}}` (kind
marker, unsubscribed), `%{role: "result", target: {:delta, result_id, "observed"}}`,
`type: "ToolCallDuplicate"` last. The claim's ts = the call's `claims.timestamp`, so
every duplicate derives the SAME observation id and merge-is-union yields exactly
one record per (call, result) pair — asserted as exactly-one, not existence (P1/P3
over P2). A duplicate is ACKED — stored ToolResult re-emitted byte-identical — never
refused (would misroute the engine), never silent. The `stored_gate_decision` branch
(refused calls) emits no observation: nothing executed, nothing to dedupe. The
three-layer once-only map is P3's (cited, §Borrowed): reactor ingest MapSet
(within-lifetime), store content-addressed admission (identical re-appends),
executor store-answer (re-fires/restarts).

### Reactor/engine integration + M5 discipline

Layered, one closed loop, zero rebuild: oracle gate at the reactor boundary, budget
at dispatch charging, URL policy in the executor's decide — `url_policy` refusals
ride the existing `"decides"` routing → hosted engine refusal path. One bounded
reactor edit (P1/P3; A2 conceded): `executor_for/2` gains
`context: Keyword.get(opts, :context, %{})` threaded to `ToolExecutor.handler/1` —
one keyword, hosting instrumentation, without which no recording seam exists on the
reactor path (AC1's "asserted, not assumed", AC4's tee).

M5 stays recorded-not-fixed; avoidance is CONFIG (the rail's verb — P3's
emission-reorder rejected as code + an existing-test edit): AC4 boots the gate as
`Gate.new(prompt: ["http.get", "http.post"], prompt_handler: fn _, _ -> :allow end)`
— the non-nil reason `"prompt answer wired: allow"` keeps the always-true guard off
the `Atom.to_string` crash; the spurious refusal is recorded-and-tolerated, never
asserted on. Explicit-allow (`allow: [...]`, nil reason) is FORBIDDEN in the live
config. Deterministic boots are `engine: :none` per the T14a record.

### Deterministic tests (per-AC pins, anti-placebo mandatory)

Topology (arbiter, hybrid of A2's `engine: :none` seam + A3's routing proof, per
P3's §7 idiom): executor-direct tests (Agent store, recording stub as
`context.http`, fixed claim timestamps) prove the mechanics; thin reactor
companions (`loop: :reactor, engine: :none`, tmp store/keyring, `:sync` barrier +
`assert_receive/3`, no `Process.sleep` ever) prove the `"decides"` routing.

- **AC1** — seed epoch `{hosts: ["allowed.example"], schemes: ["https"]}`. Allowed
  `https://allowed.example/x` → exactly one recorded request + allow decision +
  ToolResult. Refused `https://denied.example/` → `url_policy` refusal GateDecision
  (verdict `"refuse"`, pinned reason, `policy_epoch` → epoch id), NO ToolResult,
  request count unchanged. Reactor companion (H2 RE-PIN — the prior probe shape
  was a structural placebo): under `engine: :none` the handler holds the default
  deny-all `Gate.new()`, and the URL gate sits AFTER `Gate.decide` `:allow` — the
  policy layer never runs on that topology, and the `{:dispatch, "decides", _}`
  probe fires with or without the feature (the previously pinned fails-absent
  clause was false). Store-side shape adopted: the companion boots with a gate
  permitting the gated tool — `Gate.new(allow: ["http.get", "http.post"])`; the
  explicit-allow prohibition is M5-scoped LIVE-config discipline, and with
  `engine: :none` there is no engine verdict path to misroute — so `Gate.decide`
  returns `:allow` and the policy layer actually runs. The companion seeds the
  full ancestry the reactor's turn-walk requires: received message →
  InferenceRequested → refused-URL ToolCall, with the oracle seed handled — a
  bare ToolCall never dispatches. The ASSERTION is the persisted `"url_policy"`
  GateDecision (with its `policy_epoch` pointer) in the companion's store; the
  dispatch probe is DEMOTED to a routing signal — it may be observed for
  sequencing, it is never the fails-absent witness. *Fails-absent* (restated):
  executor-direct — the refused URL records a request and no `"url_policy"`
  decision exists; companion — the store holds NO `"url_policy"` GateDecision
  for the refused call (the probe proves nothing either way).
- **AC2** — epoch1 allows `a.example`; call C executes (1 request, decision G1).
  Epoch2 (M1 PIN, exact seed shape)
  `{hosts: [], schemes: ["https"], supersedes: epoch1}` — the revocation: the
  scheme list stays nonempty so the scheme check passes and the empty host set
  refuses, making the expected reason determinate under the scheme-then-host
  order. Both builds assert the exact refusal sentence
  `"url_policy: host not allowed by the current epoch"`. (i) re-fire C's delta →
  G1 re-emitted byte-identical, still 1 request, one ToolCallDuplicate; (ii) fresh
  C2, same URL → refused with that sentence, `policy_epoch` → epoch2's id;
  (iii) retract epoch2
  (`negates`) → `Policy.current/2` revives epoch1 (asserted on the pure function)
  and a fresh call executes; epoch2's claim is STILL in the store (P3's
  history-presence assertion). *Fails-absent*: without epoch resolution C2 executes;
  without the absorb C is re-decided under epoch2 (a second, differing decision
  appears); without negates-honoring the post-retraction call stays refused;
  without history-preservation the epoch2 lookup fails.
- **AC3** — ingest allowed call D, then the SAME delta twice more → exactly ONE
  recorded request across all three, one ToolResult, exactly one ToolCallDuplicate
  (union-collapsed). *Fails-absent*: 3 recorded requests; the dedupe query returns
  empty.
- **AC5** — the AC1/AC2 seed sequence in two fresh boots → GateDecision/
  ToolCallDuplicate ids byte-identical; every emitted claim's ts equals its call
  delta's `claims.timestamp` exactly. *Fails-absent*: any wall-clock in the decision
  path diverges the ids or the timestamps.
- **AC4** (`@moduletag :operational`, self-skips without the key) — real model,
  tool-bearing; prompt-allow gate per the M5 discipline; recording tee wrapping
  `HttpClient.Httpc` as `context.http`; the seeded epoch lists its schemes
  EXPLICITLY (item 4 — no default exists). Allowed leg (H3 RE-SCOPE): under the
  M5-avoidance config the engine's string-vs-atom verdict guard (verified live)
  misroutes every allow into the refusal path — the model sees
  `"refused: prompt answer wired: allow"` and may legitimately re-fire the
  action, so "exactly one recorded request" is flaky by construction. Pinned:
  the live allowed leg machine-checks the FIRST recorded request (method + URL +
  request-body marker) and the persisted `gate_decision` + `tool_result` pair
  for that call — never answer content; exactly-one is DETERMINISTIC-ONLY
  (AC1 owns it). The fabricated refusal shown to the model is behaviorally
  accepted beside this leg (M6 — already carried in the register):
  recorded-and-tolerated, never asserted on. Refused leg: epoch allowing only `allowed.example`, model
  prompted elsewhere → `url_policy` refusal persisted AND zero recorded requests.
  *Fails-absent*: a turn that never triggers the action records zero requests
  (allowed leg fails); a non-gating policy layer records a request (refused leg
  fails).

### Diff metric (plan-fidelity bar for the two builds)

this shared-elements list with the pinned spellings: (a) the Policy template's five
pointer roles in the pinned order, exact-host/explicit-scheme semantics, no defaults,
genesis entries for both new types; (b) chain-walk supersession with

each AC's fails-absent behavior demonstrable. Divergence in helper names, private
decomposition, or test internals is NOT design-level; divergence in any pinned wire
spelling, pointer role/order, default, placement, or file above IS design-level and
fails the metric.
