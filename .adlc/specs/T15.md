# T15 — Agent I/O surface + model configurability (the Wisp slice)

## Purpose
Stand up an **isolated kyber agent ("Wisp")** as a sibling-in-waiting for Liet, and in
doing so build two reusable capabilities the harness lacks:

- **F1 — configurable model/provider.** The engine already accepts a pre-built
  `LlmHandler` (engine.init `:llm` opt). Today the *only* construction site is
  `reactor.ex:481-482`, hardcoded to Moonshot `kimi-k3` (`@base_url`/`@model`).
  Make the daemon boot thread `:api_key/:base_url/:model/:system_prompt` through to
  `LlmHandler.new/1`; default behavior UNCHANGED (k3). This lets Wisp run on the
  user's direct deepseek account.
- **F2 — per-agent persona.** `LlmHandler` carries `@system_prompt` hardcoded AND
  `prompt.ex:66` has a *second* `@system_prompt` for the assembly path. Both must be
  overridable per-boot so Wisp gets his own voice; the default kyber prompt is preserved.
- **F3 — `kyber ctl` control client.** A non-interactive CLI verb over the EXISTING
  channel-socket JSONL protocol (`{"verb":"send"|"status"|"tail"|"tick"}` at `<log>.sock`).
  `kyber ctl --log <path> send "<msg>"` / `status` / `tail` / `tick`. Replaces the
  stdin-kludge TUI for automation and is the future sibling-operator door (Liet's
  operator drives Wisp's daemon identically). Exit-coded like the rest of the CLI.
- **F4 — skills for Wisp.** Seed 1-2 read-only skills into Wisp's store at boot via the
  `skill:`-family epoch (proves the profile skill lens path works end-to-end). Non-
  destructive, no terminal-permission tools.
- **F5 — isolation.** Wisp boots on `/tmp/wisp/` store + keyring (NEVER `~/.kyber`),
  fresh operator seed minted on first boot. Opens a `Kyber.Peer` TCP listener so a
  later Liet can federate with him (the sibling topology the sequence was built for).

## Why now
The T14 arc wired reactor workspace threading, profiles, channels, always-on context, and
the crash-window rider — the substrate for "one instance, multiple profiles / sibling
agents." T15 exercises that substrate for real and closes the two gaps (model config,
clean I/O) that make spinning up an arbitrary agent a one-command act.

## Acceptance (AC)
- **AC1** `LlmHandler.new/1` accepts `:system_prompt`; when present it overrides
  `@system_prompt` in `conversation/1`. `Prompt.system_prompt/0` accepts an override
  (app env `:kyber, :system_prompt` or boot opt) falling back to the kyber default.
- **AC2** reactor boot threads `:api_key/:base_url/:model/:system_prompt` to the handler
  build; with none supplied the behavior is byte-identical to today (k3 defaults).
- **AC3** `kyber ctl --log <path> send "<msg>"` connects to `<log>.sock`, sends the
  JSONL frame, prints the daemon's `{"ok":true}` (or `{"error":...}`), exits 0/1.
  `status`/`tail`/`tick` verbs behave per `channel/socket.ex` (M7/M8).
- **AC4** A live turn against deepseek (the user's direct account) answers end-to-end;
  Wisp's persona system prompt is observed in the request body (operational test, like
  `reactor_operational_test.exs`).
- **AC5** Wisp boots isolated on `/tmp/wisp/`; his store and keyring are the ONLY files
  written there; `~/.kyber` is untouched. His `Peer` listener accepts a federation frame.
- **AC6** 1-2 seeded skills are visible to Wisp via the profile skill epoch (no crash,
  fail-closed when ungoverned).

## Out of scope
- Multi-provider *routing* / fallback inside one agent (one model per boot is enough).
- In-process siblings (the daemon is a singleton `__MODULE__`; siblings = separate
  processes + federation, by design — not a refactor this slice).
- Liet's actual return (deferred; T15 only proves the topology Wisp will join).

## Design notes (resolution)
- Edit sites: `reactor.ex:481-482` (thread opts → `LlmHandler.new`), `llm_handler.ex`
  (add `:system_prompt` field + thread into `conversation/1`), `prompt.ex:66` (override
  hook), `cli.ex` (new `ctl` verb + socket client, mirroring `tui`'s connect code).
- The channel socket protocol is PINNED in `channel/socket.ex` — `ctl` must speak it
  verbatim (RECV-accumulate to trailing `\n`, 0600 UDS auth is filesystem-permission).
- No change to `deps/`, `spec/`, `mix.exs`, `config/` (frozen). App-env override for
  `:system_prompt` goes through the existing `Application.get_env(:kyber, ...)` pattern.
