# T14g — Agent Identity: Soul Docs, Profiles, and the Always-On Block

Status: OPEN (light ceremony — rumble for the design cells, one deterministic
build). Parent: T14f (merged; provisional/t14 @ b52183e — the premortem probes
ran through the real door post-merge). Rails: carried.

## The framing

Hermes injects USER.md (who the user is) + MEMORY.md (agent notes) into every
turn; OpenClaw ships a person.md as the persona. Both treat identity as STATIC
blobs. kyber's unique affordance: identity is a DERIVED ENTITY — a view over
its delta stream, exactly like skills (T14f's binding framing). A "soul doc"
is not a file; it is the fold of identity primitives, rendered into the
always-on system block. And PROFILES are policy-shaped: the epoch machinery +
the gate allowlist already know how to bound visibility and capability — a
profile is a named binding of (identity view, memory/skill visibility,
capability subset), not a new storage mechanism.

## The primitives (the rumble pins the set)

Identity primitives = named entities whose canon folds into the always-on
block. Candidates:
- `soul` — who the agent IS (persona, voice, values, the "Veles" layer for
  Liet). Operator-attested (the agent does not write its own soul).
- `user` — who the operator/user is (preferences, context, how to be useful).
- `operator` — system/operator constraints (hard rules, escalation paths).
- `profile` — the active profile's own rules (per-channel behavior).

Each primitive = an entity (like `memory:cap`) with a versioned body; the
fold renders it. Writability is gated (the T14c fail-closed pattern: the
soul/user docs are operator-attested writes; agent-writable memory stays in
the memory seam).

## The always-on block (G3)

The system block in Prompt.assemble: [system, identity (soul, user,
operator, profile rules), memory_notes, summary_notes, skill_notes, elision,
turns] — identity primitives FIRST, before the ad-hoc notes. Capped (byte
bound), deterministic ({timestamp, id} fold), rendered by the same lens
machinery as skills. (An earlier draft of this bracket read "memory_notes,
skill_notes, summary_notes" — a prose contradiction against the T14f M3
parent pin; corrected to summary-then-skill, see the resolution G3.)

## Profiles (G4-G7)

A profile = a named binding of THREE things:
1. **Identity view** — which primitives ride (a Discord server profile might
   ride the soul but NOT the broader user doc).
2. **Memory/skill visibility** — bounded by a policy epoch (the memory +
   skill epochs' allowlists define what the profile can see; a channel profile
   has its own epoch — no access to broader memory).
3. **Capability subset** — the gate allowlist (Gate.new(allow: [...])) ∩ the
   boot tool registry; a channel profile runs a subset of tools.

Profiles are declared (a profile-entity delta family) + selected at boot
(the reactor/attach boot takes a profile id). The SAME Kyber instance hosts
default / coding-agent / per-channel profiles — the identity view, the
epochs, and the gate differ; the store is shared but the visibility is
epoch-bounded (the atom: the store only learns; profiles bound the VIEW).

## Acceptance criteria (shape)

AC1 — the always-on block: a boot with a soul + user doc renders them FIRST
in the assembled prompt, deterministic, capped (the identity fold witnessed).
AC2 — profiles: a default profile and a channel profile boot on the SAME
instance — SEQUENTIAL boots over one store (Revision 1/H3: two engines over
one store double-answer); the channel profile's memory/skill visibility is
epoch-bounded (cross-profile leakage witnessed ABSENT — the `:none` arm, the
replay seam, AND the tool surface); its capability subset is enforced (the
gate refuses what the profile doesn't allow).
AC3 — writability: the soul doc rejects agent writes (operator-attested
only); the user doc likewise; the memory seam is unchanged.
AC4 — determinism: identity + profile folds are {timestamp, id}-ordered,
replica-identical (the T14f D2 norm).

## Design resolution (converged plan)

The rumble (P1/P2/P3 → A1/A2/A3 → R1/R2/R3, `.adlc/rumble-t14g/`) converged
on every contested cell. The binding framing held: **an identity primitive is
a DERIVED ENTITY — a fold over its delta stream, exactly like a skill (T14f);
a profile is a POLICY-SHAPED BINDING (identity view + epoch-bounded
visibility + gate capability subset), never a storage mechanism.** The
resolutions below are pins, not sketches. Revision 1 (premortem fold)
adds the boot-context threading (R1 — the keystone every other pin hangs
off), the author-filter pins, the AC2 witness re-pin, the replay-key matrix,
the render-format pins, and the T14f first-assembly fix; the fold log is at
the foot of this document.

### R1 — the boot context: one object, threaded everywhere (premortem H1 — the keystone)

One boot context `{profile | nil, operator_author | nil}` is derived at
attach and threaded attach → `Engine.start_link` opt → engine state → BOTH
assemble sites (engine.ex:200 and engine.ex:508) + `replayed_prompt`
(engine.ex:259) + `resume/1` + the tool executor handler (M2). The attach
surface (agent.ex:33-74) grows TWO new opts: `:profile` (G5) AND
`:operator_seed` — the latter DOES NOT EXIST on attach today (the only
`:operator_seed` surface in the repo is the REACTOR path, reactor.ex:509 /
daemon.ex:540, which G5 carries OUT of slice); **the new attach opt is a
DELIVERABLE**. The fold's boot-constant author is derived ONCE at boot:
`Keys.author_for_seed(operator_seed)` — and `author_for_seed(nil)` RAISES
(probed: "invalid seed"), so the nil-seed leg is pinned FAIL-CLOSED: **no
operator seed ⇒ no identity block at all (and no crash)** — never a crash,
never a fail-open leak. G8's `:none` flip conditions on the threaded profile;
N2's keying reads it at the replay check.

**The T14f first-assembly defect rides this fix (probed — a merged-site
miss)**: engine.ex:200 (the primary infer path) never passes `prompt_text` —
the skill lens is DARK on first assembly and only fires in `rebuild_pending`
(engine.ex:508-514). This build fixes it: pass `prompt_text` at :200 and add
a witness leg asserting a first-assembly skill note is present (the skill
lens fires on the PRIMARY path, not just on rebuild).

### G1 — the primitive set: three closed kinds (easy)

`["soul", "user", "operator"]` — a CLOSED kind set; profile rules ride on the
ProfileSet binding (G2), not as a fourth primitive. Agent-writable
profile-scoped notes are a **recorded CONVENTION over the memory seam**
(entity names under the `profile:<id>:` namespace) — NOT a fifth primitive;
AC3's memory seam is unchanged. An unknown kind string never folds (closed
set, fail-closed) — reject at the write surface, inert in the fold.
**Exact-match semantics (L4)**: `check_memory` is `entity_id in
allow_entities` (policy.ex:145-146) — NO prefix matching; every
`profile:<id>:` note entity must be individually allowlisted in the
profile's memory epoch (an operator expecting namespace wildcarding will
under-allow; the fork brief says so).

### G2 — genesis kinds: `IdentitySet` + `ProfileSet` (moderate)

Two new @defs kinds — **genesis evolution is a DELIVERABLE (the T14f H5
lesson: unknown types admit :raw)**:

- **`IdentitySet`** — entity pointer + kind/body/source. The primitive's
  ENTITY POINTER (`identity:<id>`) is the binding (P2/P3 over P1's bare kind
  role): one entity per primitive, whole-set supersede per T14f H6. The
  pointer's role name is `entity` — the MemoryEntity precedent (M5c);
  harmless today (no colliding subscriber — memory intake type-filters),
  pinned deliberately.
- **`ProfileSet`** — name / rides / allow_tool / rules / families. The
  declaration delta family; the name is the attach key (G5). Role kinds
  pinned (M5b): `rides` as `identity:<id>` ENTITY REFS, `allow_tool` as
  STRINGS (the tool ids), `families` as STRINGS (the family names).
- **Author-filtered (H2c)**: ProfileSet declarations carry the SAME author
  filter as identity primitives (R1's `operator_author` stream) — an
  agent-declared newer ProfileSet under an expected name with
  `families: ["memory"]` would escalate visibility at the next attach; the
  filter closes it. `{timestamp, id}` ordering applies WITHIN the author's
  stream (H2).
- **Supersedes pointer: NONE** — `{timestamp, id}` order alone supersedes
  (the T14f H1 norm). P3's optional pointer REJECTED: redundant,
  disagreement-prone.
- **Value-fold forks**: two live same-kind heads (both from the boot-constant
  author) resolve by explicit latest-wins on `{ts, id}` (the content-derived
  head) — NEVER the Policy fork error. Pinned so it is testable, not merely
  emergent.
- **Removal rides RAW negations (L2)**: no identity retraction builder
  exists (no `Kyber.Agent.Events.identity_retract`, no `Kyber.Events.retract`
  — probed); the operator hand-rolls raw negations this slice, and the
  negator scan stays KIND-AGNOSTIC (the dangling-negation door stays open by
  design).
- Deliverables: genesis @defs + `genesis.jsonl` regen (byte-for-byte gated,
  the T12 discipline) + builders `Kyber.Agent.Events.identity_set/…` and
  `Kyber.Agent.Events.profile_set/…` — T14f-style arities carrying the FULL
  payload (the events.ex:208 `skill_set/5../7` precedent; `/2` cannot carry
  it) + drift-proof entries in schema_test.exs:199-221 (the T14f
  skill_set:207-213 discipline — "the fold only sees typed deltas, so schema
  drift would blind it silently"). `Kyber.Agent.Events` is named explicitly
  (Kyber.Events is the T10 infra seam).

### G3 — the always-on block: slot, cap, never windowed (easy)

- **Note-tier order (the T14f M3 parent pin, byte-for-byte)**: system →
  **identity** → memory → summary → skill → elision → turns. The identity
  block is FIRST after the system message, before memory_notes. (The spec's
  original bracket read memory → skill → summary — a prose contradiction,
  fixed above.)
- **Cap**: 8192 TOTAL rendered bytes across the identity block,
  skip-and-continue (a primitive that would blow the bound is omitted
  entirely, never truncated — selection, not repair). **DISJOINT from the
  skill lens's 8192** — two budgets, never pooled.
- **Identity is NEVER windowed**: the identity block precedes the turn
  window and is never elided by the window lens — `window: 0` still renders
  the block (N4, adopted uncontested).
- Fold determinism: `{claims.timestamp, id}` (T14f D2), replica-identical,
  no wall-clock.
- **Render format — pinned byte-for-byte (H5; AC1's witness is written
  against THIS)**: per-primitive note spelling `"Soul: " <> body` /
  `"User: " <> body` / `"Operator: " <> body` (the house discipline:
  prompt.ex:60/67/174). Intra-block primitive order = the CLOSED-SET order
  soul, user, operator — NOT `{ts, id}` of heads (the set is closed and
  ordered). The profile-rules segment renders as `"Profile: <name>\n" <>
  rules` AFTER the three primitives and COUNTS against the 8192. The cap's
  accounting unit = RENDERED NOTE BYTES (the prompt.ex:177 discipline);
  skip-and-continue applies PER PRIMITIVE.

### G4 — liveness/removal: T14f H2/H3 VERBATIM (hard)

The identity fold's liveness is the SKILL fold's liveness, verbatim —
order-head, recursive-existential through the whole negation chain, restore =
negate every live negation of the head, removal NEVER re-exposes the prior
set (the forbidden retraction-path rollback), recomputed per read, never
latched. **The probe-2 truth table is the oracle** (T14f D4: B/C/D/E/F legs —
flat scans kill restore; the house negation pattern is flat in five places,
do NOT copy it). An identity doc REMOVED is fold-inert and never re-exposed;
re-creation beats revival with no special case.

**Author filter FIRST, then ordering (H2 — the skill fold is author-BLIND;
identity is not)**: probed through the real door (`Store.admit`) — an
AGENT-signed raw negation kills an OPERATOR-signed set
(`Skill.negators/2`, skill.ex:119-124, is kind- AND author-agnostic), and a
newer set supersedes regardless of signer (the shadowing leg). For identity,
ALL folds — primitives AND ProfileSet declarations AND negations — are
AUTHOR-FILTERED BEFORE `{ts, id}` ordering:
(a) the stream is PRE-FILTERED to R1's boot-constant `operator_author`
claims BEFORE head selection — an agent's newer inert write can never SHADOW
the operator's live soul (ordering DoS closed); (b) negations are
author-filtered too — an agent cannot retract the soul out-of-band; (c)
ProfileSet declarations carry the same filter (G2). The probe-2 oracle stays
the LIVENESS oracle (B dead / C live / D dead / E live / F dead — verified
green through the real door).

**Operator rotation (unargued, deepseek R2 — absorbed)**: the fold's author
is BOOT-CONSTANT — derived ONCE at boot from R1's `operator_author`
(`Keys.author_for_seed(operator_seed)`; `nil` ⇒ no identity block at all,
fail-closed per R1); a rotated operator's identity docs are fold-inert at the
next boot. **Witness pinned: "the old persona never re-renders
post-rotation"** — an N8 edge leg in identity_fold_test.exs.

**Shared liveness helper (M1 — pinned: ONE implementation)**: extract a
shared recursive-existential helper parameterized by a NEGATOR FILTER —
identity passes the author filter (H2), skill passes identity (author-blind,
unchanged) — OR explicit re-implementation witnessed by re-running the
probe-2 B/C/D/E/F legs for identity through `Store.admit`. The shared helper
is PREFERRED; either way there is exactly ONE recursive-existential
implementation, never two divergent ones. Copy skill.ex's revisited-id
path-guard ("revisited id answers live", skill.ex:105-117) VERBATIM (L3 —
cycles are unconstructible with content-derived ids, so the guard is
belt-and-suspenders, but copy it anyway).

### G5 — profile selection: the ATTACH surface (easy)

- **Surface**: `Agent.attach/1` grows TWO new opts (agent.ex:33-74): the
  `:profile` opt (default_tools seam agent.ex:78-83) AND the
  `:operator_seed` opt (R1 — a DELIVERABLE; the opt does not exist on attach
  today — the reactor path is the only surface and it is carried out). **The
  reactor path is a RECORDED CARRY** — daemon.ex:534-542 drops opts; do NOT
  thread it this slice.
- **Unknown/undeclared profile**: refuse LOUDLY at attach —
  `{:error, {:unknown_profile, name}}`. No silent fallback to profile-less
  boot (that is the leak). **Whitespace-only names resolve the same way
  (M7)**: a `" "`-named ProfileSet is door-admissible (probed: `" "`
  validates, only `""` is refused — delta.ex:115-118) — attach treats
  whitespace-only names as UNRESOLVABLE ⇒ `{:error, {:unknown_profile,
  name}}` (fold-inertness applied to the LOOKUP, N3).
- **Default profile semantics**: the default is the ABSENCE of selection —
  no magic names, no reified "profile:default" entity required.
- **Byte-identical preconditions (M4 — G5's "byte-identical to today"
  spelled)**: byte-identical holds for (a) a store with NO live identity
  primitives AND (b) the nil-`:operator_seed` leg (R1 — no identity block).
  A profile-less attach over a store WITH live identity docs RENDERS the
  block — that is AC1, not a regression.

### G6 — capability enforcement: construction-time intersect (moderate)

The profile's tool registry = `Map.take(registry, allow_tool)` ∧ the boot
gate preserved — the profile only NARROWS, never widens (no escalation: a
tool absent from the boot registry cannot be conjured by a profile).
Enforcement is at gate/registry CONSTRUCTION, not a new mid-chain check —
P3's `profile_check` chain link REJECTED (violates the T14f L1 append-last
norm). **ZERO new reason strings**: a profile-refused tool answers with the
existing spellings (unknown-tool / gate-refusal); the reason-string set is
regression-frozen.
- **One-sided intersect is a build trap (L1)**: the `Map.take` intersect
  must hit the SINGLE `tools` var (agent.ex:39) feeding BOTH the engine specs
  (agent.ex:46-47) AND the executor registry (agent.ex:66) — a one-sided
  intersect either advertises dead tools or leaves profile-excluded tools
  executable. "Boot gate preserved" (agent.ex:67) is the only thing stopping
  a build from conjuring allows via `Gate.new(allow: profile.allow_tool)` —
  the single-var intersect is the guard.

### G7 — writability + operator authority (easy)

- soul/user/operator writes are OPERATOR-ATTESTED: the author id is DERIVED
  from the attach-threaded `:operator_seed` (events.ex:244 — the existing
  operator attestation seam; the boot context's `operator_author`, R1);
  **no new author opt**. Agent-authored identity writes are refused (AC3).
- **AC3's rejection is FOLD-INERTNESS, not a reason string (M6)**: there is
  NO identity write tool this slice (the registry is fs/sh/http +
  memory.read + skill.* — tool_executor.ex:128-168), so the agent cannot
  attempt an identity write through any gated surface and NO reason string
  is ever emitted. Probed: an agent-signed IdentitySet admits `:ok` through
  `Store.verify` (the door is signer-agnostic) and is FOLD-INERT — it never
  renders. G6's reason-string clause applies only if a write surface appears
  (a later slice).
- Agent-writable per-profile state rides the MEMORY seam under the
  `profile:<id>:` naming convention (G1) — gated by the profile's memory
  epoch like any memory write; the memory seam's machinery is untouched.

### G8 — profile-epoch wiring + the `:none` flip (moderate)

- **Family-name references, resolved LIVE**: the ProfileSet carries family
  NAMES, resolved at read via `Policy.current/2` — never compiled-in
  allowlists (P2's carried-allowlist compile rejected: no emission path,
  couples rotation to whole-set redeclare; live refs rotate by ordinary
  supersede).
- **Derived fail-closed defaults**: a profile that names no family gets
  `"memory:profile/<name>"` / `"skill:profile/<name>"` — its OWN empty-until-
  seeded epochs, never the broad boot epochs (fail closed).
- **The `:none` gather arm FLIPS under a profile (load-bearing — N1)**: the
  legacy fail-open memory gather at `:none` (prompt.ex:113, the T14f L8
  asymmetry) would leak the whole store into an ungoverned channel family —
  exactly AC2's leak. Under ANY active profile, `:none` ⇒ OMIT-ALL. The
  legacy arm stays for profile-less boots (byte-identical legacy behavior).
  **The flip's condition is the threaded profile (R1)**: "under ANY active
  profile" is a read of the boot context — `profile != nil` ⇒ OMIT-ALL;
  profile-less boots keep the legacy arm. The always-on context block (T14h)
  inherits this flip (L5): with R1's context object the flip is a CONTEXT
  READ — T14h must consume the same object, not re-thread.
- **Tool-side policy layers are profile-aware too (M2)**: `memory_policy` /
  `skill_policy` (tool_executor.ex:291-348) consult the BOOT families today
  (`Policy.memory_epoch/1` / `skill_epoch`, policy.ex:115) — under a profile,
  the epoch source is the PROFILE's families (the derived defaults), and the
  R1 context threads into `ToolExecutor.handler` (agent.ex:64-69). AC2's
  "leakage ABSENT" covers the TOOL surface, not just the gather.
- **Multi-family combination = UNION (M3)**: the profile sees a family if
  ANY named family governs it; the per-family forked leg omits THAT family
  ONLY (forked ≠ omit-all when other families are clean).

### N2 — the replay seam: profile-keyed PromptAssembled (moderate)

PromptAssembled is PROFILE-KEYED with match-or-rederive: a stored prompt
minted under profile A is never served to a boot under profile B
(engine.ex:256-283 stored-claim-wins would cross-serve bytes — AC2's leak
through the replay door). The key, the matrix, and the mechanics are pinned
(H4 — all three touchpoints are DELIVERABLES):

- **The key**: role name `profile` + type `{:string, name}` (a string, not
  an entity). The genesis cost of the key field is pinned as part of the G2
  evolution.
- **Emission**: the key rides ONLY under a profile — profile-less mints stay
  BYTE-IDENTICAL (G5/M4's pin). The builder grows `Events.prompt_assembled/5`
  → `/6` (events.ex:200; the extra arg carries the key).
- **The matrix (closed)**: (c) an UNKEYED pre-T14g PromptAssembled presented
  to a profiled boot does NOT match — the A→B leak through OLD stores is
  closed; (d) a KEYED claim vs a profile-less boot does NOT match (the
  converse); keyed-vs-unkeyed is a MISS, never a cross-serve.
- **Exactly-one is per (request, profile)** — the same request may
  legitimately produce one stored claim per profile.
- **Mechanics**: the mint site (engine.ex:206-212), the replay check
  (`replayed_prompt`, engine.ex:259), and the builder (events.ex:200) all
  change — ALL THREE are deliverables, with drift-proof entries in
  schema_test.exs:199-221.

### N3 — whitespace-only names/ids: fold-inert (easy)

A whitespace-only identity kind/id or profile name is FOLD-INERT — never
repaired, never normalized (reject-never-repair; the T14f N1 lesson, but
identity kinds have NO tool boundary, so inertness lives in the fold).
Whitespace names are DOOR-ADMISSIBLE (probed: `" "` validates; only `""` is
refused — delta.ex:115-118), so inertness applies to the LOOKUP too (M7):
attach's profile resolution treats whitespace-only names as UNRESOLVABLE ⇒
`{:error, {:unknown_profile, name}}` (the G5 path).

- **AC1** — a boot with a soul + user doc renders the identity block FIRST
