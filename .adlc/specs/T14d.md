# T14d — Boundary Enumeration: Failure-Mode Inventory

Status: OPEN (light ceremony — rumble for the design cells, ONE deterministic
build, no blind taste). Parent: T14c (`45a8eb9` on main, merged `4058707`).
Rails: carried (frozen `deps/ spec/ SPEC.md mix.exs config/`; no Process.sleep;
canonical spellings; content-derived identity; merge-is-union; retraction-is-negation).

## Scope

The systematic inventory of the policy layer's failure modes — every gate × input
interaction, every tool boundary, every engine path — pinned to an exact behavior
and witnessed by a deterministic test. The slice's deliverable is the MATRIX: a
cell per boundary case, each with a pinned outcome and a fails-when-absent leg.

In scope: the memory_policy clause table's undecidable cells (the T14c deferred
fork×undecodable + its neighbors), url_policy edge inputs, the tool boundary caps
(fs.read output, fs.list entries, web_fetch size/timeout, shell containment,
http.get redirects), the engine path pins (constructor fail-hard, replay
decode-failure raise — the T14c taste cells), the store/epoch mechanics
(fork-precision beyond two live heads, merge, retraction), and precision bounding
(exact values, exact behaviors — no "reasonable cap" language).

Out of scope: the M5 engine verdict bug (engine.ex:161 atom-vs-string guard —
the separate engine-decides slice; live config discipline still applies), URL
policy redesign, new tool surfaces, the operational/live ACs (all cells here are
deterministic), the channel adapter (Liet's import).

### The ten cells, resolved

**D1 — A1 fork × undecodable → REFUSE.** `{:refuse, "memory_policy",
"memory_policy: epoch forked (fail closed)", nil}` — the existing literal, no
new string; NO ToolResult. Epoch-arms-before-decode is NORMATIVE
(tool_executor.ex:226-250): args are never examined under fork. The spec's
A1 ":allow" column is recorded defect S2, corrected to refuse.

**D2 — A4 ungoverned × undecodable → REFUSE (memory) / recorded debt (url).**
Memory refuses `memory_policy: no governing epoch (fail closed)` (existing
literal), NO ToolResult — the `:none` row precedes args decode. The url twin
(`:none → :allow`) is pinned as behavior and recorded as **fail-open debt with
a deferred owner** (the governance-default slice) — witnessed as a tripwire so
the fix must consciously flip a test, never drift.

**D3 — B7 + n-head fork → refuse-before-resolve; any n≥2 ⇒ `{:error,
:forked}`.** Under a forked epoch, `memory.read` gets exactly one GateDecision
(forked reason, nil epoch), NO ToolResult, and `Memory.canon` NEVER runs —
refused known/unknown indistinguishable (no existence oracle). Fork detection
is count-insensitive: the `_two_heads` catch-all (policy.ex:140) is normative
for any n≥2 live heads — same tuple, same reason, no distinct error, no
winner-picking. Micro-fold: rename the clause comment `_two_or_more_heads`
(P3, comment-only).

**D4 — concurrency bound → cap 1 STRUCTURAL; at-cap QUEUE in commit order.**
The cap is the substrate's structure, verified: one GenServer `handle_cast`,
synchronous `LlmHandler.chat/3` inside the cast, zero Task/spawn in
`engine.ex`. NO new literal, NO new GateDecision surface. At/past cap:
requests queue in the mailbox, processed in commit order — never refuse, never
drop. Witness: blocking-stub leg (stub blocks on `receive :release` — sanctioned
synchronization; runs inside the engine process, released by `send(engine,
:release)` — no `Process.sleep`), exactly one `{:llm_request, _}` pre-release.
**The pre-release count alone does NOT discriminate commit-order-vs-reorder**
(M4): two requests over an empty store assemble identical bodies
(probe-confirmed), so body inspection cannot order them. Add the
discriminating channel: assert the notify seam's `{:answered, request_id}`
ORDER (engine.ex:98, 311 — probe: req-A answered before req-B), or use
per-session distinct conversation fixtures. Recorded rider:
the mailbox is unbounded; the pin bounds WORK, and once-per-delta-id routing
bounds distinct work per delta to 1. **Rejected:** P2's 16-refuse (underived
literal — AC5's banned "reasonable cap"; engine-minted refusal crosses a layer
that only consumes `"decides"`) and P3's `@max_in_flight` (a literal with no
enforcement site — AC5 decoration).

**D5 — A9/A10 url degenerate inputs → converged outcomes.** (a) Non-binary /
absent `"url"` (JSON null, number, missing key, non-JSON args): policy ABSTAINS
→ the action answers (`"refused: url must be a string"`/`"refused"` for null;
missing-key `"error"`); no request. (b) Binary-but-malformed: refuse in
scheme-then-host order — no scheme ⇒ `url_policy: scheme not allowed by the
current epoch`; scheme ok + empty host ⇒ the host reason. (c) A10 vacuous
epoch: empty `allow_schemes` refuses all at the scheme clause; empty
`allow_hosts` at the host clause — no default exists, refuse-all stands.
Fixtures: `URI.parse("https://")` → host `""` (NEVER nil — substrate-verified;
P3's nil≡empty collapse is moot); both proposed fixture sets land the same
reason.

**D6 — B1 fs.read cap → 65_536 via `context[:output_cap]` (action.ex:32), in

### Class C — the engine pins

`"PromptAssembled construction failed: :timestamp_not_a_number"` — no
