## The cells

**C1 — Reactor workspace threading (T14f D9's other half / T14g G5 carry).**
The attach path boots workspace-aware: `default_tools(opts)` (registry +
memory + skill tools when a `:workspace` is present; agent.ex:51, 92-101)
+ `Profile.intersect_tools`. The REACTOR path (daemon.ex:534-542's
whitelist: budget_cap/engine/test_pid/operator_seed) threads NO workspace —
a `--loop reactor` daemon with a workspace still boots `stub_tools()`
(reactor.ex:441's default) unless tools are passed explicitly. The carry:
the reactor's engine construction consumes the SAME workspace-aware default
+ the profile intersect (the T14i H8 fourth touchpoint, extracted shared
helper) when a `:workspace` + `:profile` are threaded. The witness: a
reactor-booted daemon with a workspace advertises memory.read + skill.read
(the T14f D9 witness class, now on the reactor path).

**C2 — Discord-user attribution (T14i carry).** The received message's
author was recorded as a carry (genesis closed; compiler.ex:295-312 refuses
unknown roles). The carry: a genesis evolution — the MessageReceived schema
gains an optional `discord:user:<id>` role (string pointer), the adapter
mints it on ingest, the fold renders nothing new (attribution is DATA, not
a decision surface). Genesis regen + drift-proof entries + the :raw door
leg (the T14f H5 discipline).

**C3 — A5 cross-session summary keying (T14h carry).** Summaries were
hardened in-slice (liveness + {ts,id} + cap); the cross-session half
(session→profile keying — a summary minted under profile A never serves a
boot under profile B) was carried. The carry: the summary note rides the
profile key the same way the PromptAssembled replay key does (the
{family, epoch-id} roster + ProfileSet head id — the T14h H3 material) —
or the resolution pins the simpler read: summaries are session-scoped by
construction (the summary's sessionId is its key; a cross-profile serve is
precluded by the session's own profile binding). The rumble decides.

**C4 — N4: the lens's byte-bound governance (T14f carry).** The skill
lens's 8192 cap is a CONSTANT; the carry is GOVERNANCE — who changes the
cap, how, and whether the identity/always-on budgets ride the same
governance. The carry: a lens budget family (epoch-governed like
memory_policy/skill_policy) OR the recorded posture that the caps are
operator constants (code change + rebuild). The rumble decides.

**C5 — M2: the degenerate-short-name class (T14f carry).** The N1
trim-reject stops whitespace-only names at the tool boundary, but a
one-character name ("x") survives and `String.contains?`-matches nearly
every prompt. The carry: a minimum-name-length pin (the tool boundary
rejects < N chars) + the lens's matcher reads whole-token names only
(the exact-name tier + the digests tier — never substring). The rumble
decides N.

**R1 — AC3 crash-window rider verification (T14b register).** "A crash
between execute and record leaves nothing stored → re-fire re-executes; the
record dedupes, the request does not" — the rider said a test must survive
a gate break. The T14h remediation + T14i phantom-chain work touched crash
windows; verify the rider's test exists (or add it — the ToolCallDuplicate
dedupe leg under a crashed re-fire) and close the register item.

## Acceptance criteria (shape)

- AC1 — a reactor-booted daemon with a workspace advertises the full
  default tool set (registry + memory + skill); the profile intersect
  NARROWS (the T14i H8 witness class, reactor path).
- AC2 — a Discord ingest with an author mints the `discord:user:<id>`
  pointer; the schema round-trips; legacy received deltas (no pointer)
  resolve identically (the optional role is additive).
- AC3 — a summary minted under profile A is never served to a boot under
  profile B (whichever keying the resolution pins); profile-less boots stay
  byte-identical.
- AC4 — the lens budget (or the recorded posture) is pinned + witnessed;
  the short-name class is refused at the tool boundary (< N chars) and the
  matcher never substring-matches a whole-token tier.
- AC5 — the crash-window rider's test survives a gate break (the
  ToolCallDuplicate dedupe leg under a crashed re-fire).

## Diff metric (the element classes a build must match)

The reactor's workspace-aware default + the intersect touchpoint · the
`discord:user:<id>` role + genesis regen · the summary profile key (or the
pinned session-scoped reading) · the lens budget pin + the N-char
minimum + the whole-token matcher · the crash-window rider test.

Difficulty: C1 moderate · C2 moderate (genesis) · C3 easy/moderate · C4
easy · C5 easy · R1 easy.
