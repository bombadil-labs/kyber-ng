# T14j — The Loose Ends: Carries, Closed

Status: OPEN (light ceremony — rumble for the design cells, one deterministic
build). Parent: T14i (`825d501` on provisional/t14; suite 579/0). Rails:
carried; deps/ frozen (zero new deps); no Process.sleep; the atom; the real
~/.kyber never touched.

## Context

The T14f/g/h/i arc left five code-churnable carries + one verification rider
(the register, .adlc/carries.md). This slice closes them. All five are
SMALL, substrate-cited, and carry the arc's pinned dialect (derived
entities, {ts,id} ordering, whole-set supersede, author-filtered folds,
fail-closed defaults, the reason-string freeze, the boot tuple).

## The cells

**C1 — Reactor workspace threading (T14f D9's other half / T14g G5 carry).**
The attach path boots workspace-aware: `default_tools(opts)` (registry +
memory + skill tools when a `:workspace` is present; agent.ex:51, 92-101)
+ `Profile.intersect_tools`. The REACTOR path (daemon.ex:534-542's
whitelist: budget_cap/engine/test_pid/operator_seed) threads NO workspace —
a `--loop reactor` daemon with a workspace still boots `stub_tools()`
(reactor.ex:441's default) unless tools are passed explicitly. The carry:
the reactor's engine construction consumes the SAME workspace-aware default
+ the profile intersect (the T14i H8 fourth touchpoint, extracted shared
helper) when a `:workspace` + `:profile` are threaded. The witness: a
reactor-booted daemon with a workspace advertises memory.read + skill.read
(the T14f D9 witness class, now on the reactor path).

**C2 — Discord-user attribution (T14i carry).** The received message's
author was recorded as a carry (genesis closed; compiler.ex:295-312 refuses
unknown roles). The carry: a genesis evolution — the MessageReceived schema
gains an optional `discord:user:<id>` role (string pointer), the adapter
mints it on ingest, the fold renders nothing new (attribution is DATA, not
a decision surface). Genesis regen + drift-proof entries + the :raw door
leg (the T14f H5 discipline).

**C3 — A5 cross-session summary keying (T14h carry).** Summaries were
hardened in-slice (liveness + {ts,id} + cap); the cross-session half
(session→profile keying — a summary minted under profile A never serves a
boot under profile B) was carried. The carry: the summary note rides the
profile key the same way the PromptAssembled replay key does (the
{family, epoch-id} roster + ProfileSet head id — the T14h H3 material) —
or the resolution pins the simpler read: summaries are session-scoped by
construction (the summary's sessionId is its key; a cross-profile serve is
precluded by the session's own profile binding). The rumble decides.

**C4 — N4: the lens's byte-bound governance (T14f carry).** The skill
lens's 8192 cap is a CONSTANT; the carry is GOVERNANCE — who changes the
cap, how, and whether the identity/always-on budgets ride the same
governance. The carry: a lens budget family (epoch-governed like
memory_policy/skill_policy) OR the recorded posture that the caps are
operator constants (code change + rebuild). The rumble decides.

**C5 — M2: the degenerate-short-name class (T14f carry).** The N1
trim-reject stops whitespace-only names at the tool boundary, but a
one-character name ("x") survives and `String.contains?`-matches nearly
every prompt. The carry: a minimum-name-length pin (the tool boundary
rejects < N chars) + the lens's matcher reads whole-token names only
(the exact-name tier + the digests tier — never substring). The rumble
decides N.

**R1 — AC3 crash-window rider verification (T14b register).** "A crash
between execute and record leaves nothing stored → re-fire re-executes; the
record dedupes, the request does not" — the rider said a test must survive
a gate break. The T14h remediation + T14i phantom-chain work touched crash
windows; verify the rider's test exists (or add it — the ToolCallDuplicate
dedupe leg under a crashed re-fire) and close the register item.

## Acceptance criteria (shape)

- AC1 — a reactor-booted daemon with a workspace advertises the full
  default tool set (registry + memory + skill); the profile intersect
  NARROWS (the T14i H8 witness class, reactor path).
- AC2 — a Discord ingest with an author mints the `discord:user:<id>`
  pointer; the schema round-trips; legacy received deltas (no pointer)
  resolve identically (the optional role is additive).
- AC3 — a summary minted under profile A is never served to a boot under
  profile B (whichever keying the resolution pins); profile-less boots stay
  byte-identical.
- AC4 — the lens budget (or the recorded posture) is pinned + witnessed;
  the short-name class is refused at the tool boundary (< N chars) and the
  matcher never substring-matches a whole-token tier.
- AC5 — the crash-window rider's test survives a gate break (the
  ToolCallDuplicate dedupe leg under a crashed re-fire).

## Design resolution (converged plan)

The argue + reflect rounds settled all fifteen cells (six carries + NEW-1,
NEW-4, NEW-5, N3, N5; N2 rejected). The build is one deterministic slice
against the T14i base (`825d501` on `provisional/t14`; suite 579/0).

### C1 — Reactor workspace threading (moderate)

The route is the `:engine` KEYWORD. NO daemon whitelist change; NO CLI
flag (cli.ex:430-438's `engine: :none` default constructs no witness for a
whitelist route). The shared default lives at `ToolExecutor.default_tools/1`
— ONE helper that joins the tool-map family at tool_executor.ex:49/:99/:128
and returns the {tools, context} TUPLE (P3's shape, adopted). Both reactor
construction sites consume it: reactor.ex:451 (engine construction) AND
reactor.ex:510 (executor context parity — the fs/sh arg-error-string class;
mismatch here re-opens the T14i H8 crack). The fail-closed default is
preserved (absent `:workspace` → stub tools, byte-identical to today). The
profile intersect stays the only narrower — never widens.

- Deliverable: `ToolExecutor.default_tools(opts)` returning `{tools,
  context}`, plus both consumption sites updated.
- Witness: reactor-booted daemon with a workspace advertises the full
  default set (registry + memory + skill); profile intersect NARROWS.
- Test: `reactor_tools_test.exs`.

### C2 — Discord-user attribution (moderate)

The role name is `discordUser` (P2/P1 verdict, VERIFIED at
compiler.ex:372-373: resolved pointer fields merge OVER `%{type:, author:
claims.author, timestamp:}`, so a role named `author` would silently
OVERWRITE the signer on every resolved MessageReceived — a real semantic
collision). `discordUser` rides the compound-camelCase family
(sessionId/requestRef/replayKey). The value is `"discord:user:" <>
author_id` verbatim (adapter.ex:24-27's bare-`discord:` family is the
precedent; string-kind).

- Schema: `optional: [{"discordUser", "string"}]` on MessageReceived
  (genesis.ex:171-178) + genesis regen.
- Events shim: `message_received/7` adds `discord_user \\ nil`; `/6`
  delegates (byte-identical for callers that don't pass it).
- Adapter mint: adapter.ex:386 — `"discord:user:" <> author["id"]`;
  missing / whitespace-only author → nil (fail-closed).
- Fold: renders NOTHING new. Attribution is data, never a decision surface.
- Witnesses: T-C2c REPLAY-STABILITY — the mint is a pure function of the
  dispatch. N5 loam round-trip via `Rhizomatic.Profile` on both new-shape
  forms (with and without the optional role).
- Test: `attribution_test.exs`.

### C3 — A5 cross-session summary keying (moderate)

P2's arm wins. The summary carries the profile dimension explicitly.

- Schema: `ConversationSummary` gains an optional `profile` role (string;
  the T14g profile name) + genesis regen (rides C2's already-paid regen).
- Gather (prompt.ex:99-111): filters on (session, profile) — nil == nil
  matches (profile-less boots stay byte-identical).
- `summarized?` (engine.ex:721-726): becomes (session, profile)-scoped
  AND liveness-aware (NEW-4 — retraction-blind today).
- Witness T-C3a: a same-session re-boot under a DIFFERENT profile does NOT
  serve the summary. This is the only witness that fails on the parent —
  the differential exposure is live today (verify engine.ex:698 +
  context_builder.ex:88: the summary digests the elided head the window
  never serves).
- Hard OPEN (recorded, not resolved here): the CONDITIONAL BINDING carry.
  Any future session→profile binding must sweep gather + conversation/2 +
  `summarized?` TOGETHER in one slice — never one closure alone.
- Test: `summary_profile_test.exs`.

### C4 — N4 lens governance (easy)

The recorded posture: caps are OPERATOR CONSTANTS (compile-time module
attributes, changed by code review + rebuild; NEVER read from the store —
a hostile store must never widen a cap).

- Registry = LENS caps ONLY: identity 8192, always-on 4096, summary 4096,
  skill count 4, skill bytes 8192. The reactor `@default_cap 32` and window
  8 are DISPATCH budgets — excluded by naming discipline (N3: cap registry
  moduledoc names all five lens caps + notes the two dispatch budgets are
  DELIBERATELY out-of-scope).
- Recorded in-code (the owning module's moduledoc; spec/03-agent.md does
  not exist and spec/ is frozen).
- Witnesses: BEHAVIORAL boundary tripwires per constant (assert a byte over
  the cap is cut at the cap) + a disjointness leg (the budgets never pool).
- Test: `lens_governance_test.exs`.

### C5 — M2 short-name class (easy)

- N = **4 BYTES post-trim** (assoc.ex:54's ≥4-byte token floor is the
  derivation anchor — the boundary and the tokenizer speak the same units;
  N=2 reopens the half-matcher class).
- Matcher: boundary-anchored case-sensitive literal lookaround
  `(?<![A-Za-z0-9])name(?![A-Za-z0-9])` (handles single- AND multi-token
  names; over-matching rejected).
- L2's case-sensitive exact tier PRESERVED (prompt.ex:200-202).
- Read-side twin: out-of-band sub-floor names are LENS-INERT (the door
  refuses only `""` — delta.ex:115-118 — so ≥1-char out-of-band names ride
  today; `ranked_skill_notes` must not render them).
- Test: `short_name_test.exs`.

### R1 — AC3 crash-window rider (moderate)

Four legs, all in one witness suite:

- **(A)** A re-fire after a crash-between-execute-and-record re-executes
  ONCE and the record dedupes.
- **(B)** The re-executed turn's mint is BYTE-IDENTICAL (the M6 call-ts
  mint at tool_executor.ex:491-495 makes it hold).
- **(C)** The dedupe read is {ts,id}-ordered (NEW-1 — `by_timestamp` is
  ts-only today, tool_executor.ex:761-762; nondet under the >32 filler
  regime).
- **(D)** GATE-BREAK arm: a ROTATED epoch mid-window makes the re-fire
  REFUSE.
- Test: `crash_window_test.exs`.
