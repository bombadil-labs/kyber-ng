## Context

The T14f/g/h/i arc left five code-churnable carries + one verification rider
(the register, .adlc/carries.md). This slice closes them. All five are
SMALL, substrate-cited, and carry the arc's pinned dialect (derived
entities, {ts,id} ordering, whole-set supersede, author-filtered folds,
fail-closed defaults, the reason-string freeze, the boot tuple).

## The cells

**C1 — Reactor workspace threading (T14f D9's other half / T14g G5 carry).**
The attach path boots workspace-aware: `default_tools(opts)` (registry +
memory + skill tools when a `:workspace` is present; agent.ex:51, 92-101)
+ `Profile.intersect_tools`. The REACTOR path (daemon.ex:562-574's
whitelist: budget_cap/engine/test_pid/operator_seed/profile) threads NO
workspace — a `--loop reactor` daemon with a workspace still boots
`stub_tools()` (reactor.ex:451's `Keyword.get(:tools, stub_tools())`
default) unless tools are passed explicitly. The carry:
the reactor's engine construction consumes the SAME workspace-aware default
+ the profile intersect (the T14i H8 fourth touchpoint, extracted shared
helper) when a `:workspace` + `:profile` are threaded. The witness: a
reactor-booted daemon with a workspace advertises memory.read + skill.read
(the T14f D9 witness class, now on the reactor path).

**C2 — Discord-user attribution (T14i carry).** The received message's
author was recorded as a carry (genesis closed; compiler.ex:295-312 refuses
unknown roles). The carry: a genesis evolution — the MessageReceived schema
gains an optional `discord:user:<id>` role (string pointer), the adapter
mints it on ingest, the fold renders nothing new (attribution is DATA, not
a decision surface). Genesis regen + drift-proof entries (the schema-test
drift-proof entry passes a NON-nil `discord_user` — the regen is exercised,
not decorative) + the :raw door leg (the T14f H5 discipline). The value is
string-kind BY PIN (`"discord:user:" <> author_id` — a bare-`discord:`
STRING role; the T14i L2 bare-`discord:` rejection governs ENTITY ids only,
so a moduledoc line pinning string-kind preempts entity-ref confusion).

**C3 — A5 cross-session summary keying (T14h carry).** Summaries were
hardened in-slice (liveness + {ts,id} + cap); the cross-session half
(session→profile keying — a summary minted under profile A never serves a
boot under profile B) was carried. The carry: the summary note rides the
profile key the same way the PromptAssembled replay key does (the
{family, epoch-id} roster + ProfileSet head id — the T14h H3 material) —
or the resolution pins the simpler read: summaries are session-scoped by
construction (the summary's sessionId is its key; a cross-profile serve is
precluded by the session's own profile binding). The rumble decides.

**C4 — N4: the lens's byte-bound governance (T14f carry).** The skill
lens's 8192 cap is a CONSTANT; the carry is GOVERNANCE — who changes the
cap, how, and whether the identity/always-on budgets ride the same
governance. The carry: a lens budget family (epoch-governed like
memory_policy/skill_policy) OR the recorded posture that the caps are
operator constants (code change + rebuild). The rumble decides.

**C5 — M2: the degenerate-short-name class (T14f carry).** The N1
trim-reject stops whitespace-only names at the tool boundary, but a
one-character name ("x") survives and `String.contains?`-matches nearly
every prompt. The carry: a minimum-name-length pin (the tool boundary
rejects < N chars) + the lens's matcher reads whole-token names only
(the exact-name tier + the digests tier — never substring). The rumble
decides N.

**R1 — AC3 crash-window rider verification (T14b register).** "A crash
between execute and record leaves nothing stored → re-fire re-executes; the
record dedupes, the request does not" — the rider said a test must survive
a gate break. The T14h remediation + T14i phantom-chain work touched crash
windows; verify the rider's test exists (or add it — the ToolCallDuplicate
dedupe leg under a crashed re-fire) and close the register item.

## Acceptance criteria (shape)

- AC1 — a reactor-booted daemon with a workspace advertises the full
  default tool set (registry + memory + skill); the profile intersect
  NARROWS (the T14i H8 witness class, reactor path); the witness
  EXECUTES an fs/sh call for a REAL result (the context-parity half).
- AC2 — a Discord ingest with an author mints the `discord:user:<id>`
  pointer; the schema round-trips; legacy received deltas (no pointer)
  resolve identically (the optional role is additive).
- AC3 — a summary minted under profile A is never served to a boot under
  profile B (whichever keying the resolution pins); profile-less boots stay
  byte-identical.
- AC4 — the lens budget (or the recorded posture) is pinned + witnessed;
  the short-name class is refused at the tool boundary (< N chars) and the
  matcher never substring-matches a whole-token tier.
- AC5 — the crash-window rider's test survives a gate break (the
  ToolCallDuplicate dedupe leg under a crashed re-fire, with the
  rotated-epoch refusal in the TOTAL-LOSS crash window).

### C5 — M2 short-name class (easy)

- N = **4 BYTES POST-TRIM** (assoc.ex:54's ≥4-byte token floor is the
  derivation anchor — the boundary and the tokenizer speak the same units;
  N=2 reopens the half-matcher class). M6: the boundary measures
  `byte_size(String.trim(name))` — the STORED name is NEVER normalized (a
  name stored with whitespace is the caller's data; the boundary refuses it
  at the TOOL BOUNDARY, reject-never-repair, never by rewriting the store).
  Witness cells (probe P-C5a): `"x"` (1 trimmed byte) refused; `" x "` (3
  raw bytes → 1 trimmed byte) refused at the boundary; `"abcd"` (4 trimmed
  bytes) accepted; a stored whitespace-padded name is never silently
  rewritten by the store. Alignment: `Assoc.digests("hi") == []`
  (assoc.ex:54's ≥4-byte floor, P-C5e) — sub-4 names are digest-blind, so
  the exact tier is their only path and the N=4 floor makes them
  permanently lens-inert, consistent with the "same units" anchor.
- Matcher: boundary-anchored case-sensitive literal lookaround
  `(?<![A-Za-z0-9])name(?![A-Za-z0-9])` (handles single- AND multi-token
  names; over-matching rejected). H1: the name is `Regex.escape`d BEFORE
  interpolation into the lookaround — the literal spelling over-matches on
  regex meta-characters (probe P-C5c: `"foo.bar"` vs `"see foo bar here"`
  → true; `"v1.2"` vs `"the v1x2 build"` → true; `"a+b"` vs `"the aab
  build"` → true — dots/plus are legal in skill names: N1 at
  tool_executor.ex:549-550 refuses only whitespace-only, delta.ex:115-118
  only `""`). The boundary classes stay `[A-Za-z0-9]`. The separator-variant
  leg ("foo bar" vs "foo.bar") becomes a POSITIVE test: the escape makes
  the literal match actually literal — `"foo.bar"` matches `"see foo.bar
  here"` and does NOT match `"see foo bar here"`.
- L2's case-sensitive exact tier PRESERVED (prompt.ex:200-202).
- Read-side twin: out-of-band sub-floor names are LENS-INERT (the door
  refuses only `""` — delta.ex:115-118 — so ≥1-char out-of-band names ride
  today; `ranked_skill_notes` must not render them).
- Test: `short_name_test.exs`.

### R1 — AC3 crash-window rider (moderate)

Four legs, all in one witness suite. `crash_window_test.exs` is a
DELIVERABLE, not a verify-only close (L1 — existing coverage:
skill_gate_test.exs:307-337 covers only the absorbed-set re-fire control,

ToolResult, Leg C's tied-ts read, or Leg D's re-fired-call refusal).

- **(A)** A re-fire after a crash-between-execute-and-record re-executes
  ONCE and the record dedupes. (Crash window: GateDecision recorded,
  ToolResult dropped — the engine dies between execute and record.)
- **(B)** The re-executed turn's mint is BYTE-IDENTICAL (the M6 call-ts
  mint at tool_executor.ex:491-495 makes it hold).
- **(C)** The dedupe read is {ts,id}-ordered (NEW-1 — `by_timestamp` is
  ts-only today, tool_executor.ex:762; nondet under the >32 filler
  regime). M4: the disagreeing pair is content-sensitive and PINNED — a
  hand-crafted 35-entry store (the >32 filler regime) with TWO tied-ts
  ToolResults for ONE call, contents pinned `"A2222222222"`/`"B2222222222"`
  (found at i=2 in a 500-pair search, probe P-R1C2: ts-only first-match
  picks A, {ts,id} picks B — P-R1C3); contents are PINNED, never searched
  at runtime. The two-results-per-call state cannot arise from the real
  path (M6's call-ts mint at tool_executor.ex:491-495 + the
  answer-from-the-store rule at :479-487) — the witness hand-crafts it.
- **(D)** GATE-BREAK arm — the TOTAL-LOSS crash window (H3): a ROTATED
  epoch mid-window makes the re-fire REFUSE. Constructible ONLY when the
  crash drops ALL wires (the engine dies between execute and record with
  NOT EVEN the GateDecision persisted; the store survives). The suite
  EXPLICITLY DROPS THE WIRES (kills the engine link, leaves the store) and
  the test comment + assertion name say "total-loss crash window" — never
  a partial-wire shape: with the GateDecision persisted, the re-fire
  answers the STORED allow (tool_executor.ex:219-221) and re-executes, and
  a rotated epoch is invisible (probe P-R1D: the refusal happens only with
  zero persisted wires — re-decide under the rotated epoch →
  `verdict="refuse"`, `reason="skill_policy: skill not allowed by the
  current epoch"`). Legs A/B use the GateDecision-recorded window; Leg D
  requires the total drop.
- Test: `crash_window_test.exs` (no pgrep polls of generic command lines —
  `^sleep 30$` is the action_bounds_test.exs:216 flake class in this
  shared environment; L5 — poll the reactor's own pinned command or use
