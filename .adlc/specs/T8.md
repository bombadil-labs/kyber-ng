# T8 — Loop 8: The Operator Surface — a CLI for the whole stack (escript) (rev 2)

## Context

Every loop so far delivered MODULE APIs. T8 gives the harness a FACE: a `kyber` escript
(stdlib Mix escript — ZERO new dependencies; the only mix.exs change is a ONE-TIME
additive `escript:` stanza, pinned below). The dispatch core is PURE and testable: each
command function returns `{status, message}` and never calls `System.halt/1` or prints;
`main/1` is the ONLY printer + halter. Tagged failures print as clean one-liners —
never a crash stacktrace. Exit codes pinned: `0` success, `1` operational error (any
tagged `{:error, _}`), `2` usage error (bad argv / unknown command).

**Boot ownership (rev 2 — the 10-cause premortem's central fix; rev 3 — the
load-clobber fold):** `escript: [main_module: Kyber.CLI, app: nil]` — `app: nil` is
REQUIRED, because with the default (`app: :kyber`) the escript boots the app on the
baked-in dev-config path BEFORE `main/1`, making the `--log` override dead and
store-down unreachable. The mix.exs diff for T8 is EXACTLY this one stanza (AC1). With
`app: nil`, the boot sequence is **`load → put_env → start`** (rev 3 — the build's
recorded contradiction): `main/1` calls `Application.load(:kyber)` FIRST (applies the
baked default; a no-op when already loaded — the mix-test path), THEN
`Application.put_env(:kyber, :log_path, path)` (the override wins), THEN
`Application.ensure_all_started(:kyber)` (cannot re-clobber — the app is already
loaded). The rev-2 pin ("put_env DIRECTLY before ensure_all_started") was WRONG: with
the app unloaded, `ensure_all_started` triggers `:application.load/1`, which re-applies
the build-time-baked `~/.kyber` default and clobbers the override — the exact dead-`--log`
failure the fix claims to cure, relocated from boot into load (verified empirically
against the built escript). The `{:error, {:kyber, reason}}` boot failure → the clean
one-liner "store failed to start: <reason>", exit 1. `run/1` NEVER boots — it
dispatches over whatever app state exists. No test ever halts. `--log` appears BEFORE
the command only; `--log` after the command → usage error, exit 2.

**Escript mechanics (pinned):** `config/config.exs` compiles into the app (the default
`:kyber, :log_path` = `~/.kyber/store.jsonl` is baked at build time — the operator
overrides it per-run with `--log`). The escript runs OUTSIDE the project dir.

**CLI shape (pinned; the exit codes are asserted ONLY via run/1's status + System.cmd
smokes — there is NO halt-mocking (rev 2: `:erlang.halt` terminates the VM; AC2's old
trap clause is impossible and is STRUCK)):**

```
kyber [--log <path>] <command> [args]
  view                                   sorted claims, one per line (format pinned below); exit 0
  ingest <source.json> --keyring <dir>   the T4 source map -> Harness.ingest; prints the claim id; exit 0
  render <vault_dir>                     Vault.render; prints the report; exit 0
  refresh <vault_dir>                    Vault.refresh; prints the report; exit 0
  export                                 Federation.export; prints the wire text verbatim + "\n"; exit 0
  import <wire.jsonl>                    Federation.import; prints the import report; exit 0
  migrate <legacy.jsonl> --keyring <dir> Migration.migrate; prints the migration report; exit 0
  help | (no args)                       usage text, exit 0
  <unknown> | help <extra>               usage text, exit 2
```

**View line format (PINNED BYTE-EXACT, rev 2):** one line per claim, sorted by id_hex:

```
<id_hex> <first-pointer-role> <first-8-hex-after-the-ed25519:-prefix> <ts via :erlang.float_to_binary(ts, decimals: 0)>
```

Example (a message_received claim, author ed25519:fc947730f49e..., ts 1754512345678.0):

```
1e2016979a92ebdbe039dbea08820a26f0820690f0bd1b9f1ea3fca4289f946fbd56 received fc947730 1754512345678
```

`author` = `String.slice(author_hex_after_prefix, 0, 8)` — the first 8 hex chars AFTER
the `ed25519:` prefix (never the prefix itself). `role` = the literal FIRST pointer's
role (vault.ex's precedent). `ts` = DECIMAL, `float_to_binary(ts, decimals: 0)` — never
scientific.

## Requirements
