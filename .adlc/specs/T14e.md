## E1 — M5: the engine's GateDecision verdict dialect bug (carries #28/#39)

The verdict ecosystem has two dialects: the gate emits ATOMS in memory
(`action/gate.ex:19` — `:allow | :deny | :refuse`), the WIRE carries STRINGS
(the GateDecision claim's resolved verdict — `to_string(decision.verdict)` at
tool_executor.ex:195-198). The engine reads the RESOLVED claim and compares
against atoms:

- **engine.ex:158** — `{"decides", %{type: "GateDecision", verdict: verdict, ...}} when verdict != :allow`: the resolved verdict is a STRING ("allow"/"refuse"), so `!= :allow` is ALWAYS TRUE — every GateDecision (including ALLOWED calls) routes to `refusal/3`, fabricating a refusal for every decided tool call and discarding the real ToolResult from the model's view (carry #39: "the tool-bearing agent ships semantically degraded until then"). The AC4 live evidence (run 5: refused PASS / allowed FAIL) is the fingerprint.
- **engine.ex:422** — `reason = typed.reason || Atom.to_string(typed.verdict)`: `Atom.to_string/1` on a STRING verdict crashes (ArgumentError) whenever a refusal arrives without a reason.
- tool_executor.ex:178 (`decision.verdict == :allow`) is DIALECT-SAFE (in-memory atom vs atom) — DO NOT touch it. `action/gate.ex` atoms are the in-memory dialect — DO NOT touch them.

THE FIX (bounded, engine-side normalization only):
1. engine.ex:158: `when verdict != :allow` → `when to_string(verdict) != "allow"` — the wire spelling; `to_string/1` keeps the guard dialect-agnostic (a hypothetical atom verdict still compares correctly).
2. engine.ex:422: `Atom.to_string(typed.verdict)` → `to_string(typed.verdict)` — handles both dialects, never crashes.
3. Consequence (the semantic degradation restored): a decided-ALLOW claim now falls to `_other -> state` — NO fabricated refusal, the ToolResult flows. Decided-refuse/deny still route to `refusal/3`.

Tests (in test/kyber/agent/engine_paths_test.exs — the licensed engine-pins home):
- **E1a** — decided-allow pass-through: a store containing a GateDecision claim with verdict "allow" for a call → the engine emits NO refusal wire for it (the fabricated-refusal regression; restoring the atom guard fails this leg).
- **E1b** — decided-refuse: verdict "refuse" (with reason) → refusal emitted with the reason.
- **E1c** — reason fallback no-crash: a GateDecision with verdict "refuse" and NO reason → refusal emitted with reason "refuse" (the Atom.to_string crash regression; restoring `Atom.to_string` fails this leg).
- **E1d** — decided-allow + real ToolResult: after a decided-allow, the matching ToolResult claim flows to the model's view (the semantic-degradation carry witnessed closed).
