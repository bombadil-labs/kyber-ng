# T14h — Always-On Context: Continuity Beyond the Last Prompt

Status: OPEN (light ceremony — rumble for the design cells, one deterministic
build). Parent: T14g (identity — in rumble). Rails: carried.

## The framing

The user's brief: "context injection can't just be ad hoc memories and skills
related to the last prompt, there has to be a larger form of continuity going
on. Be creative."

Today the assembled prompt is: [identity block (T14g), memory_notes (the
lens over the last turn), skill_notes (the lens over the last turn),
summary_notes, elision, turns]. Everything except the identity block is
LAST-PROMPT-LOCAL: the lenses match the current turn; the window elides the
head into summaries. There is no LARGE-SCALE continuity — nothing that
answers "what has this agent been doing for the last week" unless a lens
happens to match.

ALWAYS-ON context = the set of store-derived artifacts that ride EVERY
prompt regardless of the last turn's content. The design question is WHAT
qualifies and HOW it's derived — deterministically, capped, and without
becoming a wall of noise that eats the window.

## Candidate always-on surfaces (the rumble pins the set)

- **A1 — standing memory**: the epoch-visible canon's "long-term" subset —
  memory entities with a `standing` flag or the canon's head entities
  (per-entity-latest), folded as a standing block. (The T14c memory canon
  merges; the always-on block wants the STANDING subset, not everything.)
- **A2 — the trajectory**: a compact digest of recent activity — the last N
  prompt/response pairs (not the raw turns — the window already does that)
  but a DERIVED digest: what was asked, what was done, what was decided.
  Rendered from the store's delta stream (the reactor's prompts + tool
  results), deterministically.
- **A3 — open threads / standing intents**: derived from the delta stream —
  requests without their completion, retractions pending, etc. (a "state of
  the world" digest).
- **A4 — the identity fold's dynamic half**: profile-scoped facts the agent
  has learned (the user's preferred greeting, the channel's norms) — the
  agent-writable counterpart to the operator-attested identity primitives
  (T14g G7).
- **A5 — cross-session persistence**: the summaries (conversation_summary
  deltas) promoted from elision-fodder to an always-on digest when the
  session is long-lived.

## The mechanism (the creative part — the rumble decides)

Options for HOW the always-on block is derived:
- **Option 1 — a standing-fold**: like the memory canon but for the standing
  subset; the block = fold + digest, recomputed per assembly, {timestamp, id}
  deterministic, byte-capped.
- **Option 2 — a periodic digest delta**: the reactor emits a
  `StandingDigest` delta at a cadence (tick-based), so the always-on block
  is a READ of the latest digest, not a fold per prompt. The digest is a
  VIEW over the stream, materialized on a schedule (the store only learns —
  digests are deltas too, superseding).
- **Option 3 — hybrid**: standing memory is a fold (fresh every assembly);
  the trajectory/threads are a digest delta (materialized by the reactor
  when the store changes, or on a tick).

The always-on block sits between the identity block and the memory_notes in
Prompt.assemble — the order: [identity, always-on, memory_notes,
skill_notes, summary_notes, elision, turns]. Capped (byte bound — the
rumble pins the number; the T14f lens cap is the precedent: 8192 skip-whole).

## Constraints

- Determinism: everything {timestamp, id}-ordered; no wall-clock in the
  fold (digest deltas may claim their tick's timestamp — a cell).
- The atom: digests are deltas (supersede), never ephemeral.
- The gate: what the always-on block MAY include is epoch-bounded (the
  profile's visibility — T14g's G4); a channel profile's always-on block
  must not leak broader memory.
- Fail-closed: an ungoverned profile gets NO always-on block (or the
  standing subset only — a cell).

## Open design cells

H1 — the always-on surface set (A1-A5: which, what qualifies as "standing").
H2 — the mechanism (fold vs digest-delta vs hybrid; the digest cadence and
timestamp discipline).
H3 — the always-on block's shape: order, byte cap, rendering (a cell:
"Standing memory:" header + digest lines?), the elision interaction (does
the always-on block change what the window elides?).
H4 — standing-qualification: what makes a memory entity "standing" (a flag
in the entity delta? recency? the epoch allowlist?).
H5 — the trajectory digest: what it includes (last N prompt/result pairs?
decisions only?), the cap, and how it differs from the window + summaries.
H6 — profile interaction: the always-on block under a channel profile
(subset + no broader-memory leakage — the AC).
H7 — the digest's write path: who mints StandingDigest deltas (the
reactor's tick? the store-change observer?), the gate on digest writes.
H8 — cost control: the always-on block vs the window budget — how the cap
and the digest cadence keep the prompt from bloating.

## Acceptance criteria (shape)

AC1 — the always-on block rides every prompt (the standing subset is present
regardless of the last turn's content); deterministic.
AC2 — the trajectory digest reflects recent activity (asked/done/decided)
and is capped.
AC3 — profile isolation: a channel profile's always-on block excludes
broader memory (leakage witnessed ABSENT).
AC4 — the block is byte-capped and the window's budget is preserved (no
bloat — the cap's skip-whole semantics witnessed).
AC5 — determinism: the fold/digest is {timestamp, id}-ordered,
replica-identical.

## Deliverables (shape)

- the standing-fold + always-on block in Prompt.assemble
- the digest delta family (if Option 2/3) + genesis evolution (the H5
  lesson — unknown types admit :raw)
- the trajectory renderer
- tests: always_on_test.exs, trajectory_test.exs, profile_isolation (with
  T14g's), determinism legs

## Completion gate (shape)

`mix test && test -f <deliverables>`

## Design resolution (converged plan)

The rumble (P1/P2/P3 → A1/A2/A3 → R1/R2/R3, `.adlc/rumble-t14h/`) converged
on every contested cell; the coin-flip (digest retraction) was settled
explicitly in the reflects. The binding shape: **the always-on block is a
HYBRID — standing memory is a read-time FOLD (live-governed, fresh per
assembly, because the epoch filter only exists at read time), and the
trajectory is a `StandingDigest` DELTA FAMILY (the historical view — the
atom: the store only learns).** The block inherits T14g's boot-context
threading verbatim: the boot tuple `{profile | nil, operator_author | nil}`
IS the object (prompt.ex:66; engine.ex:213-221) — T14h consumes it, never
re-threads. Line anchors below cite the MERGED tree (65c3138); the
proposals' pre-merge cites (prompt.ex:62-67, engine.ex:200/204/256-283) are
now prompt.ex:88-93 and engine.ex:210-225/288-316.

Two spec corrections, recorded by all three voices:

1. **The bracket order was stale** — "[identity, always-on, memory_notes,
   skill_notes, summary_notes, ...]" repeats the prose contradiction T14g G3
   already fixed. The pin: system → identity → **always-on** → memory_notes
   → summary_notes → skill_notes → elision → turns.
2. **The "tick's timestamp" cell is dead** — no tick exists (the reactor
   routes without one, reactor.ex:4; the daemon tick is pulse-only, D5).
   The mint claims the TRIGGERING delta's `claims.timestamp`, never
   wall-clock (the engine's D1 comment at engine.ex:223-225 is the norm;
   the `now()` habit at the answer path is the pinned anti-pattern).

### H1 — the surface set: A1+A2+A3+A4-via-A1; A5 as hardening (easy)

- **A1 standing memory: IN, fold-based** — the standing fold over
  `Memory.resolve_set` canon heads, qualified by H4, epoch-filtered at read
  (H6).
- **A2 trajectory: IN, digest-based** — the `StandingDigest` family,
  session-scoped (H5/H7).
- **A3 open threads: IN, a SEPARATE per-assembly FOLD** over the
  resume-scan class (unanswered `InferenceRequested` + `:tool_waiting`,
  engine.ex:125-157 semantics), session-filtered, `{ts, id}` ascending —
  **never in-digest** (per-answer mints leave in-digest threads stale
  between mints; the fold closes at read). Rendered with the
  asked-without-answered line grammar.
- **A4 dynamic identity half: IN via A1, zero new machinery** — the T14g
  G1/G7 `profile:<id>:` memory-seam convention; such entities ride iff
  flagged (H4) and epoch-allowed (H6). No write tool exists this slice
  (`memory_tools/1` = `memory.read` only) — flag writes are
  operator/out-of-band, the MemoryEntity posture.
- **A5 promoted summaries: lands as IN-SLICE HARDENING, not a new
  surface.** The spec's premise was wrong: summaries already ride every
  assembly — uncapped, retraction-blind, timestamp-only-sorted (the D2
  violation is LIVE at prompt.ex:88-93, no id tie-break). The fix: liveness
  (recursive-existential) + `{ts, id}` tie-break + cap, slot unchanged. The
  liveness/tie-break legs change bytes only where today is buggy
  (AC-recorded); **the CAP leg can change healthy profile-less bytes (the
  T14g G5 byte-identity norm) — the build either AC-records that byte delta
  explicitly or defers the cap to the block budget.** The cross-session
  promotion half is a RECORDED CARRY (blocked on session→profile keying).

### H2 — the mechanism: hybrid; trigger-ts discipline (moderate)

- Standing memory + open threads: read-time folds, recomputed per assembly,
  `{claims.timestamp, id}` total order (D2 — never append order).
- Trajectory: `StandingDigest` deltas, whole-set supersede by `{ts, id}` —
  NO `supersedes` pointer (the T14g G2 norm); two live same-session heads
  resolve latest-wins, never a fork error.
- **Mint timestamp: the triggering delta's `claims.timestamp` — never
  wall-clock, never a tick** (all three converged). A crash-window re-fire
  re-mints the same content + same ts ⇒ same content id ⇒ merge-is-union
  collapses to one digest.
- **Digest retraction (the coin-flip, SETTLED): recursive-existential
  NO-ROLLBACK** — a retracted digest head ⇒ the fold is `:none` until the
  next mint (T14f D4 / T14g G4 verbatim; ONE liveness oracle in the house,
  the G4 M1 shared helper). P1's fallback-to-previous-head is rejected:
  consecutive digests overlap ~15/16 covered events, so the fallback head
  re-exposes the just-negated content, and one negation cannot purge;
  `Policy.current`'s fallback governs value lineage (epochs), not view
  logs. Restore = negate the negation; for a derived artifact the next
  answer re-mints clean.
- **The remediation runbook (pinned + WITNESSED)**: negating a poisoned
  digest head is NOT sufficient — the next per-answer mint re-derives the
  same leaked line from the LIVE source delta. The runbook: negate the
  SOURCE delta + the dead digest heads, THEN the re-mint derives clean.
  A test witnesses both halves (head-only negation re-leaks; runbook
  cleans).

### H3 — block shape: slot, the third budget, cap disciplines (easy)

- **Slot**: system → identity → **always-on** → memory_notes →
  summary_notes → skill_notes → elision → turns. The block renders AFTER
  the identity block (the T14g slot order) and BEFORE memory_notes.
- **Cap: 4096 total rendered bytes — a THIRD budget, disjoint from the
  identity block's 8192 and the skill lens's 8192, never pooled** (2-of-3
  reflects; half the identity budget — the block rides every prompt;
  note-tier total ≤ 8192+4096+8192). Disjointness, not the value, is the
  load-bearing pin.
- **Cap discipline splits by data shape**: standing = SKIP-WHOLE
  (M4 — independent items, greed is fine; an oversized line is omitted
  entirely, smaller later lines still fit); **trajectory = CONTIGUOUS
  stop-at-overflow** (newest-first accumulate, rendered chronological —
  "holes lie about the sequence"; skip-and-continue would present a gapped
  history as contiguous). Whole-line rendering everywhere — never mid-line
  truncation.
- **Headers pinned** (the house `"Memory: "` discipline): `"Standing:"` /
  `"Trajectory:"` / `"Open:"` — one system message per non-empty section;
  standing lines `"- <entity>: <content>"`; trajectory = the digest head's
  content; open = asked-without-answered lines. **Absence, never an empty
  header.** Byte-identity tests record the exact renders.
- **Never windowed; no elision interaction**: `window: 0` still renders the
  block; the window lens, the elision note, and the `maybe_summarize`
  trigger are untouched.
- **The block takes NO prompt_text input** (AC1 prompt-independence by
  construction); the merged 6-arity fresh-fire call (engine.ex:210-221)
  inherits it with zero engine edits.

### H4 — standing qualification: the `StandingFlag` family (moderate)

- **Standing = ≥1 LIVE `StandingFlag` ∧ head-live canon entity ∧
  epoch-allowlisted.** Visibility (the epoch) and salience (the flag) stay
  ORTHOGONAL — visibility ≠ salience: an epoch may allow hundreds of
  entities for retrieval without all of them riding every prompt.
- Shape: `{"StandingFlag", requires: [{"standing", "entity"}]}` — the
  `"standing"` kind marker routes to no subscription. Unflag = negate the
  flag (retraction-is-negation), never identity surgery; re-flag after
  removal rides with no special case.
- **Liveness is recursive-existential** (the T14f H3 oracle) — for the flag
  AND for the canon head. **Canon-head liveness is PINNED**:
  `Memory.resolve_set` is retraction-blind by its own slice's design
  (memory.ex:98-129 — recorded, not T14h's to change); the standing fold
  applies head-liveness itself. Retraction-is-negation is not optional — a
  retracted flagged entity is absent from every prompt.
- Rejected: P2's allowlist-∩-canon (conflates visibility with salience);
  P3's `"standing:"` prefix (no unflag lifecycle — identity surgery — and
  G1's exact-match epoch semantics mean the prefix never composes with the
  allowlist).
- Whitespace-only flagged entity ids are **fold-inert** — never repaired
  (the inertness lives in the fold; the door carries no empty-claim-string
  refusal — A1's self-correction: the stale `delta.ex` cite is dead).

### H5 — the trajectory digest: covered kinds, size, exclusions (moderate)

- **Covered kinds: {MessageReceived, ResponseDelta, ToolCall, ToolResult,
  GateDecision}**, session-scoped at mint AND read. ResponseDelta is
  covered — a stored ts is DATA (the poison theory fails: replica-identity
  is wire-log identity); without it, tool-less turns are indistinguishable
  from open threads and "done" loses its middle leg. The M6 discipline
  binds MINT timestamps, never coverage.
- **N = 16 items (2×window — the derivation anchor: engine.ex:29
  `@default_window 8` + the `maybe_summarize` threshold class), selected
  newest-first by `{ts, id}`, rendered chronological; 2048-byte mint cap on
  the content role**, contiguous stop-at-overflow at mint (H3's
  discipline). Derivation reuses `ContextBuilder.conversation/2` and
  pointer-joins (ToolCall/ToolResult via `requestRef`; GateDecision via
  `decides`) — CALLED, never re-implemented.
- **Digest-of-digest exclusion, structural**: `StandingDigest`'s
  sessionId-first kind marker routes to no subscription and matches no
  lens — the minter never observes its own output; the trajectory
  derivation excludes digest-family kinds from its input.
- Difference from the neighbors: the window = raw last-8 turns; summaries =
  elision digests; the trajectory = DERIVED asked/done/decided lines
  including mechanism events (GateDecision verdicts — the leg the raw
  window never shows). Window-agnostic by construction (the digest is
  minted without knowing any assembly's window).
- Empty derivation ⇒ no mint; the enforcement point is the minter/fold, not
  the door.

### H6 — profile interaction: the flip inherited, session-scoping as isolation (easy)

- **Standing section: born FAIL-CLOSED (the T14f D6 doctrine)** — renders
  only under `{:ok, epoch}` from the governing memory family (live family
  refs via `Policy.current/2`; the T14g G8 derived defaults
  `"memory:profile/<name>"`); `:none` and `{:error, :forked}` ⇒ no standing
  lines, profile or not. **The G8 `:none` flip is inherited**: under an
  active profile, `:none` ⇒ omit-ALL. The legacy fail-open memory gather
  stays legacy-only — the L8 asymmetry is NOT extended and NOT unified.
- **Trajectory/open sections: session-scoped at mint AND read** — they
  derive solely from the session's own stream, the same visibility class as
  the window; session-scoping IS the isolation construction. Cross-session
  trajectory waits for session→profile keying (recorded carry).
- No GateDecision minted anywhere — the block is call-less prompt assembly;
  zero new reason strings.
- **Standing/memory_notes dedup: standing WINS** — `gather_ids` drops ids
  whose chain resolves (by chain membership) to an entity already rendered
  standing; deterministic because the standing fold computes first.
- **Profile threading: MOOTED by the T14g merge** — consume the boot tuple
  (prompt.ex:66; engine.ex:213-221); one profile authority per assembly,
  never a second channel.

### H7 — the mint: engine answer path, zero-charge, change-guard (moderate)

- **Mint surface: the ENGINE ANSWER PATH, per answered turn, at BOTH
  boots** — the engine is where attach (agent.ex handler subscriptions) and
  reactor (its own Engine, sink `DurableStore.append`) converge. P1's
  gather-subscribe conceded (the reactor is dark: static `@subscriptions`,
  daemon flush bypasses Gather); P3's nobody-mints rejected.
- **UNGATED mint, GATE AT READ** — derivation adds no information to the
  store (content is a pure function of covered deltas); an epoch gate at
  the mint kills AC2 in the default deployment (most boots have no memory
  epoch). Fail-closed lives at the read (H6).
- **The mint is a ZERO-CHARGE side emission**: direct sink emission outside
  the reactor's dispatch/budget path — **no `Budget.charge`, no turn
  attribution, no GateDecision**. Signed by the boot agent seed (the Events
  builder convention).
- **The change-guard compares against the last MINTED head — live or
  dead — on POST-CAP RENDERED bytes.** A content-identical re-mint
  collapses to the negated id under merge-is-union and stays dark (the
  intended purge semantics — this is what makes the remediation runbook
  work); only a content CHANGE mints fresh. Comparing pre-cap derivation
  would let churn beyond the cap horizon mint information-free supersedes
  that render identically.
- Store growth: O(answered turns), ≤1 digest per content-changing answer;
  superseded heads cost nothing at read.

### H8 — cost control (easy)

Three stacked bounds: (i) mint-time — 2048-byte content cap + 16-item
coverage; (ii) assembly-time — the 4096 block budget, disjoint from both
8192s; (iii) stream growth — the change-guard. The window budget, the
elision note, and the summarizer are untouched; no wall-clock anywhere in
fold, mint, or render.

### N-cells (adopted from the argues)

- **N1 — standing/memory_notes dedup** (H6 above; P3's, conceded by both
  rivals).
- **N2 — the replay key repair**: `profile_key_matches?/2` keys the profile
  NAME only (engine.ex:318-326) — a same-profile memory-epoch rotation
  (wide → narrow) would re-serve stale wide-epoch always-on bytes through
  stored-claim-wins. **The key = `(profile, memory-family epoch id)`,
  match-or-rederive; NEVER the digest id** (the digest id changes virtually
  every turn — replay would never hit). Stored-claim-wins stands INTENDED
  where the key matches (mint-time bytes after new digests land = replay
  stability, witnessed). Exactly-one per (request, profile, epoch id).
- **N3 — the contiguous-stop trajectory cap** (H3/H5 above; P3's).
- **N4 — the A5 same-session hardening** (H1 above; P1's find).
- **N5 — genesis evolution is a deliverable + gate item**: TWO kinds —
  `{"StandingDigest", requires: [{"sessionId","entity"},
  {"content","string"}], many: [{"covers","delta"}]}` (the
  ConversationSummary precedent; `covers` = auditability) and
  `{"StandingFlag", requires: [{"standing","entity"}]}`. Regenerated
  `genesis.jsonl` byte-for-byte + `Events.standing_digest/…` +
  `Events.standing_flag/…` under the drift-proof gate + the `:raw`
  admission proof (a pre-evolution binary admits both kinds as `:raw`,
  never crashes — the T14f H5 lesson gates both).

### Acceptance criteria (resolved)

- **AC1** — the always-on block rides every prompt: the standing subset is
  present regardless of the last turn's content (the anti-placebo: a prompt
  engineered for ZERO digest overlap with the standing entities still
  renders them; `prompt_text: nil` renders the block; a standing supersede
  changes the block's bytes — no hardcoding). Deterministic.
- **AC2** — the trajectory reflects recent activity (asked/done/decided
  including GateDecision verdicts), capped at 16 items / 2048 mint bytes,
  CONTIGUOUS (the 17th event displaces the oldest; an overflow stops the
  sequence, never holes it).
- **AC3** — profile isolation: a channel profile's block excludes broader
  memory — leakage witnessed ABSENT through **the fold AND the digest AND
  the replay key** (three doors: the epoch-filtered standing fold; the
  session-scoped digest; the `(profile, epoch id)` replay key — the
  rotation door closed).
- **AC4** — the block is byte-capped (4096, third budget, disjoint) and the
  window's budget is preserved (elision note byte-identical with and
  without the block; `window: 0` still renders the block).
- **AC5** — determinism: `{ts, id}`-ordered everywhere; two sequential cold
  boots over identical wire logs yield IDENTICAL `StandingDigest` ids and
  IDENTICAL `PromptAssembled` ids (no wall-clock, no map-order dependence).
