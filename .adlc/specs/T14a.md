# T14a — The Reactor: the agent runs (T14 umbrella, slice 1 of 4)

Status: SLICE SPEC — the rumble's propose round runs on THIS file. P1 premortem runs AFTER
the Design resolution is appended (the corrected order — never before). Parent umbrella:

## The slice

The event-driven reactor: an agent that RUNS. Today the daemon dispatches on explicit
manual ticks — one tick per pipeline hop, proven live by the AC4 choreography (the
tick-per-hop pattern: builder → engine → tool loop each needed its own tick). The reactor
makes the agent fire on deltas: a store delta whose kind matches a subscription routes to
its handler WITHOUT a manual tick; per-turn budgets constrain the turn; and model
initiation is gated by the Oracle seed.

In scope: `lib/kyber/agent/reactor.ex` + tests. The reactor HOSTS the closed refusal loop
(engine "decides" subscription + refusal routing, merged pre-2026-08-07) — it does not
rebuild it.
Out of scope (later T14 slices): policy layer — URL policy, policy epochs, idempotence
(T14b); prompt-answer-as-delta, memory-read seam, operator-key boot wiring (T14c);
boundary enumeration + precision bounding (T14d).

## Carries touching this slice

- The manual-tick choreography (AC4 live-run finding): the reactor's "fires on deltas"
  subsumes the tick-per-hop pattern; `Daemon.tick/0` stays as the manual flush for tests.
- The refusal loop (T12 carry #1, CLOSED pre-merge): the reactor's first seed — a
  gate-refused call returns to the model, never a hung turn.

## Acceptance criteria (draft — the rumble pins the exact shapes)

- AC1: a delta of a subscribed kind fires its handler WITHOUT a manual tick — one dispatch,
  one handler invocation, provable from store state.
- AC2: per-turn budget — a turn exceeding its budget terminates cleanly with a
  refusal/termination delta; no dead turn, no hang (the mailbox-empty class of failure is
  excluded by construction).
- AC3: gated initiation — model initiation is refused without the gate (the Oracle seed),
  and the refusal routes back to the model (the closed refusal loop, exercised THROUGH the
  reactor).
- AC4 (live, @tag :operational): the AC4 choreography runs WITHOUT ticks — a real model
  turn answers end-to-end, recording preserved; the machine-checked property targets the
  request body, never the answer content. **LIVE-VERIFIED 2026-08-07**: "reactor live ok",
  4.4s, recording preserved (real kimi-k3 via the real Moonshot HTTP path, zero ticks).
- AC5: determinism clause — the reactor's decision surface derives from store state; no
  wall-clock in decisions, budget accounting included (what is counted, how it is counted).

   - SYNTH-NEW-1 (pin 11): turn attribution of chained emissions — an emitted delta is charged to the EMITTING handler's turn, carried via `Ctx.turn` through the re-entry seam. REVISED per premortem H5 — `Ctx.turn` covers only reactor-handler `{:emit, wires}` outputs; ENGINE-originated deltas (ToolCall, kind `"tool"`, SUBSCRIBED) leave via the engine's sink with no `Ctx.turn` attached, so the tool loop — the exact chain the per-turn budget exists to cap — would be turn-less. Pinned fallback: POINTER-WALK ATTRIBUTION. When an ingested delta arrives with no `Ctx.turn` carry, the reactor resolves its turn by walking the delta's claim pointers back to the initiating `"received"` delta: `ToolCall.requestRef → promptRef → the initiating received` (the substrate already pointer-walks this shape in the engine's `rebuild_pending` — reuse that pattern against store state, which keeps the resolution store-derived per AC5). The resolved initiating-`received` content id IS the `turn_id` (pin 11's key, unchanged). Attribution precedence: `Ctx.turn` carry when present; else pointer-walk; a delta that resolves to no turn (no walkable pointer to a `received`) initiates or is ignored per pin 14 — never charged to an arbitrary turn. The budget therefore caps the REAL chain, engine hops included, not just reactor-handler emissions. No proposal or argue document pinned the attribution mechanism explicitly, but AC2's per-turn budget cannot cap a chain without one; the premortem priced it under H-review (H5) and this is the resolution. 6. **Recorded substrate contradiction (premortem M5, verified live — per AGENTS.md the contradiction is the deliverable; recorded, not papered over).** The engine's GateDecision verdict guard compares string to atom: `Schema.resolve` yields the GateDecision `verdict` as the STRING `"allow"`, while the engine's `decides` guard tests `verdict != :allow` (an atom) — the guard is ALWAYS true, so an allow verdict misroutes into the refusal path; with an explicit-allow policy (`reason: nil`) the refusal path then calls `Atom.to_string("allow")` and the engine CRASHES with ArgumentError (verified live with `mix run`). T14a hosts this loop unchanged (pin 5/6 — hosted, never rebuilt), so the AC4 gate configuration MUST be pinned to avoid tripping it: the AC4 operational run uses a gate configuration that never produces an allow-verdict GateDecision reaching the engine's decides path (a tool-less turn, or default-deny with no explicit-allow policy). The one-line guard fix belongs to whichever slice owns the engine's decides path — it is NOT silently fixed under T14a's blast radius (pin 24).
