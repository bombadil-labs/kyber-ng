# T14a — The Reactor: the agent runs (T14 umbrella, slice 1 of 4)

Status: SLICE SPEC — the rumble's propose round runs on THIS file. P1 premortem runs AFTER
the Design resolution is appended (the corrected order — never before). Parent umbrella:
.adlc/specs/T14.md (carry map, ceremony commitments).

## The slice

The event-driven reactor: an agent that RUNS. Today the daemon dispatches on explicit
manual ticks — one tick per pipeline hop, proven live by the AC4 choreography (the
tick-per-hop pattern: builder → engine → tool loop each needed its own tick). The reactor
makes the agent fire on deltas: a store delta whose kind matches a subscription routes to
its handler WITHOUT a manual tick; per-turn budgets constrain the turn; and model
initiation is gated by the Oracle seed.

In scope: `lib/kyber/agent/reactor.ex` + tests. The reactor HOSTS the closed refusal loop
(engine "decides" subscription + refusal routing, merged pre-2026-08-07) — it does not
rebuild it.
Out of scope (later T14 slices): policy layer — URL policy, policy epochs, idempotence
(T14b); prompt-answer-as-delta, memory-read seam, operator-key boot wiring (T14c);
boundary enumeration + precision bounding (T14d).

## Carries touching this slice

- The manual-tick choreography (AC4 live-run finding): the reactor's "fires on deltas"
  subsumes the tick-per-hop pattern; `Daemon.tick/0` stays as the manual flush for tests.
- The refusal loop (T12 carry #1, CLOSED pre-merge): the reactor's first seed — a
  gate-refused call returns to the model, never a hung turn.

## Acceptance criteria (draft — the rumble pins the exact shapes)

- AC1: a delta of a subscribed kind fires its handler WITHOUT a manual tick — one dispatch,
  one handler invocation, provable from store state.
- AC2: per-turn budget — a turn exceeding its budget terminates cleanly with a
  refusal/termination delta; no dead turn, no hang (the mailbox-empty class of failure is
  excluded by construction).
- AC3: gated initiation — model initiation is refused without the gate (the Oracle seed),
  and the refusal routes back to the model (the closed refusal loop, exercised THROUGH the
  reactor).
- AC4 (live, @tag :operational): the AC4 choreography runs WITHOUT ticks — a real model
  turn answers end-to-end, recording preserved; the machine-checked property targets the
  request body, never the answer content.
- AC5: determinism clause — the reactor's decision surface derives from store state; no
  wall-clock in decisions, budget accounting included (what is counted, how it is counted).

## Open decisions the rumble must pin (the propose brief = this list + the pinning list)

1. Where the reactor lives: inside the daemon's dispatch? a new GenServer? replaces the
   tick loop? (integration seam — pin the exact seam).
2. Event delivery: reuse the Gather kinds (received / promptRef / call / tool / decides) —
   the exact subscription map and handler contract (signatures).
3. Budget units and accounting: tokens? turns? both? — the exact budget record shape, where
   it lives in state, and the refusal at the boundary (exact function signatures).
4. Gated initiation: the Oracle seed's exact semantics — what initiates a turn, what the
   gate checks, how the seed is provisioned (back-compat with existing keys/boot paths).
5. The deterministic test: exact seeding + the assertion proving the no-tick property
   (anti-placebo: how it FAILS when the reactor is absent — a manual-tick daemon must make
   it red).
6. The AC4 live-run shape: the machine-checked property (request-body, never
   answer-content).
7. Module/test file names (the deliverable-existence gate).
8. Back-compat shape: `Daemon.tick/0` and the boot opts (`loop: :none`) — unchanged or
   extended, never broken.

## Design resolution (converged plan) — T14a

1. **Pins.** All 26 items, numbered as in contested.md. Shape / provenance / DIFFICULTY.

   1. Public shape: `Kyber.Agent.Reactor.ingest(delta :: map()) :: :ok` (cast). Provenance: hybrid of P2+P3 via the A2/A3 argue repair; all three reflects converge (R1.1, R2.1, R3.1); carries UNARGUED U1. DIFFICULTY: hard.
   2. Supervision placement — early: after the store, before dispatch children (a last-child reactor leaves boot-window deltas with no observer). P1/P2 via unanimous reflect (R3 switched). DIFFICULTY: easy.
   3. Subscription map mutability — static module-attribute constant `@subscriptions`; NO runtime `subscribe/2`; test observation rides `Ctx.test_pid` and never mutates routing (spec decision 2: "the exact subscription map" is pinned at write time). P1/P2 via unanimous reflect. DIFFICULTY: easy.
   4. Kind representation — wire strings verbatim: `"received"`, `"promptRef"`, `"call"`, `"tool"`, `"decides"` (spec decision 2 spells them as strings; the substrate's `Gather.subscribe/2` takes string roles; CLAUDE.md: no internal dialect — no atom mapping, no `normalize_kind`). P1 via unanimous reflect (R2 and R3 both switched). DIFFICULTY: easy.
   5. Kind set — the five Gather kinds only; no `:refusal` kind. Refusals ARE GateDecision deltas routed as `"decides"` (spec: the reactor "HOSTS the closed refusal loop … it does not rebuild it"). P1/P2 via unanimous reflect. DIFFICULTY: easy.
   6. Refusal reasons pinned: `{:refuse, :no_oracle_seed}` (gate), `{:refuse, :budget_exhausted}` (budget), both routed through the existing "decides" refusal loop. P2 contract + P1 rule, unanimous reflect. DIFFICULTY: medium.
   7. Emission loop-back — emitted deltas re-enter the same commit seam (pin 1) and dispatch once each, one dispatch per delta id; the budget caps the chain; turn end is STRUCTURAL (chain end or budget refusal), never mailbox-emptiness (AC2: "the mailbox-empty class of failure is excluded by construction"). P2/P3 via unanimous reflect (R1 conceded no-chain). DIFFICULTY: hard.
   8. Re-fire/flush dedupe — routing owns once-per-delta-id; the store's content-addressed admission skip is the backstop; NO capped MapSet cache (the 1024 wraparound silently re-permits double-fire). P1/P2 via unanimous reflect. DIFFICULTY: medium.
   9. Budget units — dispatch-units only as the live counter: one unit per dispatched delta of a subscribed kind (store-derived by construction — AC5); P2's conditional clause retained DORMANT: a token charge fires only when a store delta carries usage (no such delta exists in T14a; the seam is T14c's, where usage rides the answer delta). Hybrid: P3 core + P2 clause (R1/R2 hybrid, R3 keep). DIFFICULTY: easy.
   10. Charge point — check-before-dispatch: an exceeding dispatch never fires (the tighter AC2 reading); P2's boundary semantics: a charge landing exactly on max succeeds, the next exhausts. P2/P3 via unanimous reflect. DIFFICULTY: easy.
   11. Turn/budget state — `%Kyber.Agent.Reactor.Turn{turn_id: binary(), budget: Budget.t()}` held in reactor state as `%{turns: %{turn_id => Turn.t()}}`; `turn_id` = the initiating `"received"` claim's content-derived id; chained emissions are charged to the emitting dispatch's turn, carried via `Ctx.turn` through the re-entry (see SYNTH-NEW-1).    12. Default cap + override — single cap, `@default_cap 32`, boot opt `budget_cap: pos_integer()` (the AC2 test needs a tiny cap, so the override must exist). P3 shape, 2-of-3 number, unanimous reflect. DIFFICULTY: easy.

   14. Turn initiation + gate placement — a turn is initiated by a `"received"` delta (P1; the Turn record is created there); the gate check is a PURE store check on the first line of BOTH the `"received"` and `"promptRef"` handlers (closes the directly-written-promptRef bypass A2 conceded); `"call"` is the ToolResult role and is never an initiation gate (vacuous — A2/A3 substrate fact).    15. Seed scope — one singular Oracle seed, presence semantics ("the Oracle seed", definite article; per-pubkey authorization is T14b policy surface this slice doesn't own). P2/P3 via unanimous reflect. DIFFICULTY: easy.
   16. Gate check semantics — gate open iff an UNRETRACTED seed claim exists; retraction closes it (binding atom: retraction-is-negation; in a store that only learns, presence-only is irrevocable — R3 conceded). P1/P2 via unanimous reflect. DIFFICULTY: medium.
   17.    18. 3. **UNARGUED dispositions.** (Adopted items are priced by the premortem under H-review — not buried.)
   - U1 (cast emitted from inside the store's append process): ADOPT — it is the only seam where delivery order == commit order holds under concurrent committers; a daemon-side hook inherits the cursor-poll delay, which IS a tick (fails AC1). H-review.
   - U2 (`tick_ms: :manual` in the deterministic test boots): ADOPT — without it the daemon's default 250 ms auto-tick greens the anti-placebo red run and pollutes the exactly-once proof. H-review.
   - U3 (per-invocation-distinct probe emissions): ADOPT — merge-is-union collapses identical re-emissions to one claim, so store-count==1 without distinctness is itself placebo-able. H-review.
   - U4 (ownership-transfer mechanism for `reactor: true`): REJECT — mooted: pin 25 selects `loop: :reactor`, so there is no `reactor: true` opt to transfer ownership for; ownership is structural on the argued loop axis (A3's R19 point — the ack loop is simply never the owner of `"received"` in reactor mode), and no new transfer mechanism ships.

4. **SYNTH-NEW flags.**

No proposal or argue document pinned the attribution mechanism explicitly, but AC2's per-turn budget cannot cap a chain without one; the premortem prices it exactly like an UNARGUED adoption. (No other resolution element is untraceable: the demoted chain-observation is A3's R16, the distinct-probe shape is A3's R15, the pulse admission is A3 §2, the boundary semantics are P2's.)
