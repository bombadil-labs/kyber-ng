# T14 — The Agent Runs: event-driven waking, initiation, the Oracle seed

Rev 1 — arc ticket of the ORACLE ARC (user mandate 2026-08-06; PLAN.md §0). Builds on T11
(think + remember), T12 (act), T13 (associate). T14 closes the loop: the agent does not wait
to be asked — it wakes on events, initiates within its gated powers, and its operation is
itself a store-citizen (signed claims, auditable, provenance-ranked).

## Why

Everything so far is reactive: a prompt arrives, the chain answers. The Class 4 Oracle the
user is building wakes on its own: a memory edit, a vault change, a scheduled moment, a
saturated context — and the agent ACTS on the event within its gated capability surface. The
loop is event-driven by construction (the harness's own doctrine: no daemon/heartbeat, wake on
callbacks), the store is the memory across restarts, and every initiation is a signed claim
with a gate decision — nothing autonomous-beyond-bounds (the user's guardrail: aligned by
construction).

## Deliverables (scope: `lib/kyber/agent/reactor*` + `lib/kyber/agent/agent.ex` extension + `test/reactor*`)

- **`Kyber.Agent.Reactor`** — the event-driven waker: subscribes to the gather's events
  (prompts, watcher ticks, memory edits, gate decisions) and to a scheduler (one-shot +
  interval callbacks, the no-sleep drive — `send_after`, never `Process.sleep`); on wake it
  builds an `AgentTurn` (a `SubmittedPrompt`-shaped claim authored by the agent itself,
  attested, gated) and hands it to the chain. An agent-authored turn is a claim like any
  other — the store learns it, the memory stores it, provenance ranks it (agent-auto,
  below human).
- **`Kyber.Agent.Reactor.Scheduler`** — bounded scheduling: at-most-one-pending per trigger
  (no pile-ups), a max daily budget of agent-initiated turns (a boot option), and a
  cooldown between initiations. Budget exhaustion is a refused-reason claim (reject, never
  repair).
- **`Kyber.Agent.Reactor.Policy`** — which events may wake the agent INTO ACTION vs. which
  only warm the association cache (T13's saturation): a boot table `{event, allowed_actions,
  budget_cost}`. A memory edit by a HUMAN may wake a limited action set; a watcher tick alone
  never does; anything with a side effect passes the T12 gate, always.
- **`Kyber.Agent` extension** — `initiate/2`: the public entry for an agent-authored turn
  (used by the reactor AND by tests), routing through the gate + chain exactly like an
  external prompt, so the agent's own initiations are indistinguishable in the store from
  any other turn (the same deltas, the same guarantees).

## Acceptance criteria

- **AC1 — The agent wakes, gated:** a human memory edit (T11c watcher) wakes the reactor;
  the reactor builds an agent-authored turn and the chain runs it WITHIN the policy's allowed
  actions and budget; the turn is a signed claim authored by the agent, persisted, and its
  provenance is agent-auto (below human). verify: the reactor test drives a watcher tick,
  asserts the agent-authored `SubmittedPrompt`-shaped claim, its gate decision, and its
  persistence.
- **AC2 — Budgets are real:** the max-daily-budget and cooldown hold — a burst of events
  produces at most one pending initiation per trigger, and budget exhaustion emits a
  refused-reason claim, never a silent drop. verify: the budget test bursts N events and
  asserts ≤1 pending + the refused-reason claim on exhaustion.
- **AC3 — The store is the memory across restarts (carried):** an agent-authored turn's
  outcome (ToolResults, ResponseDelta, memory entities) survives a daemon restart — the
  reactor rehydrates by replay (the T11c container), no turn is re-initiated after a crash
  (the byte-identical re-fire). verify: the restart test kills and re-boots mid-turn and
  asserts no re-initiation + the persisted outcome.
- **AC4 — The operational run (THE gate):** Hermes boots the daemon on a tmp store/keyring
  with a REAL model; a human memory edit wakes the reactor; the agent initiates a gated turn
  (an fs.read of a planted fixture via T12) whose outcome is a persisted ToolResult and
  ResponseDelta; SIGTERM; re-boot; no re-initiation; the outcome is in the store. verify: the
  recorded operational run (this exact sequence) with the real model, machine-checked by the
  smoke.
- **AC10 — Gates (carried):** no `Process.sleep` in test/ (the reactor's scheduler is the
  no-sleep drive — `send_after`); rails frozen; tmp everywhere; format clean;
  warnings-as-errors clean. verify: the carried greps + rails-guard.

## Carried contract (binds this slice)

- Gate decisions are deltas (T12) — the reactor's initiations carry them; deny is fail-closed.
- Provenance as authority (T11c): agent-auto never outranks human; the T13 divergent channel
  never surfaces agent-auto above human-edited memory.
- The determinism clause (T11b/T13): the reactor's wake logic is a pure function of the store
  + scheduler state; re-fires answer from the store, never re-initiate.
- The user's guardrail, in the contract: NO event type may wake the agent into an action the
  policy table does not name; the policy table is boot data, attested, auditable.
