# T2 — Loop 2: The Durable Store

## Context

T1 (archived) built the door: the pinned wire envelope `{id, claims, sig}` verified then
merged into an in-memory grow-only set (spec/04-persistence.md §3). T2 makes the store
remember across restarts: an append-only JSONL wire log behind the door, replayed through
`Kyber.Store.admit/2` (re-verify + re-merge, spec/04-persistence.md §2) on boot. The
substrate (deps/rhizomatic) stays FROZEN; the witness has no serializer, so wire envelopes
are kyber's own JSON (Elixir's built-in JSON module).

## Requirements

1. **Kyber.Log** — the append-only file (Verification: `mix test test/log_test.exs`):
   - `open(path)` → `{:ok, io} | {:error, _}` — opens in append+create mode.
   - `append(io, wire_json_map)` → `:ok | {:error, _}` — one envelope per line (JSON text,
     newline-terminated).
   - `stream(path)` → lazy lines (Enumerables), for replay.
   - Torn-write tolerant: a partial final line is reported, never fatal — the log never
     rewrites or deletes anything (append-only; spec/04 §2).
2. **Kyber.DurableStore** — the door on disk (Verification: `mix test test/durable_store_test.exs`):
   - `start_link(log_path)` → replays the whole log through `Kyber.Store.admit/2` into the
     in-memory set (every signature re-verified, union-merged); serves from there.
   - `append(wire_json_map)` → `:ok | {:error, reason}` — the SAME door as `Kyber.Store`
     (verify → merge → persist, in that order); a rejected delta is neither merged nor
     written.
   - `set()` → the current delta set.
   - No second verification path — replay and live appends share `Kyber.Store.admit/2`.
3. **Replay integrity** (Verification: `mix test test/durable_store_test.exs`):
   - a tampered line mid-log (valid JSON, invalid signature/id) is refused and reported;
   - a torn final line (truncated JSON) is tolerated and reported;
   - duplicates across the log are no-ops (union).
4. TDD; no Process.sleep (assert_receive/3 or state polling); `mix format` clean.
   Verification: `grep -r "Process.sleep" test/` finds nothing, and `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes.**
  Verification: `mix test` exits 0 with no skips.
- **AC2 — A delta survives a restart: open → append → stop → reopen → the delta is present
  and its signature re-verifies.**
  Verification: `mix test test/durable_store_test.exs` (append, stop_supervised, restart,
  assert member + `Rhizomatic.Signer` re-verify).
- **AC3 — A torn final line is tolerated: earlier lines replay, the torn line is reported,
  the store serves.**
  Verification: `mix test test/durable_store_test.exs` (write a truncated envelope as the
  last line; boot; assert the honest set + a reported warning/return).
- **AC4 — A tampered line mid-log is refused and reported; the store serves the honest
  remainder.**
  Verification: `mix test test/durable_store_test.exs` (mutate a line's sig; boot; assert
  the set excludes it and the refusal is reported).
- **AC5 — Replay is order-independent: the same log lines in shuffled order converge to the
  same set (union).**
  Verification: `mix test test/durable_store_test.exs` (two logs, shuffled lines, equal
  sets).
- **AC6 — The log is append-only: nothing is ever rewritten or deleted; a rejected delta is
  not written.**
  Verification: `mix test test/log_test.exs` (byte-count and line-count checks; a bad
  envelope leaves the file unchanged).
- **AC7 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.
