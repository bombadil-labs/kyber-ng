# T2 — Loop 2: The Durable Store (rev 2)

## Context

T1 (archived) built the door: the pinned wire envelope `{id, claims, sig}` verified then
merged into an in-memory grow-only set (spec/04-persistence.md §3). T2 makes the store
remember across restarts: an append-only JSONL wire log behind the door, replayed through
`Kyber.Store.admit/2` (re-verify + re-merge, spec/04-persistence.md §2) on boot. The
substrate (deps/rhizomatic) stays FROZEN; the witness has no serializer, so wire envelopes
are kyber's own JSON (Elixir's built-in JSON module).

Rev 2 folds the premortem (8/8 causes accepted): exhaustive per-line replay classification
(cause 1), a pinned replay-report observable (2), pinned topology — DurableStore is THE
running store (3), write-ahead persist-then-merge (4), pinned encoder + stored-line
round-trip AC (5), first-boot contract (6), serialized appends via GenServer ownership (7),
and the Log/Door AC6 split (8).

## Requirements

1. **Kyber.Log** — the append-only file with the pinned API below; torn-write tolerant (a
   partial final line is reported, never fatal; the log never rewrites or deletes
   anything). It is a DUMB serializer: it refuses only non-map input and input Elixir's
   stdlib `JSON` cannot encode (transport-level) — it CANNOT verify signatures (the door is
   DurableStore). Encoder contract (rev 4, P5 adjudication): encode errors
   (values with no `JSON.Encoder` implementation — PIDs, tuples, refs, structs — the only
   reachable raises) map to `{:error, {:encode, reason}}`; non-map input maps to
   `{:error, {:encode, :not_a_map}}`; maps with NON-STRING keys are REFUSED with
   `{:error, {:encode, :non_string_key}}` (the stdlib encoder silently stringifies them —
   reject, never repair; keeps AC10's term-identical round-trip honest). Two rev-2 facts
   corrected: NaN/Infinity are NOT representable as Elixir floats (unreachable —
   finiteness holds per `Rhizomatic.Delta`). Verification: `mix test test/log_test.exs`.

   ```elixir
   open(path) -> {:ok, io} | {:error, _}            # append+create mode
   append(io, wire_json_map) -> :ok | {:error, _}   # one envelope per line (JSON text, NL-terminated)
   stream(path) -> Enumerable of lines              # lazy, for replay; zero lines for a missing path
   ```

2. **Kyber.DurableStore** — THE running store (Kyber.Store stays the pure door — `admit/2`
   plus the T1 in-memory Agent for T1-compat and tests; the harness runs DurableStore,
   never both in one app). It is a GenServer that owns the log device AND the delta set, so
   appends are serialized through one process and each line+newline is a single
   `IO.binwrite` (concurrent appends cannot interleave; two DurableStore instances on one
   log is out of scope). `start_link/1` → `{:ok, pid} | {:error, reason}`; first boot on a
   nonexistent path returns `{:ok, pid}` with an EMPTY set and the log is created lazily on
   the first append. `append/1` is WRITE-AHEAD: verify → persist → merge, in that order — a
   rejected delta is neither persisted nor merged, and a failed write leaves the in-memory
   set and the file unchanged, returning `{:error, :persist_failed}`. Replay on boot runs
   every line through `Kyber.Store.admit/2` (re-verify every signature, union-merge), NEVER
   halts on a bad line, and never rewrites the file. A stored line decodes to a
   term-identical envelope map (claims byte-verbatim) and re-admits.
   Verification: `mix test test/durable_store_test.exs`.

   ```elixir
   start_link(log_path) -> {:ok, pid} | {:error, reason}
   append(wire_json_map) -> :ok | {:error, reason}   # verify -> persist -> merge (write-ahead)
   set() -> DeltaSet.t()
   replay_report() -> %{refused: [non_neg_integer], torn: [non_neg_integer], failed_appends: non_neg_integer}
   ```

   `replay_report/0` is the pinned observable: refused/torn LINE NUMBERS from the last boot
   replay, plus `failed_appends` — a LIVE count of failed live appends (incremented on every
   `{:error, :persist_failed}`, monotonic since boot; the store's write-health signal that
   survives the boot snapshot).

3. **Replay classification — exhaustive per-line policy** (for every line on boot):
   valid JSON that admits → merge (union); torn/partial FINAL line (truncated JSON at EOF)
   → tolerate + report in `torn`; torn/partial NON-final line (crash left it mid-log; live
   appends continue after it) → report in `torn` + skip + continue (never repaired — AC6;
   the delta is unrecoverable by design, every boot re-reports it); empty/whitespace line →
   skip silently; valid JSON NOT the pinned envelope shape → refuse + report in `refused` +
   continue; valid JSON with wrong id/signature (tampered) → refuse + report in `refused` +
   continue. Verification: `mix test test/durable_store_test.exs`.
4. TDD; no Process.sleep (assert_receive/3 or state polling); `mix format` clean.
   Verification: `grep -r "Process.sleep" test/` finds nothing, and `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes.**
  Verification: `mix test` exits 0 with no skips.
- **AC2 — A delta survives a restart: open → append → stop → reopen → the delta is present
  and its signature re-verifies.**
  Verification: `mix test test/durable_store_test.exs` (append, stop_supervised, restart,
  assert member + `Rhizomatic.Signer` re-verify).
- **AC3 — A torn FINAL line is tolerated and REPORTED: earlier lines replay, the store
  serves, and `replay_report().torn` names the line.**
  Verification: `mix test test/durable_store_test.exs` (truncated envelope as the last
  line; boot; assert the honest set and `replay_report()` == `%{refused: [], torn: [n]}`).
- **AC4 — A tampered line mid-log is refused and REPORTED: the set excludes it, the store
  serves the honest remainder, and `replay_report().refused` names the line.**
  Verification: `mix test test/durable_store_test.exs` (mutate a line's sig; boot; assert
  the set excludes it and `replay_report()` == `%{refused: [n], torn: []}`).
- **AC5 — Replay is order-independent: the same log lines in shuffled order converge to the
  same set (union).**
  Verification: `mix test test/durable_store_test.exs` (two logs, shuffled lines, equal
  sets).
- **AC6 — Split boundary: Log.append/2 refuses only non-map / non-encodable input
  (transport-level, file unchanged); DurableStore.append/1 refuses everything the door
  rejects (wrong key, tampered id, unsigned) and writes NOTHING.**
  Verification: `mix test test/log_test.exs` (bad input leaves the file unchanged) and
  `mix test test/durable_store_test.exs` (door-rejected delta: set unchanged, file
  unchanged).
- **AC7 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.
- **AC8 — A mid-log torn line is classified: log of [valid, PARTIAL, valid] boots with the
  honest set (both valid deltas) and `replay_report().torn` names the middle line.**
  Verification: `mix test test/durable_store_test.exs` (write valid, truncated, valid;
  boot; assert both valid deltas present, middle line in `torn`).
- **AC9 — Write-ahead: an injected persist failure (closed device) returns
  `{:error, :persist_failed}`, leaves the in-memory set unchanged, and leaves the file
  unchanged.**
  Verification: `mix test test/durable_store_test.exs` (close the device behind the store's
  back, append, assert error tuple + unchanged set + unchanged file).
- **AC10 — Stored-line round-trip: a stored line decodes to a term-identical envelope map
  (claims byte-verbatim) and re-admits through `Kyber.Store.admit/2` with `{:ok, _}`.**
  Verification: `mix test test/durable_store_test.exs` (decode a line from the log, compare
  term-equality with the appended map, re-admit).
- **AC11 — First boot on a nonexistent path returns `{:ok, pid}` with an empty set; the log
  file is created on the first append, not at boot.**
  Verification: `mix test test/durable_store_test.exs` (fresh tmp path; boot; empty set;
  File.exists? false until first append).
- **AC12 — The replay report is the pinned observable: `replay_report/0` returns
  `%{refused: [...], torn: [...], failed_appends: n}` — `%{refused: [], torn: [],
  failed_appends: 0}` on a clean replay, and `failed_appends` increments on every
  `{:error, :persist_failed}` (live write-health signal, monotonic since boot).**
  Verification: `mix test test/durable_store_test.exs` (clean boot asserts the empty-report
  shape; AC3/AC4/AC8 assert the non-empty shapes; the AC9 persist-failure test asserts
  `failed_appends == 1`).
