# T4 — Loop 4: The Harness Loop — gather → translate → sign → persist → view (rev 2)

## Context

T1–T3 built the machinery: the door (Store.admit/2), the durable store (Log +
DurableStore), the production wire (Kyber.Wire), the supervision tree (Kyber.Application).
Nothing yet RUNS the loop — "a Discord message in, a model response out" at the atom (the
founding objective, SPEC.md). T4 wires it: a source event in → a signed claim persisted →
a materialized view out. The real transport (Discord etc.) is gated on the substrate L4
reactor; T4 builds the loop against an injectable SOURCE interface (a plain map shape)
with fake sources in tests — the plugin ticket later is a thin adapter on this interface.

Rev 2 folds the 9-cause premortem (all accepted): the harness_test lifecycle is pinned
(store-down guard, boot/stop choreography), load_human_seed has NO env fallback (identity
confusion hazard), the source shape's malformed-input contract is pinned (missing keys,
unknown keys), view/0's order and shape are pinned, AC1 pins a REAL base hash (the T3
lesson), AC7's coercion tension is resolved (builder-owned per D14), and the keyring_dir
wiring is verified (no runtime default).

## Requirements

1. **Kyber.Harness** — the loop, pure + the running store (no new process; the
   app-started DurableStore is the sink). Verification: `mix test test/harness_test.exs`.

   ```elixir
   ingest(source_event, keyring_dir) -> {:ok, id} | {:error, reason}
   agent_event(model_event, keyring_dir) -> {:ok, id} | {:error, reason}
   view() -> [claims]   # materialized from DurableStore.set(), sorted by id
   ```

   **The SOURCE shape (pinned, rev 2):** `ingest/2` takes a map with REQUIRED keys
   `"message_id"`, `"channel_id"`, `"session_id"`, `"content"` (all binaries) and OPTIONAL
   `"ts"` (float-ms, D14; default = now as float ms). Missing required key →
   `{:error, {:missing_key, :source, key}}` (defensive `Map.fetch`/`Map.get` — a
   destructuring pattern match is FORBIDDEN: it raises MatchError, not a tagged tuple).
   UNKNOWN keys are REFUSED — `{:error, {:unknown_key, :source, key}}`, mirroring the
   door's closed-envelope norm (reject, never repair); extra fields cannot be smuggled
   into claims. Any error is a tagged tuple, never a crash.
   **Store-down guard (rev 2):** `ingest/2` and `agent_event/2` check
   `Process.whereis(Kyber.DurableStore)` FIRST — with the app not running they return
   `{:error, :store_not_running}` (mirroring `Store.append/1`), because
   `DurableStore.append/1` is a bare `GenServer.call` that raises `exit(:noproc)` when the
   store is down (T2 made the app the store's owner).
   Pipeline: load the HUMAN seed (`Keys.load_human_seed/1`) → `Events.message_received/6`
   → `Wire.envelope/1` → `DurableStore.append/1` → `{:ok, envelope_id}`. A refused delta
   returns the door's reason unchanged.
   **`agent_event/2`:** the response half — same pipeline with the AGENT seed
   (`Keys.load_agent_seed/1`) and `Events.message_sent/6` from `%{"response_delta_id",
   "out_message_id", "channel_id", "content"}` (same required/optional/unknown-key
   contract).
   **`view/0` (rev 2 pin):** `DurableStore.set()` is a map `id_hex => {claims, sig}` (atom
   keys — NOT wire envelopes); `view/0` returns the LIST of `claims` (atom-keyed claim
   maps), SORTED BY id_hex (deterministic order — `Enum.sort_by`), so view equality is
   assertable.
2. **Kyber.Keys.load_human_seed/1** — reads `home_dir/human.seed` (0600). **NO env
   fallback (rev 2 — identity confusion hazard):** unlike `load_agent_seed/1`, it must NOT
   consult `KYBER_SEED` nor write the file on load — `import_human_seed/2` is the ONLY
   import path for the human identity. Missing file → `{:error, :no_human_seed}`; missing
   dir → `{:error, {:keyring_dir_missing, path}}` (distinct, AC6-split).
   Verification: `mix test test/keys_test.exs`.
3. **Config** — `config/config.exs` gains `keyring_dir` (default `~/.kyber`, SAME HOME
   guard as log_path — raise on empty user_home); `config/test.exs` overrides it to the
   tmp dir. The harness has NO runtime keyring default — the caller's `keyring_dir` arg is
   the only source (rev 2). Verification: `mix test test/harness_test.exs` + AC11.
4. **harness_test lifecycle (rev 2, the T3 choreography contract) — Verification:
   `mix test test/harness_test.exs`:** `setup_all` does
   `Application.ensure_all_started(:kyber)` (the config/test.exs tmp log_path + keyring
   dir), `on_exit` does `Application.stop(:kyber)` — mirroring test/application_test.exs.
   The AC3 restart test re-boots the app after itself (or is declared LAST in the file);
   no harness test may leave :kyber stopped mid-file. T2's durable_store_test (which
   start_supervised!'s its own instances on the SAME global name) must stay green and
   byte-untouched.
5. TDD; no Process.sleep; `mix format` clean. Verification: `grep -r "Process.sleep"
   test/` finds nothing, `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes; T1–T3 test files byte-untouched, pinned base
  (rev 2 — the main-only empty-diff trap):** `git diff 7f42335a -- test/` touches ONLY
  test/harness_test.exs and test/keys_test.exs; `git diff 7f42335a -- config/` shows ONLY
  the keyring_dir additions (config.exs + test.exs); `mix test` exits 0 with no skips.
  Verification: the two git diff commands above (7f42335a = the pre-T4 commit, pinned at
  rev 2) + `mix test`.
- **AC2 — End-to-end ingest: a fake source event ingests to a persisted, verified claim.**
  After `{:ok, id} = Harness.ingest(source_event, keyring_dir)`: `DurableStore.set()` is
  keyed by id with `{claims, sig}` values (the value at set()[id] is `{claims, sig}`, NOT
  an envelope — rebuild via `Wire.envelope({claims, sig})` for re-admission); the id
  equals `Delta.id_hex(claims)` (content address); the claim's author equals
  `Keys.author_for_seed(human_seed)`; re-admitting the rebuilt envelope through the door
  returns `{:ok, _}` (admitted means verified).
  Verification: `mix test test/harness_test.exs`.
- **AC3 — Restart survival: ingest → supervised restart → the claim is still there.**
  `Application.stop(:kyber)` + `ensure_all_started` on the same log path, then
  `Harness.view()` contains the claim (replay through the door). The test re-boots the
  app before returning (or runs last) so no later test sees a stopped store.
  Verification: `mix test test/harness_test.exs`.
- **AC4 — The response half: `agent_event` signs with the AGENT key (author = agent
  pubkey), persists, and the view shows BOTH claims (the loop's two halves, union).**
  Verification: `mix test test/harness_test.exs`.
- **AC5 — The source interface is injectable: a second VALID source shape (different
  channel/content) flows through unchanged — distinct ids, both in the view; the map
  fields land in the claim's pointers exactly as translated by Events. Malformed shapes
  are REFUSED per the source contract: missing key → `{:error, {:missing_key, :source,
  key}}`; unknown key → `{:error, {:unknown_key, :source, key}}`; atom-keyed map → the
  missing-key error for the first required key (defensive fetch, no MatchError).**
  Verification: `mix test test/harness_test.exs`.
- **AC6 — Missing keyring fails cleanly, two DISTINCT errors (rev 2):** keyring dir
  missing → `{:error, {:keyring_dir_missing, path}}`; dir present but human.seed missing
  → `{:error, :no_human_seed}`; neither ever crashes.
  Verification: `mix test test/keys_test.exs` + `test/harness_test.exs`.
- **AC7 — Deterministic timestamps (rev 2 — builder-owned coercion) — Verification:
  `mix test test/harness_test.exs`:** the source `"ts"`
  MUST be a FLOAT — assert the claim's timestamp equals the input float exactly under
  both `==` and `===`; integer input is coerced to float by the builder per D14
  (documented, NOT harness behavior); "no coercion" means no harness-side coercion beyond
  the builder.
- **AC8 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.
- **AC9 — Store-down is a tagged tuple, never a crash (rev 2):** with :kyber stopped,
  `Harness.ingest/2` and `Harness.agent_event/2` return `{:error, :store_not_running}`.
  Verification: `mix test test/harness_test.exs` (stop the app, call, assert the tag,
  re-boot).
- **AC10 — view/0 is deterministic and assertable (rev 2):** `view/0` returns the
  atom-keyed claims sorted by id_hex; two calls on the same store return equal lists.
  Verification: `mix test test/harness_test.exs`.
- **AC11 — keyring_dir wiring is live, not dead config (rev 2):** in the test env,
  `Application.get_env(:kyber, :keyring_dir)` points under `System.tmp_dir!()`; harness_test
  DERIVES the dir it passes from that env key (the override is exercised; seeds land in
  tmp, never in the real ~/.kyber).
  Verification: `mix test test/harness_test.exs` (assert env key under tmp_dir + assert
  no ~/.kyber/human.seed or agent.seed appeared during the run).
