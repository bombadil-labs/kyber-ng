# T1 — Loop 1: The Unified Event Layer

## Context

Kyber is being rewritten on rhizomatic ground: every event is a signed, content-addressed,
loam-compatible claim (SPEC.md, spec/00-overview.md — the unification, D1). This ticket
implements the event layer: the keyring, the claim templates, the delta set, and the store
door — proven by ExUnit tests. The substrate (the rhizomatic Elixir witness at deps/rhizomatic)
is FROZEN and consumed as a git dep; it is never edited from here (spec/03-substrate.md).

## Requirements

1. Kyber.Keys — agent seed mint/load (0600 file under a home dir option; KYBER_SEED hex
   import), human key import, `author_for_seed/1` -> `"ed25519:..."`, signing via
   Rhizomatic.Signer. File I/O confined to this module (spec/02-identity.md).
   Verification: `mix test test/keys_test.exs`.
2. Kyber.Events — claim builders `message_received`, `prompt_annotated`, `llm_response`,
   `message_sent`, `tool_exec` with the exact pointer structures of spec/01-events.md §2,
   signed with the right key: human-origin by the human key, agent-origin by the agent key.
   Verification: `mix test test/events_test.exs`.
3. Kyber.DeltaSet — grow-only set: `merge/2` (union), `member?/2`, `size/1`
   (spec/04-persistence.md §1).
   Verification: `mix test test/delta_set_test.exs`.
4. Kyber.Store — the door (spec/04-persistence.md §3): parse wire JSON via
   Rhizomatic.Profile, recompute the id, verify the signature strictly, then merge; reject
   tampered ids and wrong-key signatures.
   Verification: `mix test test/store_test.exs`.
5. TDD throughout; no Process.sleep in tests; `mix format` clean.
   Verification: `grep -r "Process.sleep" test/` finds nothing, and `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The event layer compiles and the whole suite passes.**
  Verification: `mix test` exits 0 with no skips.
- **AC2 — Every emitted delta's id recomputes from its canonical bytes, and its signature
  verifies.**
  Verification: `mix test test/events_test.exs` asserts, for each Kyber.Events delta, that
  `Rhizomatic.Hash` recomputes the same id from the canonical bytes and `Rhizomatic.Signer`
  verifies the signature.
- **AC3 — message_received is signed by the human's key; llm_response and message_sent are
  signed by the agent's key.**
  Verification: `mix test test/events_test.exs` asserts each delta's `claims.author` equals
  the derived author of the expected seed (human vs agent).
- **AC4 — DeltaSet.merge is commutative and idempotent on a 3-delta fixture.**
  Verification: `mix test test/delta_set_test.exs` asserts `merge(a, b) == merge(b, a)` and
  `merge(s, s) == s` for the fixture sets.
- **AC5 — The door rejects a tampered id and a wrong-key signature.**
  Verification: `mix test test/store_test.exs` asserts `Kyber.Store` returns `{:error, _}`
  for both cases.
- **AC6 — The wire JSON (JSON debug profile) of a signed message_received round-trips through
  Rhizomatic.Profile to identical canonical bytes — the loam-compatibility proof.**
  Verification: `mix test test/events_test.exs` compares canonical bytes before and after a
  Profile parse/re-serialize round-trip.
- **AC7 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.
