# T9 — Loop 9: Federation Peers — the wire speaks to itself over the network (TCP) (rev 2)

## Context

T5 made the wire portable (export/import); T8 gave the operator a CLI. T9 makes
federation REAL: a `Kyber.Peer` TCP listener (stdlib `:gen_tcp` — ZERO new deps) serves
the federation wire; a client connects, sends the export text, and the peer imports it
through the SAME door (Federation.import/1). The trust model IS the claims: every
signature is re-verified at the door, a peer can only ADD signed, content-addressed
claims — the store only learns. Garbage input is refused per line (the import report),
never a crash; a dropped OR idle connection is a non-event; store-down answers a clean
refusal line. `kyber serve --port N` and `kyber send <host> <port>` extend the CLI
(lib/ scope).

**Protocol (PINNED — rev 2 folds the 8-cause premortem, incl. the off-by-one frame
deadlock and the phantom-skipped):**

- A frame = the federation wire text PLUS the blank terminator: `wire_text <> "\n\n"`.
  NOTE the TWO newlines (rev 2): the T5 export byte shape is pinned NO trailing
  newline, so one `"\n"` would produce NO blank line and the first live exchange
  would deadlock (handler waits for the terminator, sender waits for the reply). The
  blank line after the final envelope IS the terminator — the protocol's one new
  grammar element, and it is pinned HERE.
- The handler reads `:line`-delimited packets (each INCLUDES its trailing `"\n"`),
  accumulating NON-BLANK packets only (rev 2 — the terminator packet is a DELIMITER
  and is DROPPED before joining: joining it in would leave a surviving blank segment
  that import counts as a phantom `skipped=1`; the blank predicate is
  `String.trim(line) == ""` — CRLF-safe), until a blank packet arrives; joins the
  accumulated lines with `"\n"` → `Federation.import/1` on the joined text (the empty
  frame → `import("")` → `ok imported=0 skipped=0 refused=0`).
- The reply = ONE status line, newline-terminated: `ok imported=N skipped=N refused=N`
  (every completed import, including the empty frame), or `err <tag>` for a tagged
  import error. The `err` renderer is pinned for EVERY import error shape:
  `:store_not_running` → `err store_not_running`; `{:import_failed, line_no, reason}`
  → `err import_failed:<line_no>`; `{:store_exit, info}` → `err store_exit:<info>`.
  The peer never sends an unparseable status and never crashes.
- The connection closes after the reply (one frame per connection). A client that
  connects and stays silent (no blank terminator) is dropped after a recv TIMEOUT
  (rev 2 — no idle process/fd leaks; the drop is the non-event path); a client that
  drops mid-frame (closed) is likewise a non-event; the LISTENER survives both.

**Socket mechanics (PINNED — rev 2, the load-bearing :gen_tcp contract):** the peer
GenServer owns the listen socket and loops: `:gen_tcp.accept(listen, timeout)` (an
accept timeout keeps GenServer.stop/1 from hanging on the blocking NIF) →
`:gen_tcp.controlling_process(socket, handler_pid)` (THE transfer — without it the
handler's first recv fails not_owner) → `spawn` (UNLINKED — a handler crash must not
take down the listener) the handler → re-accept. `Peer.stop/1` closes the listen
socket + stops the GenServer (tests start/stop peers; the API is complete).

**Trust & scope note:** no auth/TLS — the claims ARE the trust (the door re-verifies
every signature; a peer can only add). Transport encryption is a later ticket. The
peer is started EXPLICITLY (`Kyber.Peer.start_link/1`) — NOT in the application
supervision tree (the app must not listen by default); the CLI's `serve` starts it.

## Requirements

1. **Kyber.Peer** — Verification: `mix test test/peer_test.exs`.

   ```elixir

   port(pid) -> pos_integer                                  # the BOUND port (actual)
   stop(pid) -> :ok                                          # close + stop (rev 2)
   send_wire(host, port, wire_text) -> {:ok, status_line} | {:error, reason}
   ```

   `send_wire/3` (rev 2 — the client contract): `:gen_tcp.connect(host, port,
   [:binary, packet: :line, active: false], 5000)` → send `wire_text <> "\n\n"` →
   recv ONE line with a 5000ms timeout → strip a trailing `"\n"`/`"\r\n"` →
   `{:ok, line}`; `{:error, :timeout}` on a silent peer; `{:error, :closed}` on a
   peer that closes without replying; `{:error, reason}` on connect failure.
2. **Kyber.CLI extensions** — Verification: `mix test test/cli_test.exs`.

   ```elixir
   kyber serve --port N      # starts the peer, prints "listening on <actual-bound-port>",
                             # then blocks (a receive-forever; the operator runs it in a
                             # terminal). Port 0 is allowed (ephemeral -> the printed port).
   kyber send <host> <port>  # Federation.export -> Peer.send_wire -> prints the peer's
                             # status line verbatim
   ```

   **The serve/run(1) split (rev 2 — coherent):** `run/1` stays PURE: its serve
   command calls a public `serve_start/1` (starts the peer, validates the port,
   returns `{:ok, {:serve, line, pid}}` — a MARKER 2-tuple; a listen failure →
   `{:error, "listen failed: <reason>"}` exit 1) and returns the marker unchanged.
   `main/1`'s wrapper is the ONLY place that knows serve: `print_and_halt({:ok,
   {:serve, line, pid}})` prints the line then blocks in a `receive` that never
   matches (NO Process.sleep — the no-sleep rule is absolute; the peer's socket keeps
   the VM alive). Port validation: a non-integer or out-of-range `--port` → usage
   error exit 2; a port already in use → the listen-failure one-liner exit 1.
   `send` prints the status line verbatim; a connection failure → "peer unreachable:
   <host> <port>", exit 1. Both commands keep the T8 boot/pre-flight/exit-code
   discipline.
