# T9 — Loop 9: Federation Peers — the wire speaks to itself over the network (TCP)

## Context

T5 made the wire portable (export/import); T8 gave the operator a CLI. T9 makes
federation REAL: a `Kyber.Peer` TCP listener (stdlib `:gen_tcp` — ZERO new deps) serves
the federation wire; a client connects, sends the export text, and the peer imports it
through the SAME door (Federation.import/1). The trust model IS the claims: every
signature is re-verified at the door, a peer can only ADD signed, content-addressed
claims — the store only learns. Garbage input is refused per line (the import report),
never a crash; a dropped connection mid-frame is a non-event; store-down answers a clean
refusal line. The protocol framing is the format itself: the wire text (JSONL, T5's
byte shape) followed by ONE blank line as the frame terminator — the T5 import already
treats the final empty segment as the delimiter, so the protocol adds no new grammar.
`kyber serve --port N` and `kyber send <host> <port>` extend the CLI (lib/ scope).

**Protocol (PINNED):**
- A frame = the federation wire text (export bytes, zero or more JSONL lines) + `"\n"`.
  The peer accumulates `:line`-delimited packets until a BLANK line, joins them, and
  calls `Federation.import/1` on the joined text (the blank line is the delimiter — it
  is NOT part of the import text; the T5 import drops the final empty segment anyway).
- The reply = ONE status line: `ok imported=N skipped=N refused=N` (every completed
  import, including an empty frame → `ok imported=0 skipped=0 refused=0`), or
  `err <tag>` for a tagged import error (store-down → `err store_not_running`). The
  peer never sends an unparseable status and never crashes.
- The connection closes after the reply (one frame per connection).

**Trust & scope note:** no auth/TLS — the claims ARE the trust (the door re-verifies
every signature; a peer can only add). Transport encryption is a later ticket. The
peer is started EXPLICITLY (`Kyber.Peer.start_link/1`) — it is NOT in the application
supervision tree (the app must not listen on a port by default); the CLI's `serve`
command starts it.

## Requirements

1. **Kyber.Peer** — Verification: `mix test test/peer_test.exs`.

   ```elixir
   start_link(port: 0 | pos_integer) -> {:ok, pid}          # port 0 = ephemeral
   port(pid) -> pos_integer                                  # the BOUND port (actual)
   send_wire(host, port, wire_text) -> {:ok, status_line} | {:error, reason}
   ```

   `start_link/1`: `:gen_tcp.listen(port, [:binary, packet: :line, active: false,
   reuseaddr: true])`; a handler process per accepted connection (the GenServer
   accepts + spawns; the handler is short-lived): `:gen_tcp.recv` lines until a blank
   line → `Federation.import/1` on the joined non-blank lines → `:gen_tcp.send` the
   status line → close. Every import result maps to the pinned status line; an
   `{:error, _}` import (store-down) → `err <tag>`; a `:closed`/`:error` recv (client
   dropped mid-frame) → the handler just exits — the listener survives (the accept
   loop restarts the next connection; a crashed handler is a non-event). `port/1`
   reads the bound port from the listen socket (`:inet.port/1`). `send_wire/3`:
   `:gen_tcp.connect(host, port, [:binary, active: false], timeout)` → send the text +
   `"\n"` → recv one line → close → `{:ok, line}` (a connection failure / closed
   before a reply → `{:error, reason}`).
2. **Kyber.CLI extensions** — Verification: `mix test test/cli_test.exs`.

   ```elixir
   kyber serve --port N      # starts the peer, prints "listening on <port>" (the ACTUAL
                             # bound port — 0 is allowed), then BLOCKS (a receive-forever;
                             # the operator runs it in a terminal)
   kyber send <host> <port>  # Federation.export -> Peer.send_wire -> prints the peer's
                             # status line verbatim
   ```

   `serve` prints the bound line then blocks in a `receive` that never matches (NO
   Process.sleep — the no-sleep rule is absolute); the listener keeps the VM alive via
   its socket ownership. `send` prints the status line verbatim (`ok imported=...` or
   `err ...`); a connection failure → the pinned one-liner ("peer unreachable: <host>
   <port>", exit 1). Both commands keep the T8 boot/pre-flight/exit-code discipline
   (run/1 purity; only a recognized command boots).
3. TDD; no Process.sleep; `mix format` clean. Verification: `grep -r "Process.sleep"
   test/` finds nothing, `mix format --check-formatted` exits 0.
