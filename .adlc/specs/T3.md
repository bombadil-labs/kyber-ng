# T3 — Loop 3: The Harness Core — production wire + supervision tree

## Context

T1 built the door (Kyber.Store.admit/2), T2 made it durable (Kyber.Log +
Kyber.DurableStore). Two gaps block every downstream loop (plugins, federation,
migration): (1) there is no PRODUCTION wire serializer — the witness has no serializer and
the only envelope code lives in test/support/wire.ex (TestWire, test-only); (2) there is no
supervision tree — mix.exs has no `mod:` application callback, so nothing boots the store
at app start (T1's build report flagged: "the door must be started before append/1 — the
harness/later loops own that"). T3 closes both: the running harness gets a real wire and a
started door.

## Requirements

1. **Kyber.Wire** — the production envelope serializer (the witness has no serializer; the
   pinned wire envelope `{id, claims, sig}` is kyber's own JSON, Elixir stdlib `JSON`).
   Verification: `mix test test/wire_test.exs`.

   ```elixir
   envelope(signed_claims) -> envelope map (%{"id" => ..., "claims" => ..., "sig" => ...})
   encode(wire_map) -> {:ok, json_text} | {:error, {:encode, reason}}   # non-map -> {:encode, :not_a_map}; unencodable -> tagged
   decode(json_text) -> {:ok, wire_map} | {:error, {:decode, reason}}
   claims_json(claims) -> the string-keyed claims map for the envelope
   ```

   Round-trip contract: `encode` then `decode` is term-identical; `envelope/1` output
   re-admits through `Kyber.Store.admit/2` with `{:ok, _}`; NaN/Infinity are NOT
   representable as Elixir floats (finiteness holds per `Rhizomatic.Delta`) — not an error
   case; maps with non-string keys are REFUSED (`{:error, {:encode, :non_string_key}}` —
   the stdlib encoder would silently stringify them; reject, never repair, per T2 rev 4).
   `Kyber.TestWire` is superseded: the harness uses Kyber.Wire (tests may keep TestWire).
2. **Kyber.Application** — the OTP application: a Supervisor; `mix.exs` gains
   `mod: {Kyber.Application, []}` (a deliberate, scoped amendment — mix.exs leaves this
   ticket's frozen rails; deps/ + spec/ + SPEC.md + PLAN.md stay frozen). The supervisor
   starts exactly one child, `Kyber.DurableStore`, with the log path from app env
   (`Application.get_env(:kyber, :log_path)`), defaulting to
   `Path.join(System.user_home(), ".kyber/store.jsonl")` — a RUNTIME artifact (gitignored
   territory; never the repo tree), overridable in tests via app env. `Kyber.Store` (the
   T1 in-memory Agent) is NOT started — DurableStore is THE running store (T2 rev-2
   topology pin). Verification: `mix test test/application_test.exs`.
3. TDD; no Process.sleep (assert_receive/3 or state polling); `mix format` clean; app tests
   assert the store is actually reachable after boot (registered name + a working append).
   Verification: `grep -r "Process.sleep" test/` finds nothing, `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes.**
  Verification: `mix test` exits 0 with no skips.
- **AC2 — Wire round-trip: `encode/1` then `decode/1` of a signed message_received
  envelope is term-identical to the input map; `envelope/1` output re-admits through
  `Kyber.Store.admit/2` with `{:ok, _}`.**
  Verification: `mix test test/wire_test.exs` (build a signed event via Kyber.Events,
  envelope, encode/decode, term-equality, admit).
- **AC3 — Wire error tagging: non-map input → `{:error, {:encode, :not_a_map}}`;
  unencodable values (a tuple/PID) → `{:error, {:encode, _}}`; malformed JSON text →
  `{:error, {:decode, _}}`; the file is never touched by Wire (it has no file I/O).**
  Verification: `mix test test/wire_test.exs`.
- **AC4 — The app boots the durable store: starting `:kyber` starts a registered
  `Kyber.DurableStore` whose log path is `Application.get_env(:kyber, :log_path)` (default
  under the user home, overridable), and an append through it persists and replays.**
  Verification: `mix test test/application_test.exs` (boot with a tmp log_path, append a
  signed delta, stop_supervised, reboot, assert present).
- **AC5 — `Kyber.Store` (the T1 Agent) is NOT started by the application — there is
  exactly one running store.**
  Verification: `mix test test/application_test.exs` (after boot,
  `Process.whereis(Kyber.Store)` is nil while `Process.whereis(Kyber.DurableStore)` is a
  pid).
- **AC6 — mix.exs amendment is scoped: only the `mod:` application callback is added;
  the rhizomatic dep tuple is untouched.**
  Verification: `git diff main -- mix.exs` shows only the `mod:` addition; `deps/` and
  `spec/` diffs are empty.
- **AC7 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.

## Out of scope (later tickets)

The Discord plugin, the reactor/subscriptions (gated on substrate L4), federation,
migration, vault-as-view, sqlite/packs backends. Only lib/, test/, and mix.exs (the mod:
amendment) may be touched; runtime artifacts (log files) go to tmp dirs or the user-home
default — never the repo tree.
