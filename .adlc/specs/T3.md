# T3 — Loop 3: The Harness Core — production wire + supervision tree (rev 2)

## Context

T1 built the door (Kyber.Store.admit/2), T2 made it durable (Kyber.Log +
Kyber.DurableStore). Two gaps block every downstream loop (plugins, federation,
migration): (1) no PRODUCTION wire serializer — the witness has no serializer and the only
envelope code lives in test/support/wire.ex (TestWire, test-only); (2) no supervision tree
— mix.exs has no `mod:`, so nothing boots the store at app start. T3 closes both.
Rev 2 folds the 9-cause premortem (all accepted): the mod: amendment's suite-breaking
choreography is pinned, the default-path mkdir contract is owned, AC6 gets a real base,
and the wire format is pinned (parity, bytes, depth, decode symmetry, end-to-end chain).

## Requirements

1. **Kyber.Wire** — the production envelope serializer (the witness has no serializer; the
   pinned wire envelope `{id, claims, sig}` is kyber's own JSON, Elixir stdlib `JSON`).
   Verification: `mix test test/wire_test.exs`.

   ```elixir
   envelope(signed_claims) -> envelope map (%{"id" => ..., "claims" => ..., "sig" => ...})
   encode(wire_map) -> {:ok, json_text} | {:error, {:encode, reason}}
   decode(json_text) -> {:ok, wire_map} | {:error, {:decode, reason}}
   claims_json(claims) -> the string-keyed claims map for the envelope
   ```

   Contract (rev 2 pins): encode refuses non-map input (`{:error, {:encode, :not_a_map}}`),
   maps with ANY non-string key at ANY DEPTH (`{:error, {:encode, :non_string_key}}` — the
   stdlib encoder silently stringifies nested atom keys; reject, never repair), and values
   with no `JSON.Encoder` implementation (PIDs, tuples, refs → tagged error). NaN/Infinity
   are NOT representable as Elixir floats (finiteness holds per `Rhizomatic.Delta`) — not
   an error case. decode refuses malformed JSON (`{:error, {:decode, _}}`) AND valid JSON
   that is not a map (`{:error, {:decode, :not_a_map}}` — mirroring encode).
   `Kyber.TestWire` is the FORMAT ORACLE until deleted: `Kyber.Wire.envelope/1` and
   `claims_json/1` must render byte-identically to `Kyber.TestWire` on the same signed
   event (the differential AC pins it). Round-trip: encode→decode term-identical;
   envelope/1 output re-admits through `Kyber.Store.admit/2`.
2. **Kyber.Application** — the OTP application (Verification: `mix test test/application_test.exs`):
   a Supervisor; `mix.exs` gains `mod: {Kyber.Application, []}` (the ONLY mix.exs change).
   The supervisor starts exactly one child, `Kyber.DurableStore` (restart: :permanent —
   a crash respawns it and replay rebuilds the set from disk), with the log path from app
   env (`Application.get_env(:kyber, :log_path)`), defaulting to
   `Path.join(System.user_home(), ".kyber/store.jsonl")`. **Kyber.Application OWNS the
   side effect that ~/.kyber/ exists**: the parent directory is created (mkdir_p) before
   the child starts, so a fresh account's first append succeeds instead of silently
   returning `{:error, :persist_failed}` (premortem cause 2). `Kyber.Store` (the T1
   in-memory Agent) is NOT started — DurableStore is THE running store (T2 rev-2 topology
   pin). `config/config.exs` holds the default log_path and loads the env override via
   `import_config "#{Mix.env()}.exs"` (REQUIRED — Mix auto-loads ONLY config/config.exs;
   without the import, a test run falls back to the real ~/.kyber store, rev 3
   adjudication of the build's import_config contradiction); `config/test.exs` overrides
   the log_path to a tmp path — the suite never touches the user's real store.
3. **Suite choreography (the mod: amendment's precondition, premortem cause 1):** with
   `mod:` present, `mix test` auto-boots :kyber. `test_helper.exs` STOPS the auto-started
   app (`Application.stop(:kyber)` after loading config/test.exs's tmp path) so the T2
   suite's per-test `start_supervised!({DurableStore, path})` instances keep working and
   no test touches the user's real store. application_test boots the app EXPLICITLY
   (`Application.ensure_all_started(:kyber)` with the env's tmp path) and stops it on
   exit. No test may rely on the app being auto-started or auto-stopped outside these
   pinned commands. Verification: `mix test` exits 0 AND the T2 durable_store tests pass
   unchanged.
4. TDD; no Process.sleep (assert_receive/3 or state polling); `mix format` clean.
   Verification: `grep -r "Process.sleep" test/` finds nothing, `mix format --check-formatted` exits 0.

## Acceptance Criteria (each names its verification method)

- **AC1 — The suite compiles and passes, T2 tests untouched.**
  Verification: `mix test` exits 0 with no skips; `git diff <pre-T3-commit> -- test/durable_store_test.exs test/log_test.exs` is EMPTY.
- **AC2 — Wire parity + round-trip: `envelope/1` and `claims_json/1` render BYTE-IDENTICAL
  to `Kyber.TestWire` on the same signed event; `encode/1` then `decode/1` is
  term-identical; the envelope re-admits through `Kyber.Store.admit/2` with `{:ok, _}`.**
  Verification: `mix test test/wire_test.exs` (differential test vs TestWire on a signed
  message_received event; term-equality; admit).
- **AC3 — Wire error symmetry: non-map input → `{:error, {:encode, :not_a_map}}`;
  unencodable value (tuple/PID) → `{:error, {:encode, _}}`; malformed JSON →
  `{:error, {:decode, _}}`; VALID non-map JSON (`"[]"`, `"42"`, `"\"str\""`) →
  `{:error, {:decode, :not_a_map}}`; a nested atom-keyed map inside claims →
  `{:error, {:encode, :non_string_key}}` at ANY depth. Wire has no file I/O.** (Rev 2:
  decode symmetry + deep key check pinned.)
  Verification: `mix test test/wire_test.exs`.
- **AC4 — The app boots the durable store: `Application.ensure_all_started(:kyber)` (with
  the config/test.exs tmp log_path) starts a registered `Kyber.DurableStore`; an append
  through it persists and replays across a SUPERVISED RESTART (Application.stop + start
  again, or stop_supervised of the child).** (Rev 2: the wire chain — the appended
  envelope is built via Kyber.Wire, not TestWire: Wire → DurableStore.append → stop →
  restart → decoded line re-admits and is present in the set.)
  Verification: `mix test test/application_test.exs`.
- **AC5 — Exactly one running store: after boot, `Process.whereis(Kyber.Store)` is nil

  Verification: `mix test test/application_test.exs`.

  Verification: the two git diff commands above (named hash in the body).
- **AC7 — No Process.sleep anywhere in test/.**
  Verification: `grep -r "Process.sleep" test/` finds nothing.
