# T12 — The Agent Acts (k3 fork)

Rev 1 — fork of the shared T12 arc contract for the k3 leg of the three-way blind taste test (T12 rematch 2026-08-06). Same contract as its siblings; amendments to THIS file only.

Original Rev 1 — arc ticket of the ORACLE ARC (user mandate 2026-08-06; PLAN.md §0). Builds on the T11
umbrella (closed: schema layer + inference chain + memory store). The T11b tool chain ends at a
stub executor (`tool:echo`); T12 makes the agent ACT — real actions with real side effects,
through the SAME ToolCall → ToolResult delta chain, crash-window idempotence intact.

## Why

The agent can think (T11b) and remember (T11c); it cannot DO anything. T12 gives it a
capability surface: an action registry with typed schemas, a permission gate, and the first
real actions — filesystem (read/write under a workspace root), shell (bounded, sandboxed cwd,
timeout, output-capped), HTTP (fetch/post). Every action is a ToolCall delta (attested,
pointer-linked), its outcome a ToolResult delta — the store learns what the agent did, and the
crash-window guarantee (AC3) holds because a re-fired action is byte-identical by construction
(deterministic action id from the call delta; the executor answers from the store, never
re-executes).

**Aligned by construction (the user's guardrail):** every action passes the permission gate —
allow-list / prompt / deny, resolved at boot; no action executes without a gate decision; the
gate's decisions are THEMSELVES deltas (attested, auditable). No misaligned capability.

## Deliverables (scope: `lib/kyber/agent/action*` + the executor seam + `test/action*`)

- **`Kyber.Agent.Action`** — the action registry: `{name, schema}` where the schema is a typed
  JSON-object shape (the OpenAI `parameters` shape the T11b fold already speaks); registry
  entries are data, not code — the executor maps them.
- **`Kyber.Agent.Action.Gate`** — the permission gate: `allow`/`deny`/`prompt` policy per
  action name, resolved at boot from opts; `decide/2` returns the decision; every decision is
  attested (a `ToolCall` refused by the gate emits NO ToolResult and a refused-reason claim —
  reject, never repair).
- **`Kyber.Agent.Action.Fs`** — filesystem actions (`fs.read`, `fs.write`, `fs.list`) bound to
  a workspace root (path traversal outside the root → refused by construction); write is
  create-or-update under the root, attested.
- **`Kyber.Agent.Action.Shell`** — one bounded shell action (`sh.run`): sandboxed cwd, hard
  timeout, output cap (N bytes, truncated with a marker — never a silent truncation);
  non-zero exit is a ToolResult with the status, not a crash.
- **`Kyber.Agent.Action.Http`** — `http.get` / `http.post` through the existing stdlib
  `:httpc` seam (the LlmHandler's injectable HTTP client), response body capped like shell
  output; no secrets in request payloads (the handler's key-refusal doctrine extends to
  actions).
- **`Kyber.Agent.ToolExecutor`** — re-architected from the stub to route ToolCall deltas by
  action name through the registry; the stub tools stay (the A/B property: stub and real
  registry are swappable behind the same seam).

## Acceptance criteria

- **AC1 — The chain is the same chain:** a tool turn produces `ToolCall` → gate decision →
  executor action → `ToolResult`, each persisted and pointer-linked; the projection shows the
  action as a tool step. verify: the action-chain test asserts the link sequence with a real
  (fs) action; a mid-chain restart resumes with the executor answering from the store — the
  action is NEVER re-executed after a crash-window re-fire (the byte-identical re-fire holds).
- **AC2 — The gate is the boundary:** an allow-listed action runs; a denied action emits NO
  ToolResult and a refused-reason claim; the gate's decisions are attested deltas (auditable);
  a `prompt`-policy action is refused when no prompt answer is wired (fail closed). verify:
  the gate test asserts all three outcomes + the attestation.
- **AC3 — Bounded by construction:** path traversal outside the workspace root is refused
  (fs.read/fs.write); shell runs have a hard timeout and a capped output; HTTP bodies are
  capped. verify: the bounds test asserts traversal refusal, a timeout-hitting shell run
  yields a timeout ToolResult, and capped outputs carry the truncation marker.
- **AC4 — The operational run (THE gate):** Hermes boots the daemon on a tmp store/keyring
  with a REAL model (kimi-k3) and the gate allow-listing `fs.read`; the agent is asked a
  question whose answer REQUIRES reading a file (a fixture planted in the workspace); the
  model emits a native `tool_calls`, the executor runs `fs.read`, the ToolResult feeds back,
  and the final ResponseDelta contains the file's content. verify: the recorded operational
  run (this exact sequence) with the real model, machine-checked by the smoke.
- **AC10 — Gates (carried):** no `Process.sleep` in test/; rails frozen; tmp everywhere;
  format clean; warnings-as-errors clean; the stub and real executor are A/B-swappable behind
  the same seam. verify: the carried greps + rails-guard + the A/B swap test.

## Carried contract (binds this slice — from the T11b/T11c amendments)

- The determinism clause: the executor is a pure function of (store, call delta, state) —
  re-fires answer from the store, never re-execute; action outcomes are deterministic where
  the action allows (fs.read of the same path is idempotent; sh.run of a pure command is
  idempotent; the docs say which actions are NOT idempotent and how the gate treats them).
- Provenance as authority: human-issued action permissions outrank agent-auto (the T11c rule).
